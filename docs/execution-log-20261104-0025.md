## 五、自省（用户点名要记的一条）

### 5.1 `editDistance` 漏 `+1`：距离恒为 0 → 任何乱敲都「匹配」任何候选

- **我写的初版**三处递推是 `d[i-1][j]`、`row[j-1]`、`d[i-1][j-1] + cost` —— 前两处漏了 `+ 1`（编辑一次的最小代价）。后果：距离恒 0 ⇒ 相似度恒 1 ⇒ 阈值形同不存在。
- **实测症状（我自己先看到、但没归因）**：真进程打 `bogus-xyz` 得到「你是不是想输入 `balance`？」，`--bogus-opt` 一次给三个候选（`--project / --provider / --version`）。当时我把它当「阈值太松」，把阈值从 ≤3 收紧到 ≤2 —— **那是在错误的层打补丁**：真正的原因是距离算错了，收紧阈值只是让症状变窄（`bogus-xyz` 恰好距离 3 被挡掉，但 `chek` 被建议成 `chat` 这种仍然错）。
- **真正的根因由并行体修掉**（补 `+1`），并留了注释。
- **该有的护栏（明天补）**：单测必须断言**「乱敲词不得匹配任何真实命令」**这一**否定**面，而不是只断言 `docter → doctor` 这种**正例**。只跑正例时，距离恒 0 的实现照样"通过"（因为它对任何词都给最近的那个候选）—— 这正是 AGENTS「探针通电」条款的镜像：**只有正例的测试，和没有测试在该 bug 面前等价**。
