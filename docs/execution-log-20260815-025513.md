### 问题分析（四层独立问题叠在一起）

| # | 问题 | 性质 | 根因 |
|---|------|------|------|
| 一 | 第一次 lint 失败「Missing script: lint」 | 项目配置问题（非 concertoai bug） | precommit 模板假设项目已配置 lint/typecheck/test 三条命令；test-autofix 未配 |
| 二 | 第二次 lint 失败（biome 格式报错） | 模板完善点 | 项目文件 CRLF+空格缩进 vs biome 默认 LF+Tab 缩进；precommit 模板未提示格式约定（biome.json）前置条件 |
| 三 | `[F]修复后重试` 不自动修 | UX 模糊点 | executor 中 fix-and-retry 与 retry 走同一条路径（仅重跑失败步骤），无「请手动修复后按 F」提示 |
| 四 | Ctrl+C 崩溃 → crash.log + exit(1) | **concertoai 真 bug** | workflow.ts / plugin.ts 的 promptLine 用 readline/promises question()，Ctrl+C 抛 AbortError 未被捕获 → crash-handler.ts 的 unhandledRejection 误判为崩溃 → 写 crash.log + exit(1) |

### 修复计划（三个落地点 + 一个防御增强）

1. **Ctrl+C 崩溃（核心）**：promptLine 捕获 AbortError → 返回 undefined → 上层按「无输入」处理（恢复走 abort=fail-closed，审批走拒绝=fail-closed，均为既有安全路径）；同类模式扫描 plugin.ts 一并修复
2. **crash-handler 防御增强**：unhandledRejection 收到 AbortError 时视为用户主动中断（不写 crash.log、退出码 130 而非 1），保证 crash.log 只记录真实异常
3. **F 选项提示**：promptRecovery 选 F 后打印「F 仅重跑失败步骤不自动修复，请手动修改后按 F」；i18n zh/en 新增 failureFixHint 键
4. **precommit 模板完善**：模板 description / lint 步骤 description 补充「需项目已配置 lint/typecheck/test 脚本与格式约定（biome.json）」
