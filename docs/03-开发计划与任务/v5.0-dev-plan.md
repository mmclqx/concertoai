## 一、设计哲学与定位（v5.0 的转向）

### 1.1 专家的核心判断：我同意，但要说得更准

> 专家原话：「用 L2 的壳，装了 L3/L4/L5 的核……技术上极其深厚，但在用户眼里，它太像一个黑盒。」

核查结论：**属实**。代码事实——`src/` 下有 workflow（DAG 引擎）/ reviewer（9 维 + autofix）/ orchestrator（4 Agent 对抗闭环）/ knowledge（知识图谱）/ plugin（7 文件）+ market（5 文件）/ lsp（5 文件，diagnostics 17.5KB），1404 个用例护着这些内核；但 CLI 门面（`src/cli/index.ts`）只暴露 19 个命令，其中最值钱的 `/review --fix`（自动修复）**只能在 TUI 里敲，CLI 层不可达**；审批框只给一行「编辑文件 X」+ diff，不提风险。

所以问题不是「核不够强」，而是**核的价值传导不到用户眼前**。

### 1.2 一句话定位（v5.0 起生效）

| | v4.x | **v5.0** |
|---|---|---|
| 对外说法 | 终端 AI 开发平台 + 守护代码 | **守护你代码的个人超级 CLI** |
| 价值主张 | 我有很多能力（平台深度） | **我替你看着风险，你只管写**（可信 + 可懂 + 可发现） |
| 用户心智 | 装了很多功能，不知道怎么用 | 一个敢让它改生产代码的助手 |
| 商业路径 | 平台/生态（插件市场、团队并行） | 个人极客工具 → Pro（云端 RAG 记忆 / 策略同步） |

**不做的事（与专家建议五一致，但表述更硬）**：v5.0 不新增任何「只有多人团队/生态才需要」的功能面。

### 1.3 为什么是 5.0 而不是 4.3

v4.x 一路加的是**能力面**（多 Provider / 工作流 / 插件 / 多 Agent）；v5.0 第一次转向**用户可感知面**（透明审批 / 场景发现 / 动词化 CLI / 可度量体验）。这是产品哲学换挡，配得上 major，且需要一次对外定位重写。

## 二、专家建议书逐条评审（采纳 / 修正 / 拒绝）

> 原则：**建议书是输入，不是指令**。每条都用代码事实验一遍，能落地的重新设计，站不住的直说。

### 建议一：审批变成「风险教学」 → ✅ 采纳，但**大改技术方案**

| 项 | 内容 |
|---|---|
| 事实核查 | 成立。`src/tools/edit.ts:199` 现在传 `summary: '编辑文件 X'`、`detail: 统一 diff`；`src/ui/App.tsx:1191` 拒绝只 `resolve(false)`，无复盘 |
| 专家方案 | 用 AST 或「复用 search_content 做 grep 关联查询」算影响面 |
| **我的修正 1** | **不用 grep 扫全项目做影响面**。理由：① 假阳性高（同名局部变量/注释/字符串全算依赖）② 大项目每次编辑扫全库 = 审批卡顿，而审批框是**同步阻塞交互**，卡 800ms 用户会骂 ③ Windows 路径/大小写在 grep 里是新的 bug 源（v4.1.1 反斜杠正则教训） |
| **替代方案（分两层，先便宜后贵）** | **第一层（微秒级，永远执行）**：内容风险规则表——对 diff 的**新增行**做确定性特征匹配（删除/清空 `rm`/`unlink`、写盘/覆盖、网络请求与超时、DB/迁移、鉴权/权限、加密/密钥、配置/环境变量、并发/锁、`catch {}` 静默吞错）。命中即标风险等级。**第二层（毫秒级，仅第一层命中中高风险时执行）**：影响面分析——只对**本文件被 import 的导出符号**做定向查询（`import ... from '<相对路径>'` 反向匹配 + 导出符号名出现次数），**300ms 硬超时 + 同文件 5s 缓存**，超时降级为「未分析（不影响审批）」 |
| **我的修正 2** | 专家说「建议关注行」——这个最值钱且几乎零成本：diff 里被标记的 `+` 行直接打 ⚠️，用户一眼看到「这次改动最危险的那一行」。优先级高于影响面 |
| **我的修正 3（安全红线）** | 风险提示**只增信息、不减管控**：不是「高风险才要审批」，而是「所有编辑照旧审批，只是把话说清楚」。审批强度与 v4.1.1 完全一致（fail-closed 不松动） |
| **我的修正 4（复盘记录）** | 采纳「拒绝即复盘」，但落**本地 JSONL**（`~/.concertoai/reflections.jsonl`），字段：时间/项目/文件/风险类别/建议关注行/AI 意图摘要/用户选择。提供 `concertoai reflect list` 查看 + `--off` 关闭。不做云端、不默认上传 |
| 遗留价值 | 长期可做「同类风险被拒 N 次 → 主动提示 AI 换策略」，但**v5.0 不做**（避免范围膨胀） |

### 建议二：场景触发器 → ✅ 采纳，但**砍掉「权重状态机」**

| 项 | 内容 |
|---|---|
| 事实核查 | 成立。App/StatusBar/PromptInput 三个 UI 文件搜 hint/tip/建议 **零命中**，确无任何提示机制 |
| 专家方案 | 「简单场景状态机 ContextualState，按最近 3 轮对话 + 报错状态 + cwd 特征，**按权重**弹出提示」 |
| **我的修正** | **权重打分 = 噪音工厂**。v4.0 客户评价里已有「进度刷屏 / 输出淹没」教训（AGENTS 边缘路径规范第 3 条）。v5.0 只做 **3 条确定性规则 + 硬性约束**：① 同时最多 1 条 ② 同一提示每会话 1 次、全局 10 分钟冷却 ③ 提示必须是**可直接复制执行的完整命令**（不能是「试试 /agent explore」这种要用户自己补参数） ④ 全局开关 `hints: on/off`，`/hints off` 一键静音 |
| 3 条内置场景（对应真实痛点） | ① **项目无 AGENTS.md** → `concertoai init`（首次进新项目）② **verify/self-heal 失败** → `concertoai self-heal`（不用记 self-heal）③ **同一文件连续 2 轮出现错误或反复读取** → `/review --fix <file>`（已验证能力被埋没的典型） |
| 呈现位置 | 输入框上方**单行**（dimColor，不占多行、不进消息流、不打断流式输出） |

### 建议三：init 双输出（AGENTS.md + PROJECT_GUIDE.md）→ ✅ 采纳，但**归属 v4.2 任务，不重复立项**

| 项 | 内容 |
|---|---|
| 事实核查 | `src/cli/` **没有 init.ts**，`concertoai init` 命令不存在。v4.2 已定稿的 T5 就是「init 生成守护指南」，但**只生成 AGENTS.md 一份** |
| 专家方案 | 双输出：AGENTS.md（给 AI）+ PROJECT_GUIDE.md（给人：最脆弱的地方 / 改哪里引发连锁 / 如何跑通本地） |
| **我的判断** | 这是**全书性价比最高的一条**，且点出了真正的差异化「Carbon 是 AI 的工具，你是 AI 与人的双向守护工具」。但它是 **v4.2 T5 的验收增强**，不是 v5.0 新任务——所以 v5.0 的 T5 直接按双输出验收（工作量 +0.2h） |
| **我的加固** | ① 「最脆弱的地方」**必须带证据**（`文件:行号 + 命中规则`，如 `src/api/client.ts:42 硬编码 5s 超时`），无证据的段落写「未检测到」而**不许编**（防 LLM 幻觉生成误导性指南）② PROJECT_GUIDE.md 生成后**打印 3 行摘要 + 路径**，不强制用户读全文 ③ 双文件同源（一次分析、两次渲染），不跑两遍分析 |

### 建议四：workflow 动词化（DAG 断舍离）→ ✅ 强采纳，但**边界要收死**

| 项 | 内容 |
|---|---|
| 事实核查 | 成立且比专家说的更严重：`/review --fix`（v4.0 就有的自动修复）**只有 TUI 入口**；workflow 要 `list/init/run/export/import/create` 6 个子命令 + 手写 YAML |
| 专家方案 | 加 `concertoai commit`（跑 verify + 分类修错 + PR 说明）、`concertoai review --fix` |
| **我的修正 1** | **不做「自动提 PR」**。commit 已经够重（AI 生成的 message + git 写操作），提 PR 涉及远端/分支/凭据，风险不可控且偏离个人 CLI 定位。v5.0 动词止于**本地 commit**，绝不 push |
| **我的修正 2** | 动词必须是**已有能力的薄包装**（check→verify+分类器 / fix→self-heal / commit→check+message+git / review→reviewer engine），**禁止第二套实现**（否则行为分叉，v4.1.1「装好却跑不通」就是这么来的） |
| 4 个动词（v5.0 全部落地） | `concertoai check`：只读体检（verify + 4 段分类摘要 + 结论「能提交/不能提交」），**不修任何东西** → 最安全，先做<br>`concertoai self-heal`：包装 self-heal（分类→修复→复验→回滚），`--dry-run` 只诊断<br>`concertoai commit`：check 通过 → 生成中文 message（**≤72 字符标题 + body 3 点**）→ 展示 → 审批 → `git commit`；check 失败 → 提示 `concertoai self-heal` 后退出（不自动修完再提交）<br>`concertoai review [path]`：CLI 层暴露 9 维审查（`--fix` 修 A 类），复用 `src/reviewer/` |
| 关于「不要鼓励用户创建工作流」 | **同意但保留底层**：DAG 引擎是 check/fix/commit/review 的支撑，用户不写 YAML ≠ 砍掉引擎。v5.0 只需保证 `workflow` 6 子命令**不删、不进 --help 首屏**（首屏给 4 个动词） |

## 四、原则（v5.0 铁律）

1. **安全不降级**：v5.0 所有「透明化」只增信息，**不减少审批、不引入 yolo**。审批强度与 v4.1.1 逐字节一致。
2. **体验不卡顿**：审批框内任何分析**必须有硬超时 + 降级路径**（超时显示「未分析」，不阻塞审批）。目标：审批框出现 P95 < 150ms，最坏 < 400ms。
3. **不添噪音**：任何主动提示都要有**上限（同时 ≤1 条）、冷却、开关、可复制执行**。宁可少提示，不可多提示。
4. **薄包装，不重实现**：4 个动词复用既有引擎，禁止并行第二套逻辑（避免 v4.1.1 类分叉 bug）。
5. **证据优先**：所有 AI 生成的结构化文档（AGENTS.md / PROJECT_GUIDE.md / commit message）每段必须引用真实文件与行号；无证据写「未检测到」，**禁止编造**。
6. **可度量**：每个体验任务验收标准里带**可观测判据**（不是「感觉更好」）。
7. **冻结即文档**：功能冻结要落文档（ARCHITECTURE / FEATURE_FREEZE），否则下个版本又长回来。
8. **边缘路径强制覆盖**（AGENTS 既有规范延续）：每个新命令必须覆盖 ① 首次运行 ② 失败恢复 ③ 主动退出 ④ 输出超长截断。
