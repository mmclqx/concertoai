## V1.1-M1：MCP 基础接入（P0，约 8h）

### T1.1 实现 MCP 客户端核心

**目标**：实现 MCP（Model Context Protocol）客户端，支持连接外部 MCP 服务、发现服务提供的工具列表、将外部工具注入 ConcertoAI 的工具注册表供模型调用。锁定 MCP 协议版本，避免后续协议变动导致集成失效。

**涉及文件**：
- `src/mcp/client.ts`（新增 — MCP 客户端连接、发现、调用）
- `src/mcp/manager.ts`（新增 — 多 MCP 服务管理、工具聚合）
- `src/mcp/types.ts`（新增 — MCP 协议类型定义）
- `src/tools/registry.ts`（修改 — 支持动态注册外部工具）
- `tests/mcp/client.test.ts`（新增）
- `tests/mcp/manager.test.ts`（新增）

**验收标准**：
- [ ] MCP 客户端可通过 stdio transport 连接外部 MCP 服务进程
- [ ] 客户端可调用 `tools/list` 获取服务提供的工具列表
- [ ] 客户端可调用 `tools/call` 执行外部工具并获取结果
- [ ] manager 可将多个 MCP 服务提供的工具聚合并注入 ToolRegistry
- [ ] MCP 服务进程退出 / 连接断开时有中文错误日志，不影响主流程
- [ ] 协议类型定义完备，覆盖 JSON-RPC 2.0 消息格式
- [ ] 测试覆盖：连接成功、工具发现、工具调用、连接失败恢复

**预估耗时**：3h
**依赖**：无

---

### T1.2 集成 filesystem MCP 服务

**目标**：通过 MCP 客户端连接官方的 `@modelcontextprotocol/server-filesystem` 服务，将文件系统的读写/列表/搜索能力通过 MCP 提供给模型。对比内置 `read_file`/`list_directory`/`search_content` 工具，决定是替换还是共存（建议：MCP 工具作为补充，内置工具保留作为回退）。

**涉及文件**：
- `src/mcp/builtin-servers.ts`（新增 — 内置 MCP 服务预配置）
- `src/store/config.ts`（修改 — 配置项新增 `mcp` 数组）
- `src/cli/chat.tsx`（修改 — 启动时初始化 MCP 连接）
- `tests/mcp/filesystem.test.ts`（新增）

**验收标准**：
- [ ] 用户可在配置文件中声明 filesystem MCP 服务（允许目录列表）
- [ ] 启动时自动连接 filesystem MCP 服务
- [ ] MCP filesystem 工具可被模型发现和调用（`read_file`、`write_file`、`list_directory`、`search_files` 等）
- [ ] 目录访问受限在用户配置的允许范围内（沙箱安全）
- [ ] 内置工具在 MCP 服务不可用时仍可正常工作（降级）
- [ ] 测试覆盖：工具发现、文件读写、目录限制

**预估耗时**：2.5h
**依赖**：T1.1

### T1.3 集成 memory MCP 服务

**目标**：通过 MCP 客户端连接 memory 服务，实现跨会话的知识存储与检索。模型可在对话中将有价值的信息写入记忆，后续会话中自动检索相关记忆注入上下文。

> **注意**：此任务为 P0（发布硬门槛），与 V1.1-M3 的「跨会话记忆」不同——M3 是实现本地优先的独立记忆系统（不依赖外部 MCP 服务），本任务是 MCP 生态集成。两者互补：MCP memory 用于外部知识库，本地 memory 用于项目级轻量记忆。

**涉及文件**：
- `src/mcp/builtin-servers.ts`（修改 — 新增 memory 服务预配置）
- `src/loop/memory-injector.ts`（新增 — 从 memory 服务检索并注入上下文）
- `tests/mcp/memory.test.ts`（新增）

**验收标准**：
- [ ] 用户可在配置文件中声明 memory MCP 服务
- [ ] 模型可通过 MCP 工具读写记忆（`create_entities`、`search_nodes`、`open_nodes` 等）
- [ ] 每轮对话前自动检索相关记忆并注入系统提示
- [ ] memory 服务不可用时不影响对话（降级，写记忆操作返回错误提示）
- [ ] 测试覆盖：记忆写入、检索、注入

**预估耗时**：2.5h
**依赖**：T1.1

## V1.1-M2：任务规划增强（P0，约 6h）

### T2.1 实现计划步骤依赖检测

**目标**：在 `/plan` 生成的计划中，自动检测步骤间的依赖关系（如"步骤2 需要读取步骤1 创建的文件"），将依赖信息结构化存储。在执行阶段，按依赖拓扑顺序调度步骤，缺失依赖时提前报错。

**涉及文件**：
- `src/planner/deps.ts`（新增 — 依赖检测核心逻辑）
- `src/planner/types.ts`（新增 — 计划步骤、依赖关系类型定义）
- `tests/planner/deps.test.ts`（新增）

**验收标准**：
- [ ] 可解析 markdown 计划中的步骤列表，提取步骤编号与描述
- [ ] 通过关键词（"读取"、"编辑"、文件路径引用）检测步骤间依赖
- [ ] 支持显式依赖声明（步骤中 `depends on: 步骤1` 格式）
- [ ] 输出拓扑排序后的执行顺序
- [ ] 循环依赖检测并报错
- [ ] 测试覆盖：无依赖、链式依赖、并行步骤、循环依赖

**预估耗时**：2h
**依赖**：无（V1.1-M1 可选依赖，可并行开发）

### T2.3 实现计划回滚/撤销能力

**目标**：计划执行过程中某一步骤失败时，支持回滚已完成的步骤。回滚策略：记录每个步骤的文件变更（edit_file 的前后内容），失败时逐步骤反向恢复文件内容。仅支持文件编辑类操作的回滚，shell 命令的副作用无法回滚（执行前提醒用户）。

**涉及文件**：
- `src/planner/rollback.ts`（新增 — 回滚核心逻辑）
- `src/tools/edit.ts`（修改 — 每次编辑前快照原文件内容）
- `tests/planner/rollback.test.ts`（新增）

**验收标准**：
- [ ] 计划执行前自动创建文件快照（备份目录 `.lumen/snapshots/`）
- [ ] 步骤失败时可选择"回滚所有已完成步骤"
- [ ] 回滚时逐文件恢复快照内容，恢复后删除快照
- [ ] 正常完成后自动清理快照
- [ ] 非文件操作（shell）在回滚时跳过并提示用户
- [ ] 测试覆盖：回滚成功、部分回滚、快照清理

**预估耗时**：2h
**依赖**：T2.2（进度跟踪感知失败步骤触发回滚）

## V1.1-M3：跨会话记忆（P1，约 6h）

**涉及文件**：
- `src/store/memory-store.ts`（新增 — 记忆存储 CRUD）
- `tests/store/memory-store.test.ts`（新增）

**验收标准**：
- [ ] 记忆存储在项目根目录 `.lumen-memory/` 下
- [ ] 支持创建/更新/删除/查询记忆
- [ ] 每条记忆包含：id、title、content、tags、createdAt、updatedAt
- [ ] 支持按标签/关键词过滤检索
- [ ] 同项目多次启动共享同一记忆存储

**预估耗时**：2h

### T3.2 实现记忆检索与注入

**目标**：每轮对话开始时，从本地记忆存储中检索与当前用户输入相关的记忆，将匹配的记忆注入系统提示或上下文开头（格式：`# 项目记忆\n- 记忆1: ...`）。检索策略优先简单实现（关键词匹配 + 标签匹配），后续可升级为向量检索。

**涉及文件**：
- `src/loop/memory-injector.ts`（新增 — 检索并格式化记忆文本）
- `src/loop/loop.ts`（修改 — 在 system prompt 后注入记忆块）
- `src/ui/App.tsx`（修改 — 传递 memoryStore）
- `tests/loop/memory-injector.test.ts`（新增）

**验收标准**：
- [ ] 对话开始时自动检索相关记忆
- [ ] 匹配的记忆以固定格式注入上下文（不影响 system prompt 结构）
- [ ] 检索支持：标题关键词、标签、内容包含
- [ ] 注入条数上限（默认 5 条），按匹配度排序
- [ ] 无相关记忆时不注入（不增加多余 token）
- [ ] 测试覆盖：精确匹配、模糊匹配、无匹配、上限截断

**预估耗时**：2h
**依赖**：T3.1

**涉及文件**：
- `src/cli/slash/memory.ts`（新增 — `/remember` `/forget` 命令处理器）
- `src/ui/App.tsx`（修改 — 识别 memory 斜杠命令）
- `src/store/memory-store.ts`（修改 — 暴露命令行接口）
- `tests/cli/slash-memory.test.ts`（新增）

**验收标准**：
- [ ] `/remember <内容>` — 让模型生成记忆摘要，用户确认后写入
- [ ] `/forget <关键词>` — 搜索匹配记忆列表，用户选择后删除
- [ ] `/memories` — 列出当前项目所有记忆
- [ ] 记忆写入/删除后 TUI 显示确认提示
- [ ] 支持 `/remember` 不带参数时进入交互式记忆创建流程
- [ ] 测试覆盖：创建、删除、列表、确认/取消

**预估耗时**：2h
**依赖**：T3.1

## 不做清单（范围控制）

| 项目 | 理由 | 计划 |
|------|------|------|
| MCP 多服务动态管理 | 复杂度高，v1.1 只做基础集成 | v1.2 |
| 子代理 / 技能系统 | 需要 MCP 基础稳定后再做 | v1.2 |
| 桌面端 / 图形界面 | 超出 CLI 定位 | 不做 |
| 多模型后端（非 DeepSeek） | 当前无需求 | 视反馈 |
| 智能摘要压缩（上下文管理优化） | P2 优先级，可推后 | v1.2 评估 |
