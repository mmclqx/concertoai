## 1. 定位与 3.1 定义

**v3.0 定位回顾**：从「可协作的伙伴」进化为「多智能体协同的 AI 开发团队」。

**v3.1 定位**：修复 v3.0 多 Agent 系统的稳定性短板 + 补齐 CLI 日常使用的基础体验缺口，从「能协作的团队」进化为「**能稳定协作、能自我修复、能跨项目使用的可靠工具**」。

v3.0 开发与发布过程中暴露的四个核心痛点（审查 🟡#14：定位聚焦真实痛点，不引入未论证的新大能力）：

| 痛点 | v3.0 表现 | v3.1 目标 |
| --- | --- | --- |
| AI 遇到自身代码错误死循环 | `npm run verify` 失败后盲目重试，或依赖模型自行修正不可控 | 建立「诊断 → 修复 → 验证 → 回滚」的确定性自我修复闭环 |

**完成定义（Definition of Done）**：通过第 6 节「发布门检查清单」全部条目。

## 3. 核心设计原则

### 3.1 确定性优先于智能（Determinism First）

自我修复以**确定性手段优先**：能机械修复的（lint 格式）绝不调用模型；只有简单类型错误（缺 import / 缺标注）才允许模型介入，且必须走审批 + 快照回滚。降低「修 1 个错误引入 3 个错误」的风险（审查 🟡#8）。

### 3.2 复用优先（Reuse First）

凡 v3.0 已交付的能力（parseVerifyOutput、SnapshotManager、AuditLogger、技能市场安装器、paths.ts 单一来源），一律复用并显式标注复用点，禁止重复建设（审查 🔴#2/#3）。

### 3.3 隔离矩阵显式化（Explicit Isolation）

多项目 / 多账号的隔离维度（会话 / 知识 / 记忆 / 审批 / MCP / 配置）必须在设计阶段写清「哪些隔离、哪些共享」，而非一句「环境隔离」带过（审查 🟡#11）。

### 3.4 跨平台兼容性保持（Cross-Platform）

v3.0 已建立命令适配层，v3.1 所有新增模块（self-heal / project / team / account）必须保持 Windows / macOS / Linux 行为一致；新增 shell 命令（如 `npm run lint:fix`）仍走 `getPlatformAdapter()`。

### 4.2 AI 自我修复闭环（M1）数据流

```text
npm run verify 失败
   │
   ▼
VerifyReport 分类器（src/loop/self-heal.ts）
   ├── stage=lint   → 确定性执行 npm run lint:fix（免审批，白名单直跑）
   ├── stage=type   → 简单类型错误（缺 import/标注）→ 模型生成修复（走审批）
   ├── stage=build  → 结构化反馈给用户（不自动修）
   └── stage=test   → 结构化反馈给用户（不自动修）
   │
   ▼
修复前快照（SnapshotManager.begin）
   ▼
执行修复 → 修复后强制 npm run verify
   ▼
通过 → commit 快照清理；失败 / 引入新错误 → rollback（diff 审查）
   │
   ▼
修复次数 > MAX_SELF_HEAL_ATTEMPTS（=2）→ 保留详细报告转人工
```

### 4.3 多项目管理（M2）隔离矩阵

| 数据 | 隔离策略 | 实现 |
| --- | --- | --- |
| 会话 | **按项目隔离**：`~/.concertoai/sessions/<projectKey>/` | `src/store/session.ts` 改造 |
| 知识图谱 | 已按项目隔离（保持） | `src/store/paths.ts` `knowledgeDir()` |
| 本地记忆 | 项目级 `<cwd>/.lumen-memory/`（保持） | 不改 |
| 审批白名单 | **按项目存储**：`projects.json` 每项目 `whitelist[]` | `src/store/projects.ts` + `src/tools/shell.ts` |
| MCP 服务 | **按项目声明**：`projects.json` 每项目 `mcpServers[]` | `src/mcp/manager.ts` |
| 全局共享 | config.json 基础配置 / 技能 / Agent / 审计日志 | 不改 |

### 4.4 多租户登录（M3）认证模型

- **账号 = 一个 DeepSeek API Key 配置文件**（参考 git credential 模式），与项目无关
- 存储：`~/.concertoai/accounts/<name>/config.json`（文件权限 0600），`active-account` 指针指向当前账号
- 解析优先级：CLI `--api-key` > 环境变量 `DEEPSEEK_API_KEY` > active account > config.json（若存在）
- 安全：任何命令不打印完整 Key；logout 仅删 active 指针与本地缓存，不删除账户文件（除非显式 `--purge`）

### 4.5 Orchestrator CLI（M5）数据流

```text
concertoai team "<任务>" [--dry-run] [--auto-approve]
   │
   ▼
decomposeRequirement（模型拆解 Task[]，--dry-run 仅输出清单并退出）
   ▼
Orchestrator.run（拓扑调度 → Architect/Coder/Reviewer/QA → 对抗性闭环）
   │
   ▼
事务回滚兜底（SnapshotManager，闭环超限时触发）
   ▼
聚合输出（工件引用 + 中文 summary）+ TraceStore 记录（可观测性面板可见）
```
