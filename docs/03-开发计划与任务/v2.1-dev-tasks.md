## V2.1-M1：子代理 MCP 工具支持（P0，约 4h）

> 背景：v2.0 ADR-007 限制子代理仅使用内置只读工具。v2.1 有条件开放：子代理通过 `allowedMcpServers` 字段声明需要的 MCP 服务，spawner 按声明加载对应工具。默认仍不加载任何 MCP 服务（安全优先）。

### T1.1 SubagentDef.allowedMcpServers + spawner MCP 工具按需加载

**目标**：扩展 `SubagentDef` 类型，新增 `allowedMcpServers` 字段。`SubagentSpawner` 接收 `McpManager` 引用（可选），spawn 子代理时按 `allowedMcpServers` 声明加载对应 MCP 服务的工具到子代理的 ToolRegistry。

**涉及文件**：
- `src/agent/types.ts`（修改 — `SubagentDef.allowedMcpServers?: string[]`）
- `src/agent/spawner.ts`（修改 — 构造函数接收 `McpManager`；spawn 时按声明加载 MCP 工具）
- `src/agent/index.ts`（修改 — 导出更新）

**验收标准**：
- [ ] `SubagentDef` 新增 `allowedMcpServers?: string[]` 字段（不声明 = 不加载 MCP）
- [ ] spawner 构造时接收可选的 `McpManager` 引用
- [ ] spawn 时：若 `allowedMcpServers` 声明了 MCP 服务，调用 `McpManager.getClient(name).listTools()` 获取工具并注册到子代理 ToolRegistry
- [ ] 声明了但未连接的 MCP 服务：跳过（不阻塞子代理启动），日志记录 `[Subagent] MCP 服务 ${name} 不可用，跳过`
- [ ] 子代理的 MCP 工具以原始工具名注册（不加 `serverName/` 前缀——子代理上下文独立，无命名冲突）
- [ ] MCP 工具调用失败时，子代理正常处理（ok:false 回填，不崩溃）

**预估耗时**：2h
**依赖**：无（McpManager 已在 v1.1 实现）

## V2.1-M2：技能嵌套与子代理调用（P0，约 5h）

> 背景：v2.0 ADR-008 限制技能不支持嵌套。v2.1 放开——技能正文中可通过 `@skill:<name>` 引用其他技能、通过 `@agent:<name>` 触发子代理。

**目标**：定义引用语法（`@skill:<name>` / `@agent:<name> <prompt>`），SkillLoader 在加载阶段展开引用——将 `@skill:<name>` 替换为被引用技能的 body，将 `@agent:<name>` 标记为待展开的占位符。

**涉及文件**：
- `src/skill/types.ts`（修改 — 新增 `SkillRef` / `AgentRef` 类型）
- `src/skill/loader.ts`（修改 — 新增 `expandRefs` 方法，解析 @skill / @agent）
- `docs/SKILL.md`（修改 — 新增「技能引用」章节，说明语法和限制）

**验收标准**：
- [ ] `@skill:<name>` 解析为 `SkillRef` 类型
- [ ] `@agent:<name> <prompt>` 解析为 `AgentRef` 类型
- [ ] `@skill:<name>` 在同一次加载中被展开（被引用技能 body 替换占位符）
- [ ] `@agent:<name>` 在加载阶段不展开（保留占位符），由运行时处理
- [ ] 被引用技能不存在时，加载失败并记录错误日志
- [ ] 展开后的技能正文 token 数计入技能大小限制（默认 10KB）

**预估耗时**：2h
**依赖**：无

### T2.2 循环引用检测 + 深度限制

**目标**：在技能加载阶段检测 `@skill` 循环引用（A→B→A 或 A→B→C→A），拒绝加载并报错。限制嵌套深度 ≤ 3 层。

**涉及文件**：
- `src/skill/loader.ts`（修改 — 新增 cycle detection + depth tracking）

**验收标准**：
- [ ] 直接循环（A → A）：检测并拒绝
- [ ] 间接循环（A → B → A）：检测并拒绝
- [ ] 多层循环（A → B → C → A）：检测并拒绝
- [ ] 深度 ≤ 3 的正常链：正常展开
- [ ] 深度 > 3：拒绝并报错 `技能引用深度超过限制（3 层）`
- [ ] 错误信息包含循环路径（如 `技能引用循环: code-review → explain → code-review`）

**预估耗时**：1h
**依赖**：T2.1

**验收标准**：
- [ ] `/skill <name>` 执行时检测到 `@agent:<name>` 引用 → 自动 spawn 子代理
- [ ] 子代理结果替换技能正文中的 `@agent:` 占位符
- [ ] 子代理调用失败时，占位符替换为 `（子代理 ${name} 执行失败: ${error}）`
- [ ] 子代理调用不阻塞其他 `@skill` 引用展开
- [ ] 多个 `@agent` 引用串行执行（避免并发复杂度）

**预估耗时**：2h
**依赖**：T2.1、T2.2、T1.2（需要 spawner 的 MCP 能力）

## V2.1-M4：轻量级知识图谱 + RAG（P1，约 6h）

> 背景：v1.1 的本地 JSONL 记忆只有关键词匹配，MCP memory 依赖外部服务。v2.1 引入嵌入式知识图谱（SQLite），支持实体/关系/观察三层模型 + 语义检索。

### T4.1 知识图谱存储层（types + store）

**目标**：定义知识图谱的三层数据模型（Entity / Relation / Observation），实现 SQLite 存储层（CRUD + 查询）。

**涉及文件**：
- `src/knowledge/types.ts`（新增 — `KnowledgeEntity`、`KnowledgeRelation`、`KnowledgeObservation` 类型）
- `src/knowledge/store.ts`（新增 — SQLite 存储：初始化表结构、CRUD 操作）
- `src/knowledge/index.ts`（新增 — barrel 导出）

**验收标准**：
- [ ] `KnowledgeEntity` 类型：`name`、`entityType`、`observations[]`
- [ ] `KnowledgeRelation` 类型：`from`、`to`、`relationType`
- [ ] SQLite 数据库文件存储在 `~/.lumen/knowledge/{projectHash}.db`（按项目隔离）
- [ ] CRUD 操作：createEntities / createRelations / addObservations / deleteEntities / deleteObservations / deleteRelations
- [ ] 查询操作：searchNodes(query) / openNodes(names) / readGraph()
- [ ] SQLite 不可用时（原生模块问题）降级到 JSONL 文件存储
