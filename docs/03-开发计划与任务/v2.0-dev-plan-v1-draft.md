Lumen v2.0 开发计划
状态：愿景草案（2026-08-08）
基础：v1.0 已完成、v1.1 规划中
定位：从「个人编码助手」升级到「可扩展的 AI 开发平台」

1. 定位与 2.0 定义
v2.0 定位：Lumen 从「个人编码助手」进化为「可扩展的 AI 开发平台」。核心是建立完善的 Agent 生态，支持多 Agent 协作、技能系统、插件市场，以及更智能的任务编排能力。

核心升级方向：

方向	v1.x 现状	v2.0 目标
Agent 架构	单一 Agent，顺序执行	多 Agent 协作，可并行、可委托
技能系统	内置固定能力	可定义、可分享的 Skill 技能包
插件市场	无	支持第三方插件安装与发现
任务编排	线性 Plan 模式	支持条件分支、循环、并行 DAG 任务流
知识库	基础跨会话记忆	结构化项目知识图谱 + RAG 检索
完成定义：npm run verify 全绿、测试用例 ≥ 350、核心插件市场有 3 个以上可用插件。

2.2 多 Agent 协作架构
text
┌─────────────────────────────────────────────────────────┐
│                   Orchestrator Agent                    │
│              (任务分解、调度、结果整合)                   │
└──────────┬──────────┬──────────┬───────────────────────┘
           │          │          │
    ┌──────▼─────┐ ┌──▼───────┐ ┌▼─────────┐
    │  Architect │ │  Coder   │ │  Tester  │
    │   Agent    │ │  Agent   │ │  Agent   │
    └────────────┘ └──────────┘ └──────────┘
Agent 类型：

Agent 类型	职责	可用工具
Orchestrator	任务分解、调度、结果整合	全部工具 + 规划
Architect	设计方案、技术选型、架构评审	只读工具 + 设计模式库
Coder	代码编写、重构、实现	全部工具（写权限）
Tester	测试用例生成、执行、质量检查	只读 + 测试工具
Explorer	代码探索、文档检索、知识获取	只读 + 搜索工具
2.3 Skill 技能系统
Skill 定义规范（SKILL.md）：

markdown
---
name: code-review
description: 执行代码审查，检查代码质量、安全性和最佳实践
version: 1.0.0
author: lumen
tags: [review, quality, security]
---

## 技能描述

执行全面的代码审查，包括：
- 代码风格检查
- 潜在 bug 检测
- 安全漏洞扫描
- 性能优化建议

## 使用方式

在对话中输入：`/skill code-review` 或 `请对 src/ 目录执行代码审查`

## 依赖工具

- read_file
- search_content
- lint（调用 Biome）
内置技能清单：

code-review：代码审查

refactor：代码重构助手

doc-generate：文档生成

test-write：测试用例编写

explain：代码解释器

6. 不做清单（明确排除）
项目	理由
桌面端 GUI	与 CLI 定位冲突
云端 SaaS	超出个人工具定位
多模型后端（非 DeepSeek）	当前无需求
完全自动化的 Agent 自主决策	安全风险高，需逐步探索
7. 风险与开放问题
风险	影响	缓解
Agent 间通信复杂度	稳定性下降	采用标准协议，充分测试
Skill 执行安全	可能执行恶意代码	实现 Skill 沙箱，权限控制
插件生态冷启动	缺乏第三方插件	内置 3-5 个官方插件作为标杆
知识图谱数据膨胀	存储和检索性能下降	设计数据生命周期管理
开放问题：

Agent 间的信任边界如何定义？

Skill 能否调用 Agent 能力（即 Skill 是否成为一等公民）？

插件系统是否需要支持闭源分发？
