## 1. 定位与 v3.3 定义

v3.2 定位回顾：从「功能可用」进化为「跨平台可靠 + 长任务可感知 + 代码可维护」，总评 9.2/10，审查结论「✅ 可发布」。

v3.3 定位：**消化 v3.2 审查遗留 + 质量收尾**。审查报告明确将 5 项改进标注为「v3.3 方向」（2 警告 W1/W2 + 3 完善建议 S1-S3），不做新的大功能面，聚焦：

- **代码健壮性**：W1（lint:fix 失败 break 语义显式化）、W2（全局正则 g 标志脆弱模式移除）
- **国际化一致性**：S1（self-heal 阶段/动作文案硬编码中文 → i18n 字典，`--lang en` 下不再混合中英）
- **测试样本统一**：S2（存量解析测试迁移到 `platform-samples.ts`，减少内联样本散落）
- **缓存语义明确**：S3（`resolveApiKeyCached` 补过期机制注释，消除长驻进程误解）

> **4.0 决策**（用户咨询后结论）：**先做 v3.3，4.0 延后**。语义化版本 4.0 应承载破坏性变更或重大架构升级（插件市场 / DAG 工作流 / TypeScript 7 评估），当前无紧迫需求；已识别的 5 项审查遗留应尽快闭环，保持 3.x 连续迭代节奏（3.0→3.1→3.2→3.3）。4.0 立项条件：v3.3 完成且基线稳定后，另行评估大功能面。

## 2. 现状盘点（v3.2 → v3.3 差距）

| 维度 | v3.2 现状（88 文件 / 1014 用例） | v3.3 差距 | 优先级 |
|------|----------------------------------|-----------|--------|
| W1 lint:fix 失败 break | `repair.ts` L105-108：`if (!fix.ok) { log(...); break; }` 直接 break，未说明「剩余 type 错误已跳过」 | break 前补注释/log 显式化语义 | P1 |
| W2 全局正则 g 标志 | `classifier.ts` `BIOME_RULE_ERROR_RE` / `BIOME_FORMAT_ERROR_RE` 常量带 `g`（当前用 `new RegExp(source,'g')` 规避 lastIndex 陷阱，但常量本身是脆弱模式） | 常量去 `g`，由使用处按需添加 | P1 |

**不做**：4.0 大功能面（插件市场 / DAG / TS7）不在 v3.3 范围；v3.2 已通过的 1004+ 用例只做回归保持。

## 3. 核心设计原则

3.1 **复用优先（Reuse First）**：v3.2 已交付的 `platform-samples.ts` / i18n 架构 / 解析器一律复用，不重复建设。

3.2 **最小变更（Minimal Change）**：v3.3 是收尾型小版本，每项任务都是「小步增量」，禁止顺手重构无关模块；行为不变，只补语义/一致性。

3.3 **国际化基线（i18n Baseline）**：`--lang en` 已支持的模块文案必须进 i18n 字典；新增文案一律走 `t()`，禁止硬编码中文（为 4.0 国际化铺路）。

3.4 **测试样本统一（Unified Samples）**：解析类测试统一引用 `platform-samples.ts`，新样本加入样本库而非测试内联（S2 完成后基线）。
