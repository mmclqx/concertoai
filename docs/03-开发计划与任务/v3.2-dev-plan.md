1. 定位与 v3.2 定义
v3.1 定位回顾：修复多 Agent 稳定性短板 + 补齐 CLI 日常体验（self-heal / project / account / team / audit），从「能协作的团队」进化为「能稳定协作、能自我修复、能跨项目使用的可靠工具」，专家评分 8.5/10。

v3.2 定位：**从「功能可用」进化为「跨平台可靠 + 长任务可感知 + 代码可维护」**。v3.1 核心功能已完整，但专家评价明确指出最大短板是「Windows 兼容性和边缘场景测试」、self-heal.ts 853 行偏大、team 执行无进度反馈。v3.2 不做新的大功能面，聚焦三类投入：

- 跨平台可靠性：Windows CI 矩阵 + spawn/路径边界补齐（把 v3.1.1 的「事后修补」固化为「事前防线」）
- 长任务可感知：team / self-heal 进度反馈（降低「黑盒等待」不安感）
- 代码可维护性：self-heal.ts 拆分（870 行 → <400 行）+ 错误处理补强

3. 核心设计原则
3.1 复用优先（Reuse First）
v3.1 已交付的能力（getPlatformAdapter、parseVerifyOutput、SnapshotManager、AuditLogger、inferErrorCode 英文匹配）一律复用，禁止重复建设；v3.1.1 已修复的问题只做回归保持，不重做。

3.2 跨平台兼容性固化为基线（Cross-Platform as Baseline）
Windows / macOS / Linux 三平台纳入 CI 矩阵；所有新增命令与解析必须用双平台样本测试（Windows 反斜杠路径/盘符冒号 vs POSIX）。「事后修补」升级为「事前防线」。

3.3 长任务可感知（Observable Long Tasks）
所有预计执行 >10s 的命令（team / self-heal / /orchestrate / /review）必须推送中间进度（阶段变更回调），不允许「黑盒等待」。

3.4 小文件优先（Small Files）
新增模块单文件 ≤400 行；self-heal.ts 拆分是 v3.2 硬性任务；重构不改变公共 API 与行为（纯结构迁移 + 回归全绿）。
