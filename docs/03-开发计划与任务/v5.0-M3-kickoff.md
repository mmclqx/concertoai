## 2. T12 增量规格（在任务书 T12 之上叠加，冲突以本节为准）

### 2.1 触发条件（苛刻，宁少勿多）

只允许**确定性**条件，禁止任何「推测 / 打分 / 权重」：

| 规则 id | 触发条件（全部为真才触发） | 提示的命令 |
|---|---|---|
| `missing-project-rules` | `hasProjectRules === false` 且 会话已产生 ≥1 轮用户输入 | `concertoai init` |
| `repeated-verify-failure` | **连续 2 轮** verify 类失败（`consecutiveFailures >= 2`） | `concertoai self-heal` |
| `repeated-edit-rejection` | **同一文件连续 2 次**被拒绝（`fileRejectStreak >= 2`） | `/review <file>` |

**禁止**：基于耗时、Token 数、消息长度、模型自评等间接信号触发（这类信号不可靠，且容易变成噪音源——v4.0「进度刷屏 / 输出淹没」教训）。

### 2.2 硬约束（**在引擎内实现，不靠调用方自觉**）

| # | 约束 | 实现位置 |
|---|---|---|
| ① | 同时最多返回 **1 条**（按 priority 取最高） | `evaluateSuggestion` 内 |
| ② | 同一 `id` **每会话 1 次** | 内存 `Set` |
| ③ | 同一 `id` **全局 10 分钟冷却**（持久化 `~/.concertoai/tip-state.json`，重启仍生效） | 纯函数层判定 + 调用方读写 |
| ④ | **每会话总计最多 3 条**（跨 id，用户新增） | 内存计数器 |
| ⑤ | **用户按 Esc / 忽略 → 立刻静默**（用户新增） | `dismissSession()` 一次性关闭本会话全部提示 |
| ⑥ | `hints: 'off'`（或环境变量关）→ 恒返回 `null` | 入口判定 |
| ⑦ | 引擎**纯函数**：无 IO、无 `Date.now()` 直接调用（时间必须注入 `now`） | 全程注入 |

### 2.3 命令可用性护栏（用户新增，必须有）

**护栏用例形态**（沿用 T10 `approval-reflect.test.tsx` 的做法）：

```ts
// 断言提示里给的命令，在真实的 commander --help 输出里确实注册过
// 不是断言「文案里有这个字符串」，而是断言「这个命令真的存在」
it('每条规则的 command 都能在 --help 里找到对应注册', async () => {
  const help = execFileSync(process.execPath, [cliPath, '--help'], { encoding: 'utf8' });
  for (const rule of SUGGESTION_RULES) {
    // 斜杠命令（/review）走 chat 内注册表校验，CLI 命令走 --help 校验
    expect(commandIsRunnable(rule.command, help)).toBe(true);
  }
});
```

理由：T10 已经吃过一次「文案承诺了不存在的命令」的教训（`config set reflections off` 当时还没实现）——**提示里的话是承诺，不能是空头支票**。

**本备忘的三条命令已当场核实存在**（2026-10-28 02:56，实跑 `dist/cli/index.js --help` 与扫 `App.tsx` 斜杠分派）：

## 3. ⚠️ 开工第一件事：配置项命名冲突（必须先确认）

| 来源 | 名称 |
|---|---|
| **用户拍板** | `config.hints: on \| off` |
| **任务书 T12 原文** | `config.tips: 'on' \| 'off'` |

两者不一致，**开工前必须定一个**（代码、i18n、用户手册、CHANGELOG、护栏用例五处联动，改起来成本不低，不能中途改）。

**我的建议：用 `hints`**（按用户拍板），理由：
1. 用户是最终决策者，拍板用词应作为产品口径；
2. `hints` 语义更准确——它提示的是「下一步该做什么」，而非「小技巧」；
3. 与既有 `approvalInsight`（洞察）语域一致，`tips` 容易与未来的「使用技巧」功能撞名。

**待用户确认后**：同步修订 `v5.0-dev-tasks.md` T12 的「涉及文件」段（把 `tips` 改为 `hints`），并在 CHANGELOG / user-guide 保持一致。
