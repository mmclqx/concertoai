1. 定位与 v3.1 定义
v3.0 定位回顾：从「可协作的伙伴」进化为「多智能体协同的 AI 开发团队」（Orchestrator + Architect/Coder/Reviewer/QA 四角色 + 对抗性闭环）。

v3.1 定位：修复 v3.0 多 Agent 系统的稳定性短板 + 补齐 CLI 日常使用的基础体验缺口，从「能协作的团队」进化为「能稳定协作、能自我修复、能跨项目使用的可靠工具」。

3. 核心设计原则
3.1 确定性优先于智能（Determinism First）
自我修复以确定性手段优先：能机械修复的（lint 格式）绝不调用模型；只有简单类型错误才允许模型介入，且必须走审批 + 快照回滚。

3.2 复用优先（Reuse First）
凡 v3.0 已交付的能力（parseVerifyOutput、SnapshotManager、AuditLogger、paths.ts），一律复用，禁止重复建设。

3.3 隔离矩阵显式化（Explicit Isolation）
多项目隔离维度（会话 / 知识 / 记忆 / 审批 / MCP / 配置）在设计阶段写清「哪些隔离、哪些共享」。

3.4 跨平台兼容性保持（Cross-Platform）
所有新增模块必须保持 Windows / macOS / Linux 行为一致。
