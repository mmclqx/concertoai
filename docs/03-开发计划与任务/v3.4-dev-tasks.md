## V3.4-M3：VS Code 崩溃防护（P1，约 2h）

> 背景：2026-08-11 深夜 VS Code 再次闪退（12 转储 / 511MB / 83 进程）。排查发现上轮「禁用 5 扩展」写入 `%APPDATA%\Code\argv.json`，但 VS Code 实际读取 `%USERPROFILE%\.vscode\argv.json` → 禁用从未生效，扩展全在加载 + 14 窗口×全套 AI 扩展 = 组合爆炸。本里程碑将排查 SOP 固化为 `concertoai doctor --vscode` 健康检查（详见 `docs/09-踩坑记录/2026-08-11-VSCode频繁崩溃内存溢出.md` §五）。

### T3.1 VS Code 进程数检测

**目标**：统计 Code.exe（Windows）/ Code（macOS/Linux）进程数，阈值告警，输出「关闭多余窗口」建议。

**涉及文件**：
- `src/cli/doctor.ts`（修改 — 新增 VS Code 检查模块 `diagnoseVscodeProcesses`）
- 平台适配：复用 `src/tools/shell.ts` 的 `getPlatformAdapter`（或新增 `src/cli/vscode-health.ts` 独立模块，含平台路径/命令适配）

**实现要点**：
- Windows：`tasklist /fi "imagename eq Code.exe"` 输出按行计数（排除表头）；或 PowerShell `Get-Process Code` 计数
- macOS/Linux：`ps -e -o comm | grep -c Code`（或 `pgrep -c Code`）
- 阈值：进程数 > 60 → ❌ 严重（对应 14 窗口×扩展组合）；> 40 → ⚠️ 警告；≤ 40 → ✅ 正常
- 检测失败（命令不存在/超时）→ ⚠️ 无法检测（不崩溃）

**验收标准**：
- [ ] 进程数解析正确（Windows tasklist 样本 + POSIX ps 样本双测试）
- [ ] 阈值分级输出 ✅/⚠️/❌ 与建议文案（「建议关闭多余窗口，合并工作区」）
- [ ] 命令超时（如 5s）降级不崩溃
- [ ] 新增单元测试 ≥ 2（解析 + 阈值分级）

**预估耗时**：0.5h
**依赖**：无

### T3.2 崩溃转储堆积检测

**目标**：扫描 Crashpad 目录 `.dmp` 文件数量与总体积，>5 个或 >100MB 告警，输出清理命令（只读检测，不代删）。

**涉及文件**：
- `src/cli/vscode-health.ts`（新增 — `detectCrashDumps`）
- `src/cli/doctor.ts`（修改 — 接入）

**实现要点**：
- 路径适配（getPlatformAdapter）：
  - Windows：`%APPDATA%\Code\Crashpad\reports`
  - macOS：`~/Library/Application Support/Code/Crashpad/reports`
  - Linux：`~/.config/Code/Crashpad/reports`
- 目录不存在 → ✅ 正常（无转储）；存在 → 统计 `*.dmp` 数量 + 字节总和
- 阈值：数量 > 5 或 体积 > 100MB → ❌；1~5 个 → ⚠️；0 → ✅
- 建议命令：`del /q "%APPDATA%\Code\Crashpad\reports\*.dmp"`（Windows）/ `rm .../*.dmp`（POSIX）

**验收标准**：
- [ ] 三平台路径映射正确（平台适配单测）
- [ ] 数量/体积统计正确（构造临时目录 + 假 .dmp 文件测试）
- [ ] 目录缺失/无读权限降级不崩溃
- [ ] 新增单元测试 ≥ 2

**预估耗时**：0.25h
**依赖**：T3.1（共享平台适配）

### T3.3 AI 扩展数量与 argv.json 核对

**目标**：解析 `code --list-extensions` 统计 AI 助手类扩展数量（>3 告警）；读取 `~/.vscode/argv.json` 核对 disable-extension 是否覆盖冗余 AI 扩展；检测无效 argv.json 位置（历史坑：`%APPDATA%\Code\argv.json` 从未生效）。

**涉及文件**：
- `src/cli/vscode-health.ts`（新增 — `detectAiExtensions` / `verifyArgvJson`）
- `src/cli/doctor.ts`（修改 — 接入）

**实现要点**：
- 已知 AI 扩展 ID 清单（常量数组，可维护）：`anthropic.claude-code`、`continue.continue`、`openai.chatgpt`、`marscode.marscode-extension`、`alibaba-cloud.tongyi-lingma`、`danielsanmedium.dscodegpt`、`ms-dotnettools.csdevkit`（C# DevKit 进程大户）等
- `code --list-extensions` 输出解析：`<id>@<version>` 行，取 id；命令不存在 → ⚠️ 无法检测
- argv.json 路径（平台适配）：Windows/macOS/Linux 均为 `~/.vscode/argv.json`；Windows 额外检测 `%APPDATA%\Code\argv.json` 是否存在（存在 → ⚠️「无效位置，VS Code 不读取，建议删除或移走」——本次复发根因）
- 核对逻辑：已安装 AI 扩展 ∩ 未在 disable-extension 中 → 列出 + 建议命令 `code --disable-extension <id>` 或写入 argv.json（给出 JSON 片段）
- 无扩展检测能力时（code CLI 不在 PATH）→ ⚠️ 降级

**验收标准**：
- [ ] `code --list-extensions` 样本解析正确（含 @ 版本号、多行、Windows 路径）
- [ ] argv.json 读取/解析（JSON 含注释容错——VS Code argv.json 有 `//` 注释，用去除注释后再 JSON.parse 或正则提取 disable-extension）
- [ ] 已装未禁用 AI 扩展 → 告警 + 建议命令；全部禁用 → ✅
- [ ] 无效位置 argv.json 检测（Windows `%APPDATA%\Code\argv.json` 存在 → ⚠️）
- [ ] 新增单元测试 ≥ 4（扩展解析 / argv.json 解析 / 核对逻辑 / 无效位置）

**预估耗时**：0.5h
**依赖**：T3.1（共享平台适配）
