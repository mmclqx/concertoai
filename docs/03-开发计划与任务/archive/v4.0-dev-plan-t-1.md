1. 定位与 v4.0 定义
v4.0 一句话定位：让 ConcertoAI 从"对话式助手"进化为"你说需求，它完成工作"。

三个用户可感知的升级：

升级	用户怎么说	交付物
能自动修了	"审查完不用手动改了"	/review --fix——审查报告出完，直接问"要修吗？"，一键批量修复
能记住流程了	"发版不用每次指挥了"	concertoai workflow run release——预定义模板，一个命令跑完整个流程
能换模型了	"我想用 OpenAI / 本地 Ollama，但不知道哪个划算" [补充]	--provider openai / 切换时显示成本对比，doctor 推荐最优模型
完成定义：第 6 节发布门检查清单全部通过。用户从"审查完"到"修好"的时间从 10 分钟（手动）降到 30 秒（一键）。

V4.0-M1：审查完就能修——/review --fix（约 5h）
用户故事：

我运行 /review，ConcertoAI 告诉我 15 个建议。以前我得手动一个个改。现在它问"要自动修复吗？"我说 y，它修好 12 个能自动修的，剩下 3 个复杂的一起展示给我，我一次确认。修完自动跑 verify，哪修坏了自动回滚。全程我只说了一个"y"。

用户价值：审查→修复 从 10 分钟降到 30 秒。

T1.5	安全阀门：审批 fail-closed（用户拒绝→不写盘）；快照回滚兜底（写盘后 verify 失败→自动恢复）；增量 verify（只测改过的文件，快）	修不坏代码	0.5h

6. 用户升级指南（v3.4 → v4.0）
升级步骤
bash
npm install -g @concertoai/cli@latest
concertoai doctor  # 验证环境，自动迁移 config，检测迁移完整性
新功能速览
功能	怎么用
审查自动修复	/review --fix
工作流	concertoai workflow init 选模板，然后 concertoai workflow run <name>
切换模型	concertoai --provider openai（切换前显示成本对比）[补充]
设置 API Key	concertoai provider auth openai [补充]
装插件	concertoai plugin install <name>
逛插件市场	concertoai plugin browse / plugin recommend [补充]
多 Agent 并行	直接说"同时做 A 和 B"
IDE 诊断	VS Code 配置 concertoai lsp --stdio
破坏性变更
config.json 格式升级：model 字段 → defaultProvider + providers。启动时自动迁移，旧配置备份为 config.v3.bak。你不需要做任何事。

插件市场新增 plugins[]：旧 skill/Agent 完全兼容，不受影响。

新增 workflow/plugin/Provider 配置项：均为可选，不影响现有配置。[补充]

插件必须 ESM：与 ConcertoAI 运行时一致，对用户无影响。[补充]

升级失败怎么办 [补充：整节新增]
bash
# 回滚到 v3.4
npm install -g @concertoai/cli@3.4.0

# 恢复 v3 配置（如果自动迁移有问题）
concertoai config restore  # 从 config.v3.bak 恢复

# v4.0 的会话记录与 v3.4 兼容，降级后可继续使用
性能预期 [补充：整节新增]
Q：v4.0 会比 v3.4 慢吗？
A：不会。插件在主进程内运行（无额外进程开销）。Provider 切换不增加延迟。首次安装插件时需下载（视网络情况），之后即时加载。LSP 诊断在文件保存时异步推送，不影响编辑流畅度。M8 将发布 v3.4 vs v4.0 性能基准对比。
