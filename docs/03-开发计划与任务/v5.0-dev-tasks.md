## 执行规范

1. **开始任务前**：阅读该任务完整定义，确认「依赖」列出的任务已完成
2. **执行任务**：按「验收标准」逐项实现；**每项验收标准都要打勾**，未打勾不得进入下一任务
3. **任务完成后**：执行 `npm run verify` 确保全绿，然后更新 `TASKS.md` 看板
4. **提交代码**：`git add . && git commit -m "feat/v5.0-<Tn>: <任务名称>"`
5. **生成总结**：按下方模板输出

### v5.0 全局硬约束（每个任务都适用，违反即返工）

| # | 约束 | 说明 |
|---|---|---|
| G1 | **安全不降级** | 所有改动**不得**降低审批强度。`approvalPolicy` / fail-closed / 无 yolo 的行为与 v4.1.1 逐字节一致 |
| G2 | **分析永不阻断审批** | 任何审批内分析（T8/T9）必须 `try/catch` 包裹：分析抛错 → 降级为 plain 审批框，**审批流程照常进行** |
| G3 | **有超时就有降级** | 任何可能超 100ms 的操作必须有硬超时 + 明确降级文案，禁止静默阻塞 |
| G4 | **i18n 双份** | 所有用户可见文案同时进 `src/i18n/zh.ts` + `en.ts`，缺一即返工 |
| G5 | **边缘路径四覆盖** | 每个新命令/新交互必须覆盖：① 首次运行（环境未初始化）② 失败后恢复 ③ 主动退出（Ctrl+C / n / 超时）④ 输出超长截断 |
| G6 | **薄包装** | 4 个动词（T15-T18）复用既有引擎，**禁止复制第二套 verify 解析 / message 生成 / 审查逻辑** |
| G7 | **证据优先** | AI 生成的结构化内容（AGENTS.md / PROJECT_GUIDE.md / commit message）每段必须引用真实 `文件:行号`；无证据写「未检测到」，禁止编造 |
| G8 | **零网络默认** | T10 复盘记录 / T21 指标一律本地 JSONL，零网络、可关闭、可清空；不上传 |

## V5.0-M2：审批透明化（主战场一，约 6.5h）

> **背景（决策 D2-A）**：v4.1.1 的审批框只有「编辑文件 X」+ diff。用户按下 y 之前不知道自己在批什么——这是「替用户做判断」而非「帮用户长判断力」。v5.0 让审批框变成一次**风险教学**：说清影响面、风险点、该重点看哪一行。
>
> **技术红线（专家复核重点）**：审批是**同步阻塞**交互，分析**绝不能拖慢审批**。因此强制两层设计 + 硬超时 + 降级矩阵，且**任何分析异常都不得阻断审批**（G2）。
>
> **皇冠上的明珠**：T8 + T9 —— 本版本技术风险最高处，验收标准最严。

#### T8.1 类型契约（先定接口再写实现）

```ts
export type RiskLevel = 'high' | 'medium' | 'low';

export interface RiskHit {
  ruleId: string;                    // 规则标识，如 'dangerous-delete'
  category: string;                  // 人类可读类别，如 '删除/破坏性操作'
  level: RiskLevel;
  side: 'added' | 'removed';         // 命中在新增行还是删除行
  line: string;                      // 命中行原文（已 trimEnd）
  diffLineIndex: number;             // 在 diff 中的行下标（供 T9 打 ⚠️）
  why: string;                       // 一句人话解释：为什么这是风险
  suggestion: string;                // 一句建议关注点（进「💡 建议重点关注」）
}

export interface ImpactSummary {
  status: 'ok' | 'timeout' | 'skipped' | 'error';
  referenceCount: number;            // 引用本文件的文件数
  topPaths: string[];                // 前 3 个引用者（相对路径，正斜杠）
  exportedSymbols: string[];         // 本文件导出符号（决定影响面怎么算）
  scannedCount: number;              // 实际扫描文件数
  skippedCount: number;              // 读取失败/跳过文件数（EMFILE/EACCES/EPERM/ENOENT）
  elapsedMs: number;
}

export interface ApprovalInsight {
  level: RiskLevel;                  // 总风险等级 = max(hits.level)，无命中为 low
  changeNatures: string[];           // 改动性质（从 hits 聚合，如 ['替换网络超时逻辑']）
  hits: RiskHit[];                   // 命中明细，按 level 降序 + diffLineIndex 升序
  focusLines: number[];              // 建议重点关注行（T9 用来打 ⚠️）
  impact: ImpactSummary;
  degraded: boolean;                 // true = 走了降级路径
  degradeReason?: 'non-tty' | 'ci' | 'huge-diff' | 'timeout' | 'error' | 'config-off';
  elapsedMs: number;                 // 总耗时（性能门用）
}
```

#### T8.3 Windows 正则红线清单（**必须逐条验证，代码审查检查项**）

> 专家指定重点。违反任一条 = 生产事故级（v4.1.1 已因反斜杠路径正则在 Biome 解析上翻过车，见 `docs/09-踩坑记录/2026-08-11-Biome解析漏掉format与assist类别错误.md`）。

| # | 红线 | 错误写法 | 正确写法 | 验证方式 |
|---|---|---|---|---|
| W1 | **反斜杠必须双转义** | `/path\.join.*\.\./` 里写 `\` 单层 | 字符类用 `[\\/]`，字面反斜杠用 `\\\\` | 单测：`path.join('..\\a')` 与 `path.join('../a')` 都必须命中 |
| W2 | **CRLF 行尾必须先剥 `\r`** | 直接 `diff.split('\n')` 后匹配 `$` 锚点 | `line.replace(/\r$/, '')`（或 `trimEnd()`），**匹配前统一剥** | 单测：同一规则喂 LF 版本与 CRLF 版本 diff，命中结果**必须完全相同** |
| W3 | **路径分隔符统一正斜杠** | 用 `\` 做包含判断 | 先 `normalizePath(p) = p.split(sep).join('/')` | 单测：`src\\api\\x.ts` 与 `src/api/x.ts` 归一化后相等 |
| W4 | **大小写不敏感匹配** | `'SRC/API'.includes('src/api')` | 路径比较用 `.toLowerCase()`；正则加 `i` flag | 单测：`SRC\\Api\\X.TS` 能命中 `src/api/x.ts` 规则 |
| W5 | **盘符冒号不误判** | 用 `:` 切分路径 | 禁止用 `:` 切路径；需要根判断时用 `/^[a-zA-Z]:[\\/]/` | 单测：`C:\\proj\\a.ts` 不被拆错 |
| W6 | **不使用字符偏移切 diff 行** | `line.slice(column)` 定位 | 用**整行匹配 + 行下标**，不做列偏移（中文/emoji 宽度不可靠） | 单测：含中文注释与 emoji 的 diff 行命中正确 |
| W7 | **BOM 不破坏首行匹配** | 忽略 BOM | 首行 `replace(/^\uFEFF/, '')` 再匹配 | 单测：BOM + `rm -rf` 首行仍命中 |
| W8 | **长行不回溯爆炸** | `.*.*.*x` 类嵌套量词 | 禁用嵌套量词；单条正则长度控制；必要时先 `includes()` 粗筛再正则 | 单测：10 万字符单行 diff 耗时 < 20ms（防 ReDoS） |
| W9 | **URL 里的 `//` 不当注释** | `^\s*(//\|#)` 会把 `https://` 判成注释 | 注释判定用 `^\s*//` 且要求**行首**（`/^\s*\/\//`），不匹配行中出现 | 单测：`const u = "https://x"` 不被判为注释行 |
| W10 | **glob/正则元字符不裸用** | 用文件路径直接构造 `new RegExp(path)` | 文件路径一律 `escapeRegExp(path)`，且**优先 `includes()` 而非正则** | 单测：路径含 `(`/`[`/`+`/`.` 时不抛异常且匹配正确 |

**另有平台无关红线**：**禁止 `new RegExp(动态字符串)` 出现在规则匹配的热路径**（v3.4 已因 `new RegExp` 的 `lastIndex` 残留踩坑）——规则表全部用**字面量正则**（`biome` 也会强制）。

#### T8.4 影响面分析（`impact-scan.ts`）与 300ms 硬超时降级

> 专家指定重点。**这是唯一有 IO 的环节，也是唯一可能卡住审批的地方。**

**执行策略**：
1. **仅在中高风险时执行**（`level === 'high' || level === 'medium'`）；`low` 直接跳过（`status: 'skipped'`）——省掉 90% 的 IO
2. **范围收敛**：只回答「谁 import 了本文件」——用**导出符号名**在项目源文件中做 `includes()` 粗筛（不做 AST、不做全库语义分析），再确认行内含 `from '<该文件路径>'`
3. **扫描约束**：跳过 `node_modules` / `dist` / `.git` / `build` / `coverage` / `*.min.js`；文件类型白名单 `.ts .tsx .js .jsx .mjs .cjs`；**文件数上限 2000**（超出则 `status: 'skipped'` 并提示「项目过大，影响面未分析」）
4. **并发读取（专家加固，必须照做）**：**禁止裸 `Promise.all(files.map(readFile))`**——Windows 下 Node 的 `fs.readFile` 极易触发 `EMFILE`（句柄耗尽），2000 文件一次铺开必崩，整个审批体验直接毁掉。采用**并发池**：
   - 方案 A（优先）：`graceful-fs` 的 `gracefulify(fs)`——它在 EMFILE 时自动排队重试（代价：新增 1 个 runtime 依赖，需并入 T4 THIRD_PARTY_NOTICES）
   - 方案 B（零依赖兜底）：自实现固定并发池 `runWithConcurrency(tasks, limit = 32)`——信号量 + 队列，任一任务完成才启动下一个，**并发数上限 32**
   - **决策**：先试方案 B（零依赖更可控、行为可测），若实测仍有 EMFILE 再引 graceful-fs；两种方案的**公开接口一致**，便于切换
   - 每个文件读失败（`EMFILE` / `EACCES` / `EPERM` / `ENOENT`）→ **计入 `skippedCount` 继续**，绝不中断整体；`ImpactSummary` 增加 `skippedCount` 字段（读取失败数）
5. **300ms 硬超时**：`Promise.race([scan, timeout(300)])`；超时返回 `status: 'timeout'` + 已完成的部分结果（不丢弃已算出的引用）
6. **5s TTL 缓存**：key = `normalizePath(文件) + '|' + mtimeMs`；否则连续多次编辑同一文件会重复扫描
7. **每个文件 IO 独立 try/catch**：`EACCES` / `ENOENT` / `EPERM`（Windows 文件锁）→ 跳过该文件，不中断整体

**降级矩阵（`degraded` / `degradeReason` 的唯一来源，实现必须与此表逐行对应）**：

| 触发条件 | `degraded` | `degradeReason` | 审批框表现 | 审批流程 |
|---|---|---|---|---|
| `!process.stdout.isTTY` | true | `'non-tty'` | 完全 plain（v4.1.1 原貌） | 正常 |
| `process.env.CI` 存在 | true | `'ci'` | 完全 plain | 正常 |
| diff 行数 > 500 | true | `'huge-diff'` | 只显示「共 N 行改动，风险分析已跳过（超大 diff）」，**不逐行分析** | 正常 |
| `analyzeImpact` 超 300ms | false（局部） | `'timeout'`（记在 `impact`） | 风险点照常显示，影响面区显示「影响面未分析（超时 300ms）」 | 正常 |

| config `approvalInsight: 'plain'` | true | `'config-off'` | 完全 plain | 正常 |
| 规则表为空 / 全部未命中 | false | — | 显示「✅ 未检测到已知风险模式（已检查 N 类）」 | 正常 |
| 文件数 > 2000 | false | `'skipped'`（记在 `impact`） | 显示「项目较大，影响面未分析」 | 正常 |

#### T9.3c 渲染节流（专家加固，防终端闪烁）

> 专家原话：「当 diff 很长、或者用户疯狂按 [v] 切换时，限制一帧内的状态更新频率，否则终端可能会闪烁。」

**实现要求**：
- `[v]` / `[?]` 切换走 **`setState` 节流**：最小间隔 **80ms**（`RENDER_THROTTLE_MS = 80`），期间连击只取最后一次意图（**丢弃中间态而非排队**，避免连按 10 次排队渲染 10 帧）
- 实现方式：`useRef` 记录 `lastRenderAt` + 未到期时写入 `pendingToggleRef`，到期后一次性 flush；**不使用 `setInterval` 轮询**
- 节流只作用于**展示态切换**（`[v]`/`[?]`），**绝不节流 `y`/`n` 审批决议**（安全红线：按键必须即时响应，G1）
- 退出时（组件卸载 / 审批完成）清空 pending，**不留悬挂 timer**（测试断言无未清理定时器）
- 实测判据：连续快速按 `v` 10 次，**实际渲染帧数 ≤ 3**（用渲染计数器断言），且最终状态正确

**验收追加（T9）**：
- [ ] `src/ui/approval-text.ts` 零 ink/react import（护栏测试）
- [ ] 文案一致性：纯字符串输出 == 非 TTY 打印内容（逐行快照断言）
- [ ] `modals.tsx` 无用户可见文案字面量（全部走 i18n + renderApprovalLines）
- [ ] 节流：连按 `v` 10 次渲染帧 ≤ 3；`y`/`n` 无节流（即时响应断言）；卸载无悬挂 timer

- **复用边界（专家点名，违反即返工）**：`commit.ts` **必须 `import { runCheck } from './check'`**，**严禁**在其内部写 `execSync('npm run verify')` 或任何自制 verify 调用：
  - 理由 1：只有走 `runCheck` 才能消费 `check --json` 的结构化结果（哪段失败、摘要、下一步命令），自制调用只能拿到一坨文本
  - 理由 2：T19 护栏测试会**断言 `commit.ts` 存在对 `./check` 的 import**，自制实现直接测试不过
  - 理由 3：双份 verify 调用 = 双份耗时 + 双份失败面（v4.1.1「装好却跑不通」的同类分叉）
  - 具体实现：`commit.ts` 只写编排（git 检查 → `await runCheck({ json: true })` → 判结论 → 生成 message → 审批 → `git commit`），**任何 verify/lint/type 解析逻辑一行都不许有**
- **message 规格（G7 证据优先）**：标题 ≤ 72 字符（中文按显示宽度算）+ body ≤ 3 点，每点引用真实改动（文件名/函数名）；**基于真实 diff 生成**（`git diff --staged` 传入模型），禁止空泛套话
- **check 失败** → 打印失败摘要 + 「先运行 `concertoai fix`」→ **退出，不自动修完再提交**
- **安全边界（决策 D3-B 硬约束）**：
  - **绝不执行** `git push` / `git pull` / `git rebase` / 分支切换 / `--force` / `--no-verify`
  - 无 git 仓库 → 提示 `git init` 后退出
  - 无暂存改动 → 提示「先 `git add`」+ 询问是否自动 `git add -A`（**默认 N**）
  - 冲突中（`.git/MERGE_HEAD` 存在）→ 拒绝提交并提示
  - detached HEAD → 警告但允许（明确告知）
- **审批门**：message 必须先展示再审批（y/N，默认 N）；`--yes` 可跳过（**CI 场景**，但 `--yes` **不跳过 check**）
- 成本提示：调用模型前显示「将调用模型生成 message（约 X tokens）」

**验收标准**：
- [ ] check 通过 → message → 审批 → commit 全流程（git 命令注入 mock）
- [ ] **代码审查确认：无 `push` / `pull` / `rebase` / `force` / `--no-verify` 任何调用**（G1/D3 硬约束）
- [ ] message 标题 ≤ 72 显示宽度 + body ≤ 3 点 + 每点引用真实改动
- [ ] check 失败 → 不提交，提示 `concertoai fix`
