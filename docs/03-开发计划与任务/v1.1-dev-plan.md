## 1. 定位与 1.1 定义

**v1.1 定位**：从「可靠的编码助手」升级到「具有扩展能力的智能编码助手」。核心是接入 MCP 协议生态、增强任务规划能力、实现跨会话记忆。

**完成定义（Definition of Done）**：通过第 5 节「发布门检查清单」全部条目，即可发 1.1.0。

**优先级框架**：

| 级别 | 含义 | 处理策略 |
| --- | --- | --- |
| P0 | 发布硬门槛（MCP 基础 / 规划增强） | 1.1.0 前必须完成 |
| P1 | 显著提升日常可用性 | 1.1.0 目标范围 |
| P2 | 锦上添花 | 有剩余容量再做，否则明确推后 |

## 2. 现状盘点（v1.0 → v1.1 差距）

| 维度 | v1.0 现状 | v1.1 差距 |
| --- | --- | --- |
| 工具生态 | 内置 5 个基础工具（读/搜/列/编/shell） | **MCP 协议接入**，可连接 filesystem/memory/github 等外部服务（P0） |
| 任务规划 | 支持 `lumen plan` 基础模式 | 计划依赖检测、进度跟踪、回滚能力（P0） |
| 记忆能力 | 仅当前会话上下文 | **跨会话记忆**，项目级知识在会话间保留（P1） |
| 上下文管理 | 裁剪策略（保留 system + 最近 N 轮） | 增加智能摘要压缩（P2，可推后） |

## 5. 发布门检查清单（Release Gate）

1.1.0 发布前逐项验收：

- [ ] MCP 客户端能连接并发现外部工具
- [ ] 跨会话记忆功能正常（项目知识在会话间保留）
- [ ] `npm run verify` 全绿（测试用例 ≥ 230）
- [ ] `npm audit` 无 high/critical
- [ ] 真实 API 冒烟通过（含 MCP 工具调用）
- [ ] 文档已更新（README、用户手册、架构文档）
- [ ] `1.1.0` tag + CHANGELOG 完整

## 6. 不做清单（范围控制，1.1 明确不做）

| 项目 | 理由 | 计划 |
| --- | --- | --- |
| MCP 多服务动态管理 | 复杂度高，v1.1 只做基础集成 | v1.2 |
| 子代理 / 技能系统 | 需要 MCP 基础稳定后再做 | v1.2 |
| 桌面端 / 图形界面 | 超出 CLI 定位 | 不做 |
| 多模型后端（非 DeepSeek） | 当前无需求 | 视反馈 |

## 7. 风险与开放问题

| 风险 | 影响 | 缓解 |
| --- | --- | --- |
| MCP 协议版本变动 | 集成代码可能失效 | 锁定 MCP 协议版本，定期检查更新 |
| memory MCP 服务稳定性 | 跨会话记忆依赖外部服务 | 设计降级方案（本地 JSON 备份） |
| 计划回滚复杂度 | 可能引入新的 bug | 充分测试，先做基础版本 |

**开放问题**：
1. MCP 服务启动方式：自动启动 vs 用户手动启动？
   - 建议：v1.1 阶段采用配置文件预配置，启动时自动连接
2. 跨会话记忆的存储范围：项目级 vs 全局级？
   - 建议：先支持项目级（在项目根目录 `.lumen-memory/`）
