## T1.1 步骤输出截断 + 智能错误摘要（P0，2h）

- **目标**：失败时用户先看到「可操作的那一行」，再看到截断详情；消除 6 文件完整 diff 淹没提示。
- **用户故事**：lint 失败 → 我第一眼看到「✗ × Found 6 errors」而非 6 个文件 diff。
- **涉及文件**：`src/utils/truncate.ts`（新增）、`src/utils/error-summary.ts`（新增）、`src/workflow/executor.ts`（defaultRunCommand 截断 + FailureInfo.error 走摘要）、`src/cli/workflow.ts`（promptRecovery 展示摘要+详情）、`src/i18n/zh.ts`/`en.ts`（截断标注文案）、`tests/utils/error-summary.test.ts`（新增）、`tests/cli/workflow.test.ts`
- **实现要点**：
  - `truncateText(text, max)`：头尾保留 + 中间省略 + 标注「…已截断，共 N 字符」
  - `extractErrorSummary(stderr)`：tsc → 第一个 `error TS\d+: ...` 行；biome → `×`/`Found N errors` 行；npm → `npm error` 行；vitest → `FAIL` 行；兜底首行非空
  - `defaultRunCommand`：stdout/stderr 各截断（MAX_WORKFLOW_OUTPUT_CHARS=4000），返回 `truncated` 标记
  - `promptRecovery`：显示 `💡 {summary}` 一行 + `详情（前 1200 字符，…共 N）`
- **验收**：单测覆盖 4 类摘要 + 截断边界；workflow 集成测试断言失败信息含摘要；i18n 键一致

## T1.2 F 选项等待态闭环 + 60s 超时（P0，1.5h）

- **目标**：F 不再是「假按钮」——选 F 后等待用户手动修复，Enter 重试 / a 放弃；60s 无输入自动放弃回滚。
- **用户故事**：按 F 后我有时间改代码，改完按 Enter；忘了也不挂死。
- **涉及文件**：`src/cli/prompt.ts`（promptLine 加 timeoutMs 可选参数）、`src/cli/workflow.ts`（promptRecovery F 分支改为等待循环）、`src/i18n/zh.ts`/`en.ts`（failureFixWait / failureFixTimeout 文案）、`tests/cli/prompt.test.ts`、`tests/cli/workflow.test.ts`
- **实现要点**：
  - `promptLine(prompt, { timeoutMs })`：超时返回 `undefined`（与 Ctrl+C 同语义，调用方按放弃处理）；不破坏现有调用（缺省不超时）
  - F 等待循环：打印 `ℹ️ 请手动修改代码…Enter 重试 / a 放弃（60s 超时自动放弃）`；Enter/空 → fix-and-retry；a → abort；其他 → 重提示；超时 → abort
  - 非 TTY 保持原 fail-closed（直接 abort）
- **验收**：prompt.test.ts 补超时用例（fake timers）；workflow.test.ts 补「选 F → 等待 → Enter 重试 / a 放弃 / 超时放弃」3 用例

## T1.3 executor 内部重试根因修复 + retry 语义（P0，2h）

- **目标**：进度刷屏根因（scheduler maxRetries:2 内部重试）消除；步骤 `retry` 字段语义重定义为「恢复后重试上限」。
- **用户故事**：lint 失败只跑一次就进入 R/S/F/A 选择，不重复刷屏。
- **涉及文件**：`src/workflow/executor.ts`（new TaskScheduler({ maxRetries: 0 }) + 恢复循环按步骤计数 retry 上限）、`src/workflow/types.ts`（retry 注释更新）、`tests/workflow/executor.test.ts`
- **实现要点**：
  - executor 创建 scheduler 传 `maxRetries: 0`（禁止内部自动重试；orchestrator 不受影响）
  - 恢复循环：按步骤统计恢复次数 `recoveryCount: Map<stepName, number>`；`step.retry` 缺省 = 无上限（用户主动 R 不限）；`retry: N` = 该步骤恢复 N 次后强制转 abort（打印提示）
  - types.ts 注释：`retry = 用户通过 R/S/F/A 恢复后的重试次数上限（缺省不限；0 = 不允许重试）`
  - YAML 解析/序列化不变（字段已支持）
- **验收**：executor 测试断言失败步骤 run 只调 1 次（无内部重试）；retry:1 步骤第二次恢复转 abort；缺省不限恢复；回归不破坏 orchestrator（独立 scheduler 实例）

## T1.4 preflight 环境预检 + 轻量自动初始化（P0，3h）

- **目标**：`workflow run` 前预检缺失脚本/未安装依赖/缺配置，提供 Y/N 自动初始化；杜绝「Missing script: lint」裸失败。
- **用户故事**：新项目敲 workflow run precommit → 提示「缺少 lint/typecheck，是否自动初始化？」→ Y → 装好直接跑。
- **涉及文件**：`src/workflow/preflight.ts`（新增：checkPrerequisites / applyAutoInit）、`src/workflow/executor.ts` 或 `src/cli/workflow.ts`（run 前调用）、`src/i18n/zh.ts`/`en.ts`、`tests/workflow/preflight.test.ts`（新增）
- **实现要点**：
  - `checkPrerequisites(workflow, cwd)`：解析步骤命令 `npm run <script>` → 读 package.json；返回缺失清单（脚本缺失 / 依赖未装：`node_modules/.bin/<tool>` 不存在 / 缺 biome.json 等配置）
  - `applyAutoInit` 只做事实标准且走审批：`lint` → `npm install -D @biomejs/biome` + 写 biome.json + 注入 `scripts.lint`；`typecheck` → `npm install -D typescript` + `tsc --init`（无 tsconfig 时）+ 注入 `scripts.typecheck`；`test` → 仅提示不自动
  - 交互：打印预检报告 + 自动初始化操作计划 + 一次 y/N 审批；拒绝/非 TTY → 继续执行（会失败）或按缺失项引导（fail-closed 倾向：非 TTY 直接报清单退出）
  - package.json 编辑用 JSON 读写（保留格式敏感度，写入后校验）
- **验收**：preflight 单测覆盖（脚本缺失/依赖缺失/配置缺失/正常）；集成测试 fake package.json 断言自动初始化操作序列；i18n 键一致

## T2.1 错误「下一步」指引 + CLI 风格统一（P1，2h）

- **目标**：所有关键错误路径带「💡 下一步」行动指引；CLI 输出统一「图标 + 分隔线 + 颜色」风格。
- **用户故事**：出错时我知道「接下来该做什么」而不是对着错误发呆。
- **涉及文件**：`src/cli/workflow.ts`（runFailed 等补下一步）、`src/cli/index.ts`（safeAction 错误补下一步）、`src/i18n/zh.ts`/`en.ts`（nextStep* 键组）、针对性测试
- **实现要点**：
  - 统一错误输出格式：`❌ 标题` + 原因 + `💡 下一步：…`（具体命令）
  - 覆盖：workflow 未找到（→ init/import 指引）、run 失败（→ R/S/F/A 或改代码）、safeAction 未知异常（→ doctor/issue）、plugin 安装失败、provider auth 失败
  - CLI 命令输出加分隔线 `──` 视觉层级（workflow list/run、doctor 已有风格对齐）
- **验收**：i18n 键一致；workflow/plugin 关键错误断言含「下一步」；文档同步
