## 执行规范

1. **开始任务前**：阅读该任务完整定义，确认依赖任务已完成
2. **执行任务**：按「验收标准」逐项实现
3. **任务完成后**：执行 `npm run verify` 确保全绿，然后更新 TASKS.md 看板

### T1.1 W1：lint:fix 失败 break 语义显式化

**目标**：`repair.ts` 中 lint:fix 执行失败（非零退出码）直接 `break`，未说明「剩余 type 错误已跳过」。补注释 + log 显式化语义，避免后人误读为遗漏。

**涉及文件**：
- `src/loop/self-heal/repair.ts`（修改 — lint:fix 失败分支补注释 + log 文案）

**验收标准**：
- [ ] `if (!fix.ok)` 分支补注释：说明「lint:fix 失败 = 环境问题（如 Biome 未安装），后续 type 简单错误一并跳过，显式转人工」
- [ ] log 文案包含「剩余 type 错误已跳过（环境问题），转人工」
- [ ] 行为不变：仍 break（不继续修复），report 已更新为 lint 修复后的 verify 结果供人工查看
- [ ] 现有 self-heal 32 用例全绿

**预估耗时**：0.25h
**依赖**：无

### T1.2 W2：全局正则常量去 `g` 标志

**目标**：`classifier.ts` 中 `BIOME_RULE_ERROR_RE` / `BIOME_FORMAT_ERROR_RE` 常量带 `g` 标志是脆弱模式（`lastIndex` 残留陷阱）。当前使用处已通过 `new RegExp(SOURCE, 'g')` 规避，但常量本身应去 `g`，由使用处按需添加。

**涉及文件**：
- `src/loop/self-heal/classifier.ts`（修改 — 两个正则常量去 `g` 标志 + 注释说明）

**验收标准**：
- [ ] `BIOME_RULE_ERROR_RE` / `BIOME_FORMAT_ERROR_RE` 定义不带 `g`
- [ ] 使用处 `new RegExp(SOURCE, 'g')` 不变（行为等价）
- [ ] 注释说明 W2 缘由（全局 `g` 残留 lastIndex 导致交替匹配/漏匹配）
- [ ] 全项目无「带 g 标志的全局正则常量」（grep 复核，排除刻意用法）
- [ ] 现有 self-heal 32 用例全绿（含 lint/format/assist 双平台样本）

**预估耗时**：0.25h
**依赖**：无
