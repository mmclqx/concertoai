## 3. 核心设计原则

3.1 **审查闭环（Review Loop）**：延续 v3.3「0 遗留」标准——C 的建议 + 自我审查发现全部闭环，不留待办；发布门强制「自我审查报告已生成」（AGENTS.md 通用检查项，v3.3 已固化）。

3.2 **最小变更（Minimal Change）**：v3.4 是收尾型小版本，每项任务小步增量，禁止顺手重构；行为不变，只补完整性/一致性。

3.3 **i18n 数据层完整性（i18n Data-Layer）**：v3.3 S1 只迁移了展示层文案，v3.4 补齐**数据层**（feedback 内容）——沿数据流追踪到文案产生点，`--lang en` 下报告任何路径不混合中英。

3.4 **模式一致性（Pattern Consistency）**：同类代码模式（正则常量标志位 / 字典遍历防护）全项目统一，审查/搜索工具也要覆盖变体（g / gm / gi / gim），避免「只搜 `/g` 结尾漏掉 `/gm`」的复核盲区（v3.3 C 复核教训）。

3.5 **环境健康可观测（Env Observability）**：环境类问题（VS Code 崩溃 / 进程爆炸 / 转储堆积）必须有自动化检测入口，不依赖人工翻阅日志；诊断只读、输出建议命令，破坏性动作（kill / 卸载 / 删除）由用户执行。

### V3.4-M3：VS Code 崩溃防护（P1，约 2h）

> 背景：2026-08-11 深夜 VS Code 再次闪退（12 转储 / 511MB / 83 进程），根因是上轮 argv.json 写错位置导致 5 个 AI 扩展从未禁用 + 14 窗口×全套扩展组合爆炸（详见踩坑记录 §五）。将排查 SOP 固化为 `concertoai doctor --vscode` 健康检查，防复发。

| 编号 | 内容 | 涉及文件 | 预估 |
|------|------|----------|------|
| T3.1 | **VS Code 进程数检测**：Windows `tasklist`（或 PowerShell CIM）统计 Code.exe 数量，macOS/Linux `ps` 统计；阈值告警（>60 严重 / >40 警告，对应多窗口×扩展组合），给出「关闭多余窗口」建议 | `src/cli/doctor.ts`（新增 VS Code 检查模块） | 0.5h |
| T3.2 | **崩溃转储堆积检测**：Windows 扫描 `%APPDATA%\Code\Crashpad\reports\*.dmp`（数量 + 总体积），>5 个或 >100MB 告警；macOS/Linux 对应路径 `~/Library/Application Support/Code/Crashpad` / `~/.config/Code/Crashpad`；给出清理命令（只读检测 + 建议，不代删） | 同上 | 0.25h |
| T3.3 | **AI 扩展数量与 argv.json 核对**：解析 `code --list-extensions` 输出，对照已知 AI 扩展 ID 清单统计数量（>3 告警）；读取 `~/.vscode/argv.json`（Windows/macOS/Linux 各自路径）核对 disable-extension 是否包含冗余 AI 扩展（安装但未禁用 → 告警 + 给出禁用写法）；同时检测**无效 argv.json 位置**（如 Windows `%APPDATA%\Code\argv.json` 存在但实际读取 `~/.vscode/argv.json`） | 同上 + 平台路径适配模块 | 0.5h |

- □ 阈值合理（进程数 >60 严重、转储 >5 或 >100MB 告警、AI 扩展 >3 告警）
- □ 诊断只读，破坏性动作仅输出建议命令（taskkill / code --uninstall-extension / del 转储）
