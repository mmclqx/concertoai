## 任务 T1：npx 零安装实测（P0，0.5h）

**目标**：验证 `npx @concertoai/cli` 零安装可用；缺 API Key 场景给中文引导（新用户第一印象）。
**用户故事**：作为新用户，我想不安装就用 npx 体验 ConcertoAI，没配 Key 时知道怎么配。
**涉及文件**：package.json（bin/files 已就绪，确认）、src/cli/index.ts（getApiKey 报错路径）、src/i18n（zh/en 缺 Key 文案）、tests/e2e/npx.test.ts（新建）
**实现要点**：
1. 真实环境 `npx @concertoai/cli --version` / `--help` 实测（用已发布的 4.1.1 或本地 npm pack + npx 指向 tgz）
2. 缺 Key 场景：`getApiKey()` 目前 `console.error(t().errors.noApiKey); process.exit(1)` ——增强为中文引导：⚠️ 未检测到 DEEPSEEK_API_KEY + 3 种配置方式（环境变量 / `concertoai provider auth deepseek` / config.json）+ 获取链接 `https://platform.deepseek.com/api_keys`
3. e2e 测试：spawn CLI（无 API_KEY 环境变量）→ 断言引导文案出现且非静默崩溃
**验收**：① npx --version 输出正确版本 ② --help 正常 ③ 无 Key 时输出 3 种配置方式 + 链接 + 非 0 退出但非崩溃 ④ e2e 测试覆盖
**依赖**：无

## 任务 T2：update 命令（P0，1h）

**目标**：`concertoai update` 检查 npm 最新版并提示/执行升级。
**用户故事**：作为已安装用户，我想一条命令检查并升级。
**涉及文件**：src/cli/update.ts（新建，runUpdateCommand）、src/cli/index.ts（注册 `update`）、src/i18n（zh/en 键）、tests/cli/update.test.ts（新建）
**实现要点**：
1. `npm view @concertoai/cli version`（或 registry API，fetch 注入可测）对比当前 VERSION
2. 有新版：显示版本对比（当前 x → 最新 y）+ 确认升级（默认 y 需确认；`--yes` 跳过）
3. 无新版：提示已最新
4. 全局安装检测：`npm root -g` + bin 路径存在判断；非全局安装（npx 场景）→ 提示「请先 `npm install -g @concertoai/cli` 后 update」
5. 升级执行：`npm install -g @concertoai/cli@latest`（需确认，`--yes` 跳过）；失败（网络/权限）友好提示
6. 边缘路径：首次运行（未安装）/ 失败恢复（网络断）/ 用户 Ctrl+C
**验收**：① 查版本对比 ② 确认升级/--yes ③ 已最新提示 ④ npx 场景提示 ⑤ 失败友好 ⑥ 测试覆盖（fetch mock + npm 命令 mock）
**依赖**：T1（缺 Key 引导模式复用）

## 任务 T5：init 生成守护指南（P1，2h）

**目标**：`concertoai init` 分析项目生成「守护指南」AGENTS.md（差异化杀手锏，比 Carbon 的 CARBON.md 更深）。
**用户故事**：作为接手别人代码的开发者，我想让 AI 快速理解项目并生成「项目是什么 + 怎么守护」。
**涉及文件**：src/cli/init.ts（新建，runInitCommand）、src/store/project-rules.ts（RULE_FILENAMES 复用 AGENTS.md 常量）、src/cli/index.ts（注册 `init`）、src/i18n（zh/en）、tests/cli/init.test.ts（新建）
**实现要点**：
1. 分析：package.json（name/scripts/dependencies+devDependencies 数量与主要框架）、入口文件（main/bin/src 探测）、目录结构（顶层条目）、CI/配置存在性（.github/workflows / tsconfig / biome.json）、TODO/FIXME 扫描（计数 + 位置）
2. 生成 AGENTS.md（中文），结构：
   - `# AGENTS.md（ConcertoAI 生成）` + 说明头部
   - 项目定位（package.json 描述/name）
   - 技术栈（依赖分析：框架/语言/工具）
   - 常用命令（scripts：dev/build/test/lint/typecheck/verify 逐个）
   - 守护要点：入口文件 / 高风险区域（网络调用 src/api、状态管理 src/cache 等启发式）/ 建议提交前 `/review --fix` / 已知技术债（TODO 统计）
3. 已有 AGENTS.md → 提示覆盖确认（y/N）；无 package.json → 友好提示「不是 Node 项目，可指定 --file 或跳过」
4. 生成内容每段引用真实证据（不套话）；`--force` 跳过确认
5. 边缘路径：非项目目录 / 已有文件 / 文件写入失败
**验收**：① 3 种项目实测（Node 库 / 前端 / 无 package.json）② 生成内容含 4 段且引用真实证据 ③ 覆盖确认 ④ 非项目提示 ⑤ 测试覆盖
**依赖**：无（独立）

## 任务 T6：auto 模型预设（P2，1h，保守方案）

**目标**：config 支持 `providers.deepseek.model: "auto"` + 手动切换 + 升级前成本提示审批（不做无监督自动升级）。
**用户故事**：作为低成本用户，我想简单任务用 flash、复杂任务手动切 pro，且切换前知道成本。
**涉及文件**：src/model/models.ts（auto 解析逻辑）、src/store/config.ts（auto 值放行）、src/cli/provider.ts（provider switch 支持 auto）、src/core/model-switcher.ts（/model auto 语义 + 成本提示）、src/model/recommend.ts（复用 detectComplexity 做建议）、src/i18n、tests/model/models.test.ts、tests/cli/provider.test.ts
**实现要点**：
1. `resolveAutoModel(complexityHint?)`：auto 默认 flash；复杂度高（复用 detectComplexity：文件数+依赖数阈值）→ 建议 pro（提示「建议升级 pro，成本 x 元/百万输出 vs flash y 元」+ y/N 审批）
2. config `providers.deepseek.model: "auto"` 合法（loadConfig 校验放行 + provider switch 接受）
3. `/model auto` 或 `-m auto` 解析为 flash + 提示可用 `/model pro` 升级
4. 升级前成本提示：显示 pro vs flash 价格对比（输入/输出/缓存命中），确认后生效
5. 不做自动触发升级（R3 保守）
**验收**：① config auto 放行 ② auto 解析为 flash ③ 复杂度高提示升级 pro + 成本对比 + 审批 ④ 测试覆盖（auto 解析 / 成本提示 / 审批拒绝保持 flash）
**依赖**：T7（价格表双档先落地，成本提示才准确）——**注意顺序：T7 先于 T6 实现**

**用户故事**：作为用户，我想看到真实成本（当前时段）。

**实现要点**：
1. **官方时段查询（前置）**：4 途径（官方 Pricing 页 / API 响应头 / 官方公告 / 社区验证），确认「高峰/空闲」具体定义（时段 + 时区）；结果写 ADR（DECISIONS.md 新条目，标注来源 URL）
2. peak-time.ts 对齐官方定义（当前自定「工作日 9-12/14-18」；若官方不同 → 修正；回归 peak-time 测试 + model-switcher 测试；若与 ollama 切换场景冲突 → 拆 `isOfficialPeakTime`（价格）/ `isOllamaPeakTime`（切换）两函数）

**验收**：① ADR 落盘（官方时段定义 + 来源 URL）② peak-time.ts 对齐官方（或拆分函数）③ 价格表新值 ④ 时段计价正确 ⑤ 测试全绿
