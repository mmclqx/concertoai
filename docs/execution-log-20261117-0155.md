## 二、锚点为什么必须是「语义锚点 + v 前缀」

实测 `README.md` 状态行（第 35 行）里的三段式版本号：

```
带 v 前缀：["v5.4.0"]                                          ← 1 个，产品版本
不带 v 的：["5.4.0","4.6.7","4.1.12","8.2.4","3.3.18","1.2.2"]  ← 5 个依赖版本
```

| 若判据写成 | 后果 |
|---|---|
| 行内**全部**三段式 | 命中 6 个 ⇒ T3 的「恰好 1 个」立刻红（**故意**：这正是 T4 否定面要挡的） |
| 行内**第一个**三段式 | 当前恰好也是 5.4.0（巧合绿）；一旦依赖被挪到前面就抓错对象 |
| **`v(\d+\.\d+\.\d+)`** ✅ | 依赖版本都没有 `v` 前缀 ⇒ 天然只命中 1 个 |

锚点用**语义锚点**（以 `> 版本：` 开头的行），不是行号、也不是「全文第一个三段式」——
文末「历史版本速览」里全是 `v4.0` / `v3.2` 两段式，全文扫描会把它们卷进来（M6 正是验这个）。

## 四、尺子自己坏了三次（本轮，必须记）

### ① 探针读数器对「全部失败」的输出形态失明（会让红的读成绿）

vitest 的汇总行有两种形态：

```
部分失败：Tests  2 failed | 2 passed (4)
全部失败：Tests  4 failed (4)        ← 没有 passed 段
```

初版正则 `Tests\s+(?:(\d+) failed\s*\|\s*)?(\d+) passed` **硬要求 `passed` 才匹配**，
于是 M3/M4 全失败时读成 `failed=0 passed=0`，我一度判成「探针不符预期」——
而同一段输出里 `×T1 ×T2 ×T3 ×T4` 明明抓到了，**两个读数自相矛盾**。

**看来自相矛盾的读数就该停下来查，而不是挑一个信。**

### ② 同一次里 `file` 变量出了作用域 ⇒ ReferenceError（会让整轮中止）

第一版探针在还原循环后写了 `fs.readFileSync(file ?? 'README.md')`，`file` 只在 `for...of` 里存在。
崩在 M1 之后 → M2–M6 一条没跑。修法：还原后**用 sha 断言**（`README` 与 `package.json` 双文件）
并「不一致就立即中止」，避免带着污染继续跑。

### ③ `npm run verify` 红了，而我的过滤器让我先看到空输出（会让红的读成绿）

`verify` 在 lint 阶段就失败（biome 要求把三元表达式拆成多行）。我的过滤器只筛
`Test Files|Tests |跳过检测`，于是**什么都没打印**——「空输出」和「全绿」在管道里长得一模一样。
查原始日志才看到 `Found 1 error`。

**判据一句话：过滤器是尺子，尺子漏掉的失败等于失败不存在；所以「空输出」必须继续往下查原文，不能当通过。**

（这是本 session 第三次同类：内联 `node -e` 空输出、`vitest --silent` 把文件路径当值、这次 verify 过滤器。）
