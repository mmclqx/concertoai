### 22:11 关键设计决策：拆两套时段口径（R7 落地）

原 `peak-time.ts` 只有一套区间，同时服务「切 ollama」与（未来的）计价。若直接复用，用户关掉 `peakTimeStrategy` 会连带影响计价语义，且日后官方时段与我们自定值不同时，改一处就会静默改变用户已习惯的切换行为。

拆为：
- `SWITCH_PEAK_RANGES` + `isPeakTime()`（切 ollama 策略，v2.2 语义不变）
- `PRICING_PEAK_RANGES` + `isPricingPeakTime()`（计价事实，v5.0 新增）
- `PEAK_TIME_RANGES` 保留为**切换口径别名**（`= SWITCH_PEAK_RANGES`），历史调用方零改动
