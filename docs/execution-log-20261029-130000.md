**选定方案**：版本库内 `.githooks/prepare-commit-msg` + `core.hooksPath=.githooks`，身份解析 `CONCERTOAI_AGENT` > `git config agent.detect.<id>` > `unmarked`。

**为什么不用 repo 级 `user.name/email`**：Codex 在同一仓库用**同一份** local config，改了对它也生效 → 根本区分不了。这是本方案最关键的一条否决理由。
**为什么不用进程链自动识别**：802ms/次（8 倍），且本机多个 agent 都跑在 `node.exe` 下（实测进程链含 `node.exe` 多层），按名字分不出「我」和外部 agent——**慢且含糊的自动识别，不如「我一律声明 + 未声明即非我」这条确定规则**。
**为什么必须是 `prepare-commit-msg`**：D 与 C 的对照证明 `commit-msg` 能被 `--no-verify` 绕过，用它等于把"跑不掉"交给对方自觉。

## 三、局限（已写入 AGENTS 第 30 条 ⑤ + TASKS 待办）

### 三之补：最后一个弱点已补（commit `3af85ba`）

首版 hook 有个静默弱点：**我若忘记 `CONCERTOAI_AGENT`，会静默落成 `unmarked`，与「手动提交」无法区分**——等于机制在我身上失效而无人知晓。已补提交期 stderr 告警（两行 ASCII 英文，避免 cmd 代码页把中文打成乱码），**不阻断提交**：

```
$ git commit --allow-empty -m "test: 未声明身份的告警是否可见"

concertoai: declare with CONCERTOAI_AGENT=<id> (see AGENTS rule 30).
```

实测：告警可见，且 `git log -1 --format="Agent=%(trailers:key=Agent,valueonly)"` → `Agent=unmarked` 正确落盘。

### 一次操作失误（如实记录）

清理「未声明」测试提交时，我用 `git reset --hard HEAD~1` 把**尚未提交的 hook 告警改动一起回滚掉了**（`.githooks/prepare-commit-msg` 当时有未提交改动）。发现后重新应用并单独提交（`3af85ba`）。
**教训**：在含未提交改动的工作区上跑 `reset --hard`，必须先 `git status` 确认待保留改动已提交或 stash——这与 AGENTS 第 7 条「工作区干净才审查」同源，属既有纪律的又一次现实印证，未新增条目。

### 三之补三：core.hooksPath 不进版本库（存量局限）

`core.hooksPath` 是**本地配置、不进版本库** → 新克隆 / 换机器必须手动 `git config core.hooksPath .githooks`，否则 hook **完全不生效且没有任何提示**（提交照常成功，trailer 静默缺失）。TASKS 里记了三步复配 + 索引模式核对 + 空跑验证。
