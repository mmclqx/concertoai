## 一、根因取证（关键，决定了方案形态）

先用探针 `.git/agent-detect-probe.mjs`（跑完即删）实测三件事：

| 手段 | 耗时 | 输出 |
|---|---|---|
| `wmic process where "name='node.exe'" get processid,commandline /format:csv` | **191ms** | 有完整命令行 |
| `tasklist /v /fi "imagename eq node.exe" /fo csv` | **147ms** | 只有名字/内存/用户，中文表头 **GBK 乱码** |
| PowerShell `Get-CimInstance` 全表 + 内存遍历 | **937–979ms** | 能算树，太慢 |

**对自己祖先进程链取证**（每层命令行都打出来）：

```
node.exe | node .git/agent-detect-probe.mjs
cmd.exe  | cmd.exe /d /s /c "node .git/agent-detect-probe.mjs"
node.exe | ...tsx/dist/preflight.cjs ...
node.exe | "node" "...tsx/dist/cli.mjs" src/cli/index.ts   ← 我就是这个
cmd.exe  | tsx src/cli/index.ts
node.exe | npm-cli.js run dev
cmd.exe  →  Code.exe → Code.exe → explorer.exe
```

**决定性数据**：所有 `node.exe` 命令行里含 `codex|claude|cursor|windsurf|aider` 的行数 = **0**，**而我自己就坐在这个 0 里**。

→ 结论：**「哪个 node.exe 是哪个 agent」这个信息在进程表里根本不存在**。agent 与进程的对应只存在于人类层面（谁在哪个窗口按的回车）。按进程名/命令行猜身份 = 猜，不是识别。**这是盲区②的根因，任何"查 tasklist 找 agent"的尝试都注定失败。**

## 二、方案：自声明锁（不检测，改为广播）

新增 `scripts/agent-lock.mjs`（151 行），锁文件 `.git/concertoai-agent.lock`（不进版本库、不污染 `git status`），TTL **10 分钟**。

- `status` / `claim --owner <id>` / `heartbeat --owner <id>` / `release --owner <id>`
- 退出码：**0** 可用/成功、**1** 被他人**新鲜**持有、**2** 用法或环境错误
- 写锁走 tmp + `renameSync`（原子替换，避免读到半个 JSON）
- 身份优先 `--owner`，回落到环境变量 `CONCERTOAI_AGENT`（与第 30 条同一口径）；非 status 命令缺身份直接 exit 2
- 锁**损坏**时不当成「空」，如实报错要人工删（与「降级不冒充低风险」同一价值观）

## 三、验证（13 个场景全通过，真实执行）

```
[1] heartbeat by 陌生人      -> 锁不属于 other（当前 owner=concertoai-loop）
[1] release by 陌生人        -> 锁不属于 other，不代删
[0] heartbeat by 持有者      -> 心跳已更新
[0] release by 持有者        -> 已释放
[0] release 再执行一次        -> 无锁（幂等，无需释放）
     —— 构造心跳 20 分钟前的残留锁 owner=ghost ——
[0] status                  -> 残留锁（心跳已过期，可接管）—— owner=ghost pid=99999 心跳 20 分钟前
[0] claim by 新实例          -> 已持有（接管了残留锁：owner=ghost ...）
[0] status（应是自己的）      -> 被持有 —— owner=concertoai-loop
[0] release                 -> 已释放
[0] 最终 status             -> 空闲（无锁）
     —— 构造损坏的锁 ——
[1] status                  -> 锁文件损坏，需人工检查并删除
[2] claim                   -> 锁文件损坏，需人工检查并删除
```
