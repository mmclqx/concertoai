## 前置准备

```bash
# 1. 确认 Node ≥ 22
node --version

# 2. 进入 Lumen 项目根目录
cd F:\developer\2026\lumen     # 换成你实际的路径

# 3. 安装依赖（仅首次）
npm install

# 4. 设置 API Key（选一种）
#    Windows cmd:
set DEEPSEEK_API_KEY=sk-你的密钥
#    Windows PowerShell:
$env:DEEPSEEK_API_KEY="sk-你的密钥"
#    macOS / Linux:
export DEEPSEEK_API_KEY=sk-你的密钥

# 5. 验证环境
npm run verify                  # 应输出 build/lint/typecheck/test 全绿
```

> ⚠️ 以下所有 `npm run dev` 均指开发模式（tsx 直接跑 TS 源码），等价于发布后的 `lumen` 命令。

## 测试 4：轮数上限截停与继续（v1.1 核心场景）

> 此测试验证：模型频繁调工具、10 轮触发截停 → 不抛错退出 → 保留进度 → 继续输入即可延续。

### 4.1 制造轮数上限

| 步骤 | 操作 | 预期结果 |
| --- | --- | --- |
| 1 | `npm run dev` | 启动 |
| 2 | 输入「反复读取 package.json、README.md、tsconfig.json——每读一个文件就告诉我内容摘要，不要停」 | 模型连续调 `read_file`（每调一次消耗 1 轮） |
| 3 | 观察状态条 | 每轮显示 spinner + "read_file" |
| 4 | 约 10 轮后 | **红色提示**：`工具调用已达 10 轮上限，进度已保留。你可以继续输入以让助手继续工作。` |
| 5 | 观察终端 | **没有退回 shell**——光标仍在输入框闪烁，可以继续打字 |
| 6 | 观察之前的回复 | 之前所有读到的文件内容都还显示在上面（没丢） |

### 4.2 截停后继续

| 步骤 | 操作 | 预期结果 |
| --- | --- | --- |
| 1 | 接上一步，输入「继续」→ Enter | 新一轮 runLoop 开始，模型基于已有的完整上下文继续工作 |
| 2 | 模型正常回复，不重复之前已读过的文件 | 上下文连贯 |

### 4.3 确认会话不丢失

| 步骤 | 操作 | 预期结果 |
| --- | --- | --- |
| 1 | 接上一步，按 Esc 退出 | |
| 2 | `npm run dev -- chat -l` | 列表中第一条是最新会话，消息数 > 20（因为 4.1 产生了很多 tool 消息） |
| 3 | `npm run dev -- chat -r <会话ID>` | 历史消息完整恢复，包括所有 tool 调用记录和截停时的提示上下文 |

## 测试 5：显示截断（v1.1 优化）

> 验证终端单条消息超过 8000 字符时不会被吞掉，而是显示截断提示。

### 5.1 触发显示截断

| 步骤 | 操作 | 预期结果 |
| --- | --- | --- |
| 1 | `npm run dev` | 启动 |
| 2 | 输入「把 src/loop/loop.ts 的全部代码解释一遍，越详细越好」 | 模型调用 `read_file` 后给出长回复 |
| 3 | 观察终端 | 如果回复超过 8000 字符，末尾出现 `…（共 XXXX 字符，终端仅显示前 8000）` |
| 4 | `npm run dev -- chat -l` 找到该会话 ID，`cat ~/.lumen/sessions/<id>.jsonl` | JSONL 文件中完整内容存在，未被截断 |

> 注意：如果模型回复较短（< 8000 字符），不会出现截断提示。可以换个方式触发——比如「详细解释 Lumen 的全部架构，输出至少 200 行的文档」。
