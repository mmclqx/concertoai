## 前置准备

```bash
# 1. 确认 Node ≥ 22
node --version

# 2. 进入 Lumen 项目根目录
cd F:\developer\2026\lumen     # 换成你实际的路径

# 3. 安装依赖（仅首次）
npm install

# 4. 设置 API Key（选一种）
#    Windows cmd:
set DEEPSEEK_API_KEY=sk-你的密钥
#    Windows PowerShell:
$env:DEEPSEEK_API_KEY="sk-你的密钥"
#    macOS / Linux:
export DEEPSEEK_API_KEY=sk-你的密钥

# 5. 验证环境
npm run verify                  # 应输出 build/lint/typecheck/test 全绿（39 文件 380 用例）
```

> ⚠️ 以下所有 `npm run dev` 均指开发模式（tsx 直接跑 TS 源码），等价于发布后的 `lumen` 命令。

| 2 | 主对话上下文不应被污染 | 子代理的中间过程不可见 |

### 6.5 research 子代理容错修复回归（Bug Fix）

> **背景**：v2.0 初版 research 子代理与 explore 配置完全相同（`maxTurns=5`、`timeoutMs=30s`、`MAX_REPAIRS=2`），但其 system prompt 要求「多角度分析 + 对比归纳 + 500 字结论」，模型尝试更多工具调用，容易触发修复管线终止（连续 3 次可修复失败即抛错）。
> **修复**：research 子代理 `maxTurns: 5→7`、`timeoutMs: 30s→60s`、`maxRepairs: 4`（容忍更多探索试错）；`SubagentDef` 新增 `maxRepairs` 字段；`LoopOptions.maxRepairs` 可覆写。
> **验证方式**：research 子代理应在复杂任务（需读取 5+ 文件）中稳定完成，不再返回「未知错误」。

| 步骤 | 操作 | 预期结果 |
| --- | --- | --- |
| 1 | `npm run dev` | 启动 |
| 2 | 输入「用 research 子代理详细分析 Lumen 的模块架构：列出所有 src/ 下的模块目录，对比各模块的职责和依赖关系」→ Enter | 模型调用 `spawn_subagent(agentName: "research", …)` |
| 3 | 等待子代理执行完成（可能需要 10-30 秒） | 回复中包含**结构化研究结论**：列出模块、对比职责、分析依赖关系；**不应**出现「未知错误」或「子代理执行失败」 |
| 4 | 再次输入「用 research 子代理对比 src/model/tokenizer.ts 和 src/loop/context.ts 的设计模式和错误处理策略」 | 子代理再次执行成功，返回对比分析结论 |
| 5 | 连续调用 3 次 research 子代理（不同问题） | 3 次均应成功；之前连续失败 3 次触发修复终止的问题不再复现 |
