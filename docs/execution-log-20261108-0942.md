## 四、本轮两起事故（都在「补账」这一步暴露，如实记录）

### 事故 A：搜错目录 ⇒ 把「已存在」判成「未实现」

| 项 | 实情 |
|---|---|
| 我的结论 | 「`.git\hooks` 只有 `*.sample` ⇒ hook 提醒未实现」 |
| 实际 | `git config core.hooksPath` = **`.githooks`**；该目录有 `prepare-commit-msg`（2211B，`git ls-files` 命中，历史上由 `afb7bdb` / `3af85ba` 两次提交引入） |
| 根因 | 直接把「默认 hooks 目录」当成「hooks 实际目录」，没有先跑 `git rev-parse --git-path hooks` 确认——**又一次「搜不到就判干净」**，正是 AGENTS「检索类必须先让探针命中必然存在的样本」要防的形态 |
| 部分结论仍成立 | 该 hook **只**做 `Agent:` trailer 追加与未声明告警，**不含**裁决 4 要的「`in_progress` 时打印一行进度提醒」⇒ 「进度提醒 hook 未实现」这一半是对的，但**支持它的证据是错的**，不能拿错证据撑对的结论 |
| 处置 | 结论改写为：「hooks 目录是 `.githooks`（`core.hooksPath`），已有 `prepare-commit-msg` 管 Agent 身份；**进度提醒 hook 尚未做**，属裁决 4 的待办」 |

### 事故 B：提交 trailer 被 hook 改写成 `Agent: unmarked`

| 项 | 实情 |
|---|---|
| 现象 | 提交时我传了 `-m "Agent: concertoai-loop"`，实际落盘末行是 **`Agent: unmarked`**，并伴随 stderr 告警 `concertoai: agent identity NOT declared` |
| 根因 | `prepare-commit-msg` 的设计是**幂等覆盖**：先 `awk` 删掉消息里所有 `Agent: ` 行，再按 `CONCERTOAI_AGENT` 环境变量重写。我没设该环境变量 ⇒ 我手写的 trailer 被当成脏行删掉、重写成 `unmarked` |
| 为什么这设计是对的 | 让「忘了声明身份」当场可见而不是事后翻 log（`3af85ba` 的提交意图），不能为了迁就我而改 |
| 处置 | `set CONCERTOAI_AGENT=concertoai-loop&&git commit --amend --no-edit` ⇒ 末行恢复 `Agent: concertoai-loop`（实测见下）；**后续所有提交都走环境变量声明，不再用 `-m` 传 trailer** |
| 自证 | `git log -1 --format=%B` 取末三行：标题行 / 空行 / `"Agent: concertoai-loop"` |

### 5.4 这次事故给出的两条硬结论（写进机制而不是写进记性）

1. **「继续」也是需要占位的动作**：ADR-051 只解决「上次做到哪」，解决不了「两个实例同时被叫醒」。⇒ `write` / `update` 必须做**并发检测**（§9.2 第 2 条已写死：比对 `lastUpdated` + 原子 rename），且 CLI 侧应把 `agent-lock claim` 作为开工第一步（本日志已是实物示范）。
2. **本轮的教训与根因同构**：ADR-051 事故是「没查别人做没做」，这次是「查了产物但没查**谁在写**」。两者都不报错，都只在事后对照时暴露 ⇒ 验证方式只能是「现跑一条能证伪的命令」（锁状态、进程表、mtime 采样）。
