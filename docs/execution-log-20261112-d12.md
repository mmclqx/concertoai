## 六、教训

1. **「我没看到回显」≠「命令没执行」**——用户的两次「继续」之间，我这一侧已完成提交；`git status` 一片干净时，第一反应应当是查「有没有已完成的产物」，而不是从头重做。三档口径（①已写入 / ②已提交 / ③已推送）之外还要加一问：**「我凭什么认为它没发生？」**
2. **0 字节文件是最隐蔽的假证据**：`TASKS.md` 已经把这个空日志当成「证据」链接出去了。文档引用一份空文件，比不引用更糟——它让复核者以为查过了。
3. **探针里的「正例标记」必须从被测对象真实形态取**：rich 与 plain 的按键行不同，照抄另一个场景的判据会得到一根恒红的假探针，而它的红指向的是错误方向。
