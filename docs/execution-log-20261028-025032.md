## S9. 结外发现：修掉一处自己引入的 flaky（04:00-04:10）

`npm run verify` 首跑时 `tests/skill/loader.test.ts > 空项目目录 → 仅有内置技能` 红过一次；单跑该文件 + 再跑 3 次全量均绿。

**根因**：我的命令护栏用例 `execFileSync(tsx, ['src/cli/index.ts','--help'])` 调起**真实 CLI 子进程**，而 CLI 入口会碰 `~/.concertoai`（迁移 / 建目录 / 读技能）——它跑在测试进程之外、与其它测试文件并行，成了跨进程共享状态写入源；`SkillLoader.loadAll()` 正好要扫 `~/.concertoai/skills`，其用例判据是「两次独立 loadAll 数量相等」，全局目录被动 → 数量不等。

**修复**：护栏用例给子进程注入隔离 `HOME` + `USERPROFILE`（`mkdtempSync` → finally `rmSync`）。修后 `npm run verify` **连跑 2 次全绿**。

**教训已落** `docs/09-踩坑记录/2026-10-28-并发会话幽灵写入与任务书空头支票.md` 第四节：测试起子进程 = 不受控写入源；「单跑绿、全量偶红」先怀疑共享状态；flaky 也是 bug。
