### 2.2 P0-1：循环依赖友好失败（推断环检测 + executor 捕获 + safeAction 兜底）

**修复前（v4.0，`v4.0-test-result.md` 真实复现）**：release 模板预置 `build.depends: [test]` + 推断建议 `test → build` 叠加成环 `test → build → test` → `CyclicDependencyError` **未捕获** → 用户主动继续却得到 `[ConcertoAI] 未处理的 Promise 拒绝，详情见 ~/.concertoai/crash.log` 崩溃，无任何可操作提示。

**修复后**：
- 生成侧：`parser.inferDependencies` 每条推断边前调用 `hasDependencyPath(tasks, rule.to, step.name)` 环检测（to 已依赖 from → 加边必成环 → 跳过），直接环 + 间接环双覆盖（parser.test.ts 断言 `not.toContainEqual({from:'test', to:'build'})` 与 `{from:'c', to:'a'}`）；
- 消费侧：`executor.runWorkflow` 捕获 `CyclicDependencyError` → 友好失败结果（`ok:false` + `failedStep:undefined` + `cycle` 环路径）→ CLI `runFailedCycle` 文案「检测到循环依赖（test → build → test）💡 请编辑 release.yml，移除互相依赖的 depends 后重跑」，不再进 crash.log；
- 兜底层：`safeAction<A extends unknown[]>` 泛型化包住 workflow action——其余未预期异常也走「命令执行失败 + 堆栈 + 💡 下一步 + exit(1)」，不再 unhandledRejection。

**验证**：回归测试（executor 改断言 + parser 环检测 + cli 环场景 + error-summary）+ 自审报告 §1 代码级逐点推演（含 `toRunResult` 对环安全性主动深挖：`topologicalSort` 对环返回部分序不抛错，二次崩溃风险已解除）。手工侧本版未复测 release 环场景（需补 test/build 脚本，见已知问题 #1）。

### 2.3 P0-2：Windows stderr 合并（真实错误不再丢失）

**修复前（v4.0 mt42 实测）**：Windows 下 `npm run typecheck` 失败，npm 包装脚本把 tsc 真实错误（`error TS1287…`）透传到 **stdout**、stderr 为空 → 旧实现 `e.stderr ?? e.message` 只得到「命令执行失败: npm run typecheck」，真实错误全丢（mt42 恢复界面三连失败都看不到 TS1287）。

**修复后**：`defaultRunCommand` 失败分支合并 `stderr\nstdout`（两者都可能含关键行），仅两者皆空才退回 `err.message`；合并后统一走 stderr 字段 → 经 `extractErrorSummary` 提取关键行；4000 字符截断 + truncated 标记保留。验证：`tests/cli/workflow.test.ts` stdout 合并 4 用例 + 自审 §2 边界推演。

## 三、测试事故与恢复（cd 跨盘符污染项目根目录）

**事故**：mt44 测试中 `cd C:\tmp\concertoai-mt44` 从 F: 盘切到 C: 盘**未生效**（cmd 跨盘符必须 `cd /d`，命令不报错但停留原盘），导致后续所有写操作实际落到了**项目根目录**：

| 命令 | 实际影响 |
|---|---|
| `echo { "name": "mt44", … } > package.json` | **覆盖项目根 package.json**（丢失 dev/build/test/verify 脚本 + 全部依赖 + type: module） |
| `echo export const test: number = 1; > index.ts` | 根目录残留 index.ts |
| `concertoai workflow init` | 根目录 `.concertoai/workflows/` 生成 precommit.yml |
| preflight 自动初始化 | 向根目录 package.json 写入 lint/typecheck 脚本 |

直接后果：`npm run dev` 报 `Missing script: "dev"`；测试记录末尾「专家建议」中的 MODULE_TYPELESS_PACKAGE_JSON 警告实为污染假象（原 package.json 本有 `"type": "module"`），**无需处理**。

**恢复措施（2026-08-16 完成，5/5）**：

| # | 措施 | 验证 |
|---|------|------|
| 1 | `git restore package.json` 恢复 HEAD 版本（dev 脚本 + 依赖 + type: module 全部还原） | `git diff HEAD` 空 |
| 2 | 删除根目录残留 index.ts | 无残留 |
| 3 | 删除 `.concertoai/workflows/precommit.yml` 及空目录（skills/snapshots 为原有内容保留） | 无残留 |
| 4 | `npm run dev` 验证正常启动（非交互保护提示为预期行为） | ✅ |
| 5 | `npm run verify` 全绿（build + lint + typecheck + 全量测试） | ✅ 117 文件 / 1402 用例 |

**教训（已落盘规范）**：手工测试隔离目录必须 `cd /d <路径>`（跨盘符）+ 进入后第一件事 `cd` 确认当前目录；隔离步骤用 `pushd`/`popd` 或独立 .cmd 脚本包装；测试记录须记录「实际执行目录」而非仅命令。→ AGENTS.md 自查第 16 条 + 命令执行规则第 2 条 + 踩坑记录 `2026-08-16-手工测试cd跨盘符未生效污染项目根目录.md`。
