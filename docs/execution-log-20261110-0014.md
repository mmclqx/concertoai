## 三、实现（`scripts/instruction-state.mjs`，+228 行）

| 决策点 | 取舍 | 理由 |
|---|---|---|
| 退出码 | **10 = 已完成 / 11 = 记录与实际不符 / 0 = 可以接着做** | 若「已完成」也返回 0，调用方无法与「可以开工」区分 ⇒ 又是「安静地给出有利结论」 |
| 判据来源 | 不带 `--step` 跑整条指令的 `doneCriteria`；带 `--step` 只跑该步 criteria | 与 `check --step` 同语义，两个入口不产生两套真话 |
| 基线 | `--baseline` → `record.baselineHead` → `HEAD~3` → 首个提交 | §5.1 原文；**`--baseline` 无效直接 exit 2，不静默换**（换近了 diff 更空） |
| 变更三样 | `git diff --name-only <基线>..HEAD -- <targets>` + `git log` + `git status --porcelain` | 矩阵用提交级 diff；但**工作区未提交的产物也是产物**，必须显示出来（本轮真机实测就撞上了：diff 0 文件 + 工作区 1 项 M） |
| 复用（§5.2） | `logHead === HEAD` + `≤10 分钟` + 范围内无新增提交 + 无产物变更，`--force` 破 | 见 §四，这里**刻意比条文更严** |
| 副作用 | 默认写回 `steps[].dedup` / 顶层 `dedup`；`--no-save` 关闭 | 查重结论要能被下次「继续」读到，但也要能纯查询 |
| 不改 `status` | `verdict=done` 也不动 `status` | 「不要重做」≠「收尾完成」：终态 `--set-status done` 仍要重跑全部判据（§9.2 约束 1） |

## 四、变异探针（AGENTS 强制：判定类实现必须有否定面 + 变异自证）

每个探针都是「改坏实现 ⇒ 跑该组用例 ⇒ 必须红 ⇒ 改回 ⇒ 绿」，改前先 `copy` 备份原文件、改后 `node` 比对 `a===b` 确认**逐字节复原**。

| # | 变异 | 结果 |
|---|---|---|
| 1 | `verdict = allPass ? 'done' : … : …` → `verdict = 'done'`（恒「已完成」） | **4 红** ✅ |
| 2 | `not-done` 与 `mismatch` 两格互换（不看 diff 的方向） | **4 红** ✅ |
| 3 | 退出码 `EXIT.DEDUP_DONE`(10) → `EXIT.OK`(0) | **5 红** ✅ |
| 4 | 删掉复用条件 `prev.logHead === head &&` | **0 红** ❌ **覆盖缺口** |
| 5 | 删掉复用条件 `ageMs(prev.checkedAt) <= ttlMs &&` | **1 红** ✅ |

**探针 4 是本轮最重要的发现**：`logHead` 那条条件当时的用例**一个都没钉住它**——「HEAD 变了」的两条用例都恰好也在 targets 内改了文件，于是被「范围内有新提交」这条掩盖，删掉 `logHead` 照样全绿。这与 AGENTS「正例测试对该 bug 等价于没有测试」是同一个形状：**条件存在 ≠ 条件被测**。

修法：补一条隔离用例「HEAD 变了但**改动不在 targets 内** ⇒ 仍不复用」（提交一个 targets 之外的无关文件，断言计数器 +1、`verdictSource=measured`）。补完重跑探针 4 ⇒ **1 红**，改回 ⇒ 绿。
