## 关键实现决策（为什么这么做）

| # | 决策 | 理由 |
|---|---|---|
| 1 | 文案层「纯字符串优先」，Ink 只按**语义角色**上色 | 降级路径（非 TTY / CI / 分析失败）与 TTY 共用同一函数 → 两套说法从结构上不可能出现；且文案分支全部可用纯单测覆盖（44 条），Ink 测试只验排版 |
| 2 | diff 行**截断**、散文**折行**（两把宽度尺子） | 源码行折了就「不是 diff」；而解释性文字截断 = 丢信息（实测丢掉的正是「不是结论」这句关键限定） |
| 3 | 审批框**先弹 plain 再补 insight** | G2 铁律：可选功能绝不挟持核心流程；用户不能因为「分析慢」而按不了 y |
| 4 | 展示态意图用 **ref** 真值 + 80ms 节流 | 快照会滞后于同一批事件，节流会把滞后合并成一个「看似合理的错值」；`y`/`n` 决议**不走节流器**（G1） |
| 5 | `focusLines`（diff 下标）→ 文件行号用 hunk 头还原 | 直接展示 diff 下标会骗用户去文件第 N 行找一个不在那里的东西 |
| 6 | shell 严格「无目标文件」 | 传 `{}` 是假参数；`impactApplies=false` 显示「不适用（该操作不涉及文件引用）」，比扫全库然后说「0 个引用」诚实 |
