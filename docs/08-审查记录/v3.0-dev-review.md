## 七、问题清单

### 🔴 必须修复（2 项）

| # | 严重 | 位置 | 问题 | 修复建议 |
|---|------|------|------|----------|
| **I1** | 🔴 高 | `src/version.ts:7` + `package.json:3` | **VERSION 仍为 `'2.1.0'`**。v3.0 代码已全部就绪，但 `VERSION` 常量和 `package.json` 版本号未同步到 `3.0.0` | 执行 `npm version 3.0.0 --no-git-tag-version` 或手动更新两处为 `'3.0.0'` |
| **I2** | 🔴 中 | `src/agents/reviewer.ts:1-10` | **TeamReviewerAgent 的 `execute` 从不使用 context 参数**（`_context` 前缀为空值断言绕过）。这违背了显式上下文原则（§3.3），当前实现将 context 直接转发给 v2.1 引擎，但引擎的 `review()` 接口不接收 AgentContext，导致上下文丢失 | 在 `ReviewEngineLike.review()` 接口中增加可选的 context 参数，或由 TeamReviewerAgent 将 context.artifacts 中的 code 工件注入到审查范围 |

### 🟡 建议优化（4 项）

| # | 严重 | 位置 | 问题 | 建议 |
|---|------|------|------|------|
| **S1** | 🟡 低 | `src/market/installer.ts:344-345` | `agentDefFromPackage` 使用 `z.any()` 作为 input/output schema（已文档化原因：JSON 无法携带 zod 实例）。这导致安装的外部 Agent 无法做运行时输入/输出校验 | 可接受当前方案，但建议在文档中注明"外部 Agent 的 zod 校验由脚手架侧（promote 生成的 index.js 中）自行实现"。v3.1 可考虑将 schema 序列化为 JSON Schema（复用 `mcp/zod-adapter.ts`） |
| **S2** | 🟡 低 | `src/agents/architect.ts:180` / `src/agents/coder.ts:294` / `src/agents/reviewer.ts:82` / `src/agents/qa.ts:208` | 所有 Agent 的 `send()` / `receive()` 方法为 no-op。这是按设计暂不启用（消息路由由编排层接入），但接口要求实现这两个方法 | 当前可接受（Architect/Coder/Reviewer/QA 均通过 Orchestrator 直接调用 execute），v3.1 启用消息路由后实现 |
| **S3** | 🟡 低 | `src/agents/orchestrator.ts:193-195` | `executeTask` 中 Agent impl 查找失败时，错误消息写为 `Agent 未注册或未提供实现`，但调用方（schedule）无法区分「未注册」还是「已注册但无实现」 | 可分别处理：`entry === undefined` → "未注册"；`entry.impl === undefined` → "已注册但无实现实例" |
| **S4** | 🟡 低 | `src/observable/trace.ts:91-97` | `queryByTaskId` 递归收集子任务时，每次 `visit` 都遍历全部 spans（O(n²) 最坏情况下的父→子查询） | 对于 5000 条 LRU 上限的规模，实际影响可忽略。若未来扩展，可加 parentTaskId→子任务索引 |

## 八、最终结论

### ✅ 可发布 v3.0.0

**核准理由**：

1. **完整性**：v3.0-dev-plan.md 定义的 24 个任务（M0~M6）全部落地，CHANGELOG 的 Added（8 项）/ Changed（2 项）/ Fixed（2 项）均有对应代码
2. **质量**：699 测试全绿 / Biome 零 lint / tsc 零类型错误 / npm audit 零漏洞
3. **安全性**：fail-closed 权限声明 + sha256 校验 + 路径沙箱 + 外部修改检测 + 事务回滚 = 六重防护
4. **文档**：ARCHITECTURE.md §5 目录树完整、ADR-015~020 齐全、CHANGELOG 完整
5. **跨平台**：Windows（npm.cmd/taskkill）适配就绪

**发布前操作**：
```bash
# 1. 修复 I1：版本号同步
npm version 3.0.0 --no-git-tag-version

# 2. 修复 I2：Reviewer 上下文传递（参见上方修复建议）

# 3. 重新验证
npm run verify

# 4. 提交版本号变更
git add -A && git commit -m "chore(release): bump version to 3.0.0"
git tag v3.0.0
```
