## 四、6 个改进方向

### 1. Windows 兼容性改进

- **现状**：得分 7/10；Windows 下 self-heal 解析失败、spawn EINVAL 等问题暴露跨平台适配不足
- **对策**：
  - 增加 Windows CI 测试矩阵（`windows-latest` + `ubuntu-latest`）
  - 命令统一走 shellTool（`getPlatformAdapter` 平台检测 + 命令映射），禁止直接 spawn `.cmd`/`.bat`
  - 覆盖场景：self-heal 解析失败、spawn EINVAL、反斜杠路径/盘符冒号解析

### 2. ESM 模块规范统一（import.meta.url）

- **问题**：`concertoai team` 因 `__dirname` 报错未完全通过测试（ESM 模块混用 CommonJS 变量）
- **对策**：全项目统一使用 `import.meta.url`，禁止裸引用 `__dirname`/`__filename`
- **关联踩坑记录**：`docs/09-踩坑记录/2026-08-11-ESM模块误用__dirname导致team命令崩溃.md`

### 3. 解析器健壮性改进

- **问题**：self-heal 解析失败，依赖中文关键词匹配错误
- **对策**：增加结构化错误码（`inferErrorCode` 已部分实现），减少对中文关键词的依赖
- **关联踩坑记录**：`docs/09-踩坑记录/2026-08-11-Biome解析漏掉format与assist类别错误.md`（解析正则需 Windows + POSIX 双样本验证）

### 4. 用户体验改进（进度反馈）

- **问题**：`concertoai team` 执行时间长且无进度反馈
- **对策**：引入中间消息推送机制（拆解完成 / 闭环轮次 / 聚合结果分阶段推送）

### 5. self-heal.ts 代码规模

- **问题**：853 行偏大，单文件混合分类器 / 修复执行器 / 快照回滚 / 触发入口，职责边界模糊
- **对策**：拆分为 3-4 个模块（`classifier.ts` / `repair.ts` / `snapshot-guard.ts` / `index.ts` barrel）

### 6. 边缘场景与测试覆盖

- **问题**：4 个验收测试中 3 项通过，1 项（team）因 `__dirname` 报错未完全通过
- **对策**：增加 Windows CI 测试矩阵，命令统一走 shellTool，覆盖 Windows 下 self-heal 解析失败、spawn EINVAL 等问题场景
