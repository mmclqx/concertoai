## 三、真缺陷：④ 栏永远写「正常收尾」

### 3.1 判红读数（修复前，`.tmp-c2-e2e.log`）

```
❌ 再启动首屏的退出原因是「用户中断」
════════ 汇总：10/12 通过 ════════
```

### 3.2 根因（三处，都定位到行）

| # | 位置 | 事实 |
|---|---|---|
| ① | `node_modules/ink/build/components/App.js:148-163` | `if (input === '\x03' && exitOnCtrlC) { handleExit(); return; }` —— **`emit('input')` 在 `handleInput` 之后**，被 return 跳过 ⇒ `useInput` 永远收不到 Ctrl+C |
| ② | 同上 + `App.js:134-140` | TUI 期间 raw mode ⇒ Ctrl+C 是**字节** `0x03`，不是 SIGINT ⇒ `process.on('SIGINT')` 兜底一次都不触发 |
| ③ | `node_modules/ink/build/ink.js:295-305` | `handleAppExit` 只 `unmount()`，**不 `process.exit()`** ⇒ 进程自然结束（实测退出码 0） |

### 3.3 为什么原有护栏全绿

`tests/cli/handoff-wiring.test.ts` 那条断言的是「每个 `exit();` 的前 300 字符内有
`writeHandoffOnExit()`」——**形状正确、可达性为零**。同族旁证也不顶用：
`sandbox` 里向子进程发真 SIGINT 那条绿，走的是真机不存在的那条路。

### 3.4 修法

`src/cli/handoff.ts` 新增 `writeHandoffAtProcessExit()` + `installHandoffExitHook()`；
`src/cli/chat.tsx` 在 `render()` 之前装配一次。三条「不写」条件：
无快照（非交互命令）/ 空会话（B1 降噪裁决）/ **本轮已由更精确出口写过（不覆盖崩溃原因）**。

## 五、尺子自己坏了一次（同轮，必须记）

写 `doctor` 零写盘探针时，造的第 4 份样本是 `{provider, apiKey, model}`——**不是 v3 形状**
（`isV3Config` 只认 `schemaVersion === 1` 或无 `schemaVersion` 且有 `defaultModel`）。
于是四条「不写盘」全绿而**样本压根不会触发迁移**。改成 `{schemaVersion:1, defaultModel}` 后，
正例自证立刻把 `config get model`（无此子命令，exit 1）打红，换成 `config set hints off` 才 10/10。
判据一句话：**「不写」在验过「会写」之前没有证据力**（AGENTS 第 33 条同源）。
