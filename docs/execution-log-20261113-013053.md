| 文件 | 改动 |

**为什么只记 `'auto-low'` 不记 `'user'`**（用户裁决已认可）：记 user 会让默认路径每条 tool 消息多一个字段，现有精确形状用例大面积红；而 N2 要回答的恰是「是不是自动放的」。歧义写进字段注释，不藏。

## 二、T1.2 传递链接线（4 处小改）

```
autoLowApprove（App.tsx）  → request.autoLow = true（放行分支内，1 行）
edit.ts / shell.ts         → 成功返回带 approval（只成功路径；拒绝时用户已点过 n）
loop.ts executeGroup       → 条件展开盖戳
```

**关键实现细节（写进代码注释）**：`loop.ts` **必须用条件展开**
`...(result.approval !== undefined ? { approval: result.approval } : {})`。
写成 `approval: result.approval` 会给每条 tool 消息写入**值为 undefined 的键**——`JSON.stringify` 丢掉它（落盘看不出差异），但内存里 `hasOwnProperty('approval')` 是 true，「关闭 auto-low 不得有该键」那条否定面就会失真。

`shell.ts` 的透传**当前恒不生效**（shell 永不被自动放行），写它是为与 edit 对称，注释已说明。

回归：`tests/loop tests/tools tests/ui/auto-low-approval.test.tsx` ⇒ **10 文件 / 187 用例绿**。

## 五、本轮踩到并修掉的坑：测试竞态（单独跑绿、全量跑红）

**现象**：新增的端到端用例单独跑 **15/15 绿**，但混进全量 verify 里 **2 条红**：`expected [] to have a length of 1`（读到的 tool 消息为空）。

**根因**（不是产品 bug）：`App.tsx` 的顺序是 `setMessages(result.messages)` → 渲染出「完成了」→ 才 `await store.appendAll(...)`。而 `waitDone` 只等「完成了」出现在帧里 ⇒ 返回时**写盘可能还没完成**。机器越忙时间窗越大，所以单独跑不出现。

**修法与两次试错**：
1. 初版想复用 `waitFor(() => { void store.read().then(...); expect(...) })`——**错的**：`waitFor` 的断言函数是同步的，读盘是异步的，同步 tick 里拿到的永远是旧值，会白等满超时；
2. 改成**显式异步轮询**（`while (Date.now() < deadline) { await store.read(); if (够了) return; await sleep(20) }`）；
3. 同轮两条工具那条要 `expectAtLeast = 2`，否则读到 1 条就返回、断言 `toHaveLength(2)` 偶发红。
