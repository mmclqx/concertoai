## 关键实现决策（为什么这么做）

| # | 决策 | 理由 |
|---|---|---|
| 1 | 复盘写盘 **fire-and-forget**（`void` + 永不抛错） | 决议必须在写盘之前 resolve；用户按 `n` 的目的是「别改」，不是「等我写完文件」 |
| 2 | 用 `CONCERTOAI_REFLECTIONS` 做测试隔离，而不是 mock `node:fs` | 环境变量是产品**本来就支持**的开关，走真实链路比 mock 更贴近用户行为，也不会因 mock 顺序偶发失效 |
| 3 | `level: 'unknown'` 是独立枚举值，不是 `low` | 「没测到」和「结论是低」必须分开，否则复盘功能整体失真（实测踩到） |
| 4 | `ImpactSummary` 新增 `not-needed` 第五态 | 一个枚举承载两种事实时，文案必然在某一侧说谎（实测踩到） |
| 5 | `reflect clear` 非 TTY 无 `--yes` → fail-closed | 复盘是不可再生的判断历史，不能让脚本在管道里静默清空 |
| 6 | `clear` 的 `（y/N）` 回车 = 取消（区别于审批框回车 = 批准） | 审批框回车=批准是 v4.1.1 既有语义（G1 逐字节保留）；不可逆删除的默认必须最保守——两者场景不同，不能统一 |
| 7 | 环境变量非法值**回落 config** 而非回落默认值 | 否则 CI 里一次手滑（`=plian`）会静默推翻用户配置文件里的有效值（实测由测试报红捕获） |
| 8 | `validateConfigValues` 非法值**提示不抛错** | 配置写错一个字不该让 CLI 起不来，但用户必须看得见（与 pricingHolidays 非法日期同口径） |
| 9 | `config set` 非法值 **fail-closed 不写盘** | 与「读取时宽容」刻意相反：写入是用户明确表达意图的时刻，此时报错比写入一个「看起来设了但无效」的值诚实 |
