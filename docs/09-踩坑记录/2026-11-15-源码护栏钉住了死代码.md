# 源码护栏钉住了「死代码」：Ctrl+C 退出永远写不出「用户中断」

> 日期：2026-11-15（v5.3 收尾 C 轮）· 暴露环节：**发布门第 6 条**
> 一句话：`App.tsx` 里「Ctrl+C / Esc 退出前先写交接单」的两处调用**在真机上永远执行不到**——
> 因为 Ink 在把按键交给 `useInput` **之前**就把 Ctrl+C 截走了，而 raw mode 下那个 `\x03`
> 也不产生真信号。当时的源码护栏只断言「`exit()` 前面有这行代码」，于是**形状对、可达性错**，
> 全绿。真 PTY 一跑，④ 栏写着「正常收尾」——用户明明是 Ctrl+C 退的。

---

## 1. 现象（实测读数，不是推断）

`node .tmp-c-handoff-e2e.mjs`（真 PTY、真 TUI、mock SSE、临时 HOME）：

```
✅ 交接单文件已写出
✅ 四栏标题齐全
❌ ④ 栏 = 用户中断（Ctrl+C 走同一条收尾函数） ｜ > 退出原因: completed
✅ ② 栏记录了 echo hi 且判为通过
❌ 再启动首屏的退出原因是「用户中断」
  首屏读数: 上次交接：正常收尾（1 小时前）· …\handoff.md
════════ 汇总：10/12 通过 ════════
```

同一份脚本在**修好之后**：

```
✅ ④ 栏 = 用户中断（Ctrl+C 走同一条收尾函数） ｜ > 退出原因: interrupted
✅ 再启动首屏的退出原因是「用户中断」
  首屏读数: 上次交接：用户中断（1 小时前）· …\handoff.md
════════ 汇总：12/12 通过 ════════
```

顺带一条同样值的读数：**退出码是 0**（脚本里打印「第一次退出码：0」）——
「Ctrl+C 退出码 130」这个直觉在 Ink 下也不成立。

## 2. 根因（逐个文件定位到行）

### 2.1 Ink 在 `useInput` 之前把 Ctrl+C 吃掉

`node_modules/ink/build/components/App.js:148-163`：

```js
const handleInput = useCallback((input) => {
    // Exit on Ctrl+C
    if (input === '\x03' && exitOnCtrlC) {
        handleExit();     // ← 只 unmount，不 process.exit()
        return;           // ← 在 emit('input') 之前返回
    }
    …
}, …);
const emitInput = useCallback((input) => {
    handleInput(input);
    internal_eventEmitter.current.emit('input', input);   // ← 走不到这里
}, [handleInput]);
```

`useInput` 的所有处理器都订阅 `internal_eventEmitter` 的 `'input'` 事件
（`node_modules/ink/build/hooks/use-input.js`）⇒ **`App.tsx:2092` 里
`if (input === 'c' && key.ctrl) { writeHandoffOnExit(); exit(); }` 是真机上的死代码**。

### 2.2 raw mode 下 `\x03` 不是信号

`App.js:134-140` 的 `disableRawMode` 说明终端在 TUI 期间处于 raw mode。raw mode 里
Ctrl+C 只作为**字节** `0x03` 交给读流，**不产生 SIGINT** ⇒ `App.tsx:525-534` 装的
`process.on('SIGINT')` 兜底同样不触发。任务书 T2.2 写「SIGINT 兜底」时假设的是
「某些状态下 Ctrl+C 直接走信号」，实测在 Ink 7 + raw mode 下**这个分支一次都不走**。

### 2.3 进程是被「自然结束」的，不是被杀

`node_modules/ink/build/ink.js:295-305`：

```js
handleAppExit = (errorOrResult) => {
    if (isErrorInput(errorOrResult)) { this.unmount(errorOrResult); return; }
    this.exitResult = errorOrResult;
    this.unmount();          // ← 只卸载 React 树，没有 process.exit()
};
```

`unmount()` 清掉 stdin 监听、`stdin.unref()`（`App.js:137`）⇒ 事件循环空 ⇒ Node
自然退出。这解释了「退出码 0」：**没有人调 `process.exit`**。

## 3. 为什么四条护栏全绿（这才是真正要记的教训）

`tests/cli/handoff-wiring.test.ts` 当时写着：

```ts
for (const at of exits) {
  const before = src.slice(Math.max(0, at - 300), at);
  expect(before).toContain('writeHandoffOnExit()');   // ← 只证明「写在 exit() 前面」
}
```

它证明的是**代码形状**：那行确实在 `exit()` 前面。它证明不了**可达性**：那段代码
所在的 `if (input === 'c' && key.ctrl)` 分支在真机上永不成立。

三个「看着都对」的旁证也没帮上忙：

| 旁证 | 为什么不算证据 |
|---|---|
| 38 条 `handoff.test.ts` 全绿 | 测的是 `buildHandoff` / `finalizeSession` 的行为，**没人调用它们**也不影响 |
| `handoff-wiring.test.ts` 里真 SIGINT 打真进程那条绿 | 它是 `spawnSync` + 向子进程发 `SIGINT`，**不经过 Ink 的 raw mode** ⇒ 走的正是真机上不存在的那条路 |
| v5.3 N4 收尾时「真机已验：上次交接：正常收尾（1 小时前）」 | 那次验的是**正常收尾**（出口 ①），④ 栏对得上，所以没人怀疑 ③ |

这是「只测纯函数不测接线」（M-C 探针当初抓到的那个）的**第二种形态**：
接线写了，但接在一条真机不会走的分支上。判据一句话：

> **护栏钉的是「代码长什么样」，而缺陷可以是「这行代码永远执行不到」。
> 凡「某个事件发生时要做某事」，必须回答「这个事件在真机上是靠什么送到这里的」，
> 并用一次真入口的验证证明它送到过。**

## 4. 修法：在唯一必然发生的事件上兜底

新增 `writeHandoffAtProcessExit()` + `installHandoffExitHook()`（`src/cli/handoff.ts`），
在 `chat.tsx` 的 `render()` 之前装配一次。选 `process.on('exit')` 的理由：
它是上面三条路径（Ink 自然卸载 / `process.exit(130)` / 崩溃 `exit(1)`）下**唯一必然发生**
的事件，且允许**同步**写盘（与崩溃出口同步写同一理由）。

三条「不写」条件，缺任一条就会造出假记录：

| 条件 | 缺了会怎样 |
|---|---|
| 没有快照（UI 从未挂载，如 `doctor`） | 所有非交互命令退出时往用户 home 写一份空交接单 |
| 快照里一条消息都没有（打开就退） | 违反 AGENTS §已知边界 B1 的降噪裁决 |
| 本次退出已被 terminal 出口写过 | 崩溃写下的「异常退出：boom」被后面的 exit 钩子盖成「用户中断」——**真话被假话覆盖** |

第三条尤其要紧：它复用 `finalizeSession(terminal: true)` 的幂等标志，所以
「崩溃 → `finalizeActiveSession`」与「崩溃 → `process.exit(1)` → exit 钩子」不会打架。

## 6. 尺子自己坏了一次（同一轮内，必须一起记）

写 T4.1 真机手工 ①（`doctor` 零写盘）时，我造的「v3 配置」是：

```js
{ provider: 'deepseek', apiKey: 'sk-…', model: 'deepseek-v4-flash' }   // ← 不是 v3
```

而 `isV3Config`（`src/store/migration.ts:69-79`）只认
`schemaVersion === 1` / 「无 schemaVersion 且含 `defaultModel`」。
于是四条「doctor 不写盘」全部通过——**因为它们读的是一个本来就不会迁移的样本**。

这正好是本仓库立过的判据的反面：**「不写」在验过「会写」之前没有证据力**。
改成 `{ schemaVersion: 1, defaultModel: … }` 之后，正例自证那一条立刻变红（旧样本下
`config set hints off` 也不生成 `.v3.bak`），修好样本后才 10/10：

```
✅ 正例自证：默认路径（`config set hints off`）**确实**迁移——sha 变 + 生成 .v3.bak
   ｜ 128e06136eadf800 → 065e10ba7429422a；.v3.bak=true；exit=0
```

**同族提醒**：`config` 没有 `get` 子命令（第一版探针拿 `config get model` 当正例，
`exit=1` 且什么都没写）。写探针时先用 `--help` 确认子命令存在，别凭记忆。

## 7. 遗留（不假装覆盖）

- `App.tsx` 里那两处 `writeHandoffOnExit()` **保留**（不是删掉）：万一将来 Ink 版本改回
  「先 emit 再 return」，或者有别的按键路径进得来，它仍然是对的；`terminal: true` 的幂等
  保证与 exit 钩子撞车也只写一次。但**不能再把「它存在」当成「出口 ③ 已覆盖」**。
- `SIGINT` 兜底同理保留：Windows 上 `Ctrl+Break` / 外部 `taskkill` 等仍可能真发信号。
- 本轮只钉了「Ctrl+C 在空闲态退出」。**流式生成中按 Ctrl+C**（`abort()` 分支）不进退出路径，
  不写交接单——那是设计（不是退出），未变。
