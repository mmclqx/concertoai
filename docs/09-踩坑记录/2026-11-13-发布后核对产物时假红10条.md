# 2026-11-13 发布后核对「产物里有没有本轮改动」，10 条断言里 9 条假红 —— 探针错了，不是产物错了

## 问题描述

- **现象**：v5.2.0 发布成功后，为了证明「用户装到的那 1.1 MB 里，本轮修的文案真的在」，
  我写了个探针：把 `npm install @concertoai/cli@5.2.0` 装进临时前缀，读 `dist/**/*.js` 拼成一个大字符串，
  逐条 `includes()` 本轮新增的 i18n 文案。首轮读数 **1/10**：

  ```
  ✅ N1 doctor 无配置三态     -> 「尚无配置文件，将使用默认 v4 配置」   ← 唯一「命中」
  ❌ N1补完 v3 分支会备份      -> 「迁移前会自动把原配置备份到」
  ❌ N2  /approvals 零记录     -> 「本会话没有自动放行记录」
  ...
  ❌ 旧文案「不扫影响面」应已消失 -> 「不扫影响面」（仍存在！）
  ```

  正面 9 条全灭、反面 1 条「仍存在」。**看着像「发布出去的包根本不是新代码」**。
- **环境**：Windows 10 x64 / Node 22.23.2 / tsup(esbuild) 构建产物

## 根因分析

- **直接原因（两个方向相反的错误，凑在一起）**：

  1. **正面 9 条假红**：esbuild 默认 `charset: 'ascii'`，**i18n 里的中文在产物中是 `\uXXXX` 转义形态**：
     ```js
     migrationNoConfig: "\u5C1A\u65E0\u914D\u7F6E\u6587\u4EF6\uFF0C\u5C06\u4F7F\u7528\u9ED8\u8BA4 v4 \u914D\u7F6E"
     ```
     我按裸中文 `尚无配置文件` 去搜，当然一条也搜不到。
  2. **反面 1 条假绿**：`tsup` **保留注释**，而注释里的中文是**裸的**（源码注释原样进产物）。
     所以「裸形态搜到了」并不等于「用户可见字符串还在」，可能只是某条历史注释里提过这个词。

  于是同一个探针，**在正反两个方向上各错一次**——这比单方向错更危险：它同时给出「新内容不见了」和「旧内容还在」，
  两条结论一凑，几乎可以断定「发错包了」。

- **深层原因**：**我把「字符串匹配」当成了「语义核对」，却没先确认这个字符串在目标载体里长什么样。**
  这与 AGENTS 里两条老教训同源：
  - 「检索类必须先做正例自证」——本例连「我搜的形态在这个载体内是否存在」都没验；
  - 「否定断言必须精确到那句错话」——反面那条搜的是裸形态，而裸形态在注释里合法存在。

- **为什么它会骗过我自己**：探针**有 `blob.length` 检查**（1 MB，说明文件确实读到了），
  于是「探针通电」这一层看起来是绿的。但「读到了文件」≠「用对了匹配形态」，
  正例自证必须落在**被测的那个形态**上，而不是落在「文件读到了」上。

## 解决方案

- **修复方式**：把判据按**形态**拆开，并在脚本里写清理由：

  ```js
  // 用户可见字符串 ⇒ 搜转义形态（esbuild charset=ascii）
  const esc = (s) => [...s].map((c) => {
    const n = c.codePointAt(0);
    return n < 128 ? c : `\\u${n.toString(16).toUpperCase().padStart(4, '0')}`;
  }).join('');

  // 正面：转义形态命中（同时也接受裸形态，兼容将来改 charset 的情况）
  blob.includes(esc(s)) || blob.includes(s)

  // 反面：「旧文案已从用户可见处消失」必须断言**转义形态不存在**
  //       （裸形态若存在，只可能是注释残留，不影响用户）
  !blob.includes(esc('不扫影响面'))
  ```

- **正例自证改成「同形态探针」**：先断言 `blob.includes(esc('配置')) === true`，
  证明「在这个载体的这个形态下，我确实能搜到东西」，再去搜目标串。
- 修正后 **10/10**，其中反面那条附注：旧文案裸形态 `true`（注释残留）、转义形态 `false`（用户可见处已消失）——
  **两条读数一起看才说得清**。
- **涉及文件**：一次性脚本（未入库，判据已固化进 `docs/07.12-手工测试报告-v5.2.md` §11.3 与执行日志 §二十三）

## 经验教训

1. **对构建产物做字符串核对前，先确认「字符串在这个载体里长什么样」**。
   问自己：产物是压缩/转义/保留注释的哪一种？答案决定用裸串还是转义串。
   `charset: 'ascii'` 这一条尤其容易忘——源码里看得见中文，产物里全是 `\u5C1A`。
2. **「探针通电」要通到被测的那一层**。本例 `blob.length === 1MB` 只能证明「读到了文件」，
   不能证明「匹配形态对」。正例自证必须用**同一个匹配函数**去打一个必然存在的串。
3. **同一探针在正反方向各错一次时，两条结论会互相「印证」一个错误结论**（新内容没了 + 旧内容还在 ⇒ 判定发错包）。
   所以正面与反面都要先各自自证，不能只验一条。
4. **否定断言（「旧内容应已消失」）必须说清「在哪个载体形态下消失」**：
   注释里保留历史术语是合法的，把它算成违规会让护栏永远红。
5. 是否需要更新规范：✅
   - 规范更新位置：`AGENTS.md`「检索类/归因类必须先做正例自证」段 —— 补一句「正例探针必须**用同一个匹配函数**打在**被测载体的真实形态**上」。
