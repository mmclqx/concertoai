## 问题描述

- **现象**（真进程，zh 默认环境，C1 开发中实测）：
  ```
  $ concertoai bogus-xyz
  没有这个命令：bogus-xyz
  你是不是想输入 `balance`？        ← 错：bogus-xyz 与 balance 毫无关系

  $ concertoai --bogus-opt
  没有这个选项：--bogus-opt
  你是不是想输入 `--project` / `--provider` / `--version`？   ← 错：一次给三个，全是瞎猜
  ```
- **环境**：全平台（纯算法问题，与 OS / locale 无关）。
- **报警方式**：**没有任何报警**——不报错、不崩、`npm run verify` 全绿。

## 根因分析

- **直接原因**：Damerau–Levenshtein 距离的三处递推里，前两处漏了 `+ 1`：
  ```ts
  // 错（距离恒为 0）
  row[j] = Math.min(d[i-1][j], row[j-1], d[i-1][j-1] + cost);
  // 对（每次编辑的最小代价是 1）
  row[j] = Math.min(d[i-1][j] + 1, row[j-1] + 1, d[i-1][j-1] + cost);
  ```
  矩阵只由 `d[0][*]` / `d[*][0]` 的初值撑着，`Math.min` 一路取到 0 ⇒ **任何词与任何候选的距离都是 0** ⇒ 相似度恒为 1 ⇒ 阈值（距离 ≤N、相似度 >M）形同不存在。
- **深层原因（真正的教训）**：**测试只写了正例**。
  `docter → doctor`、`chek → check` 这类正例，在「距离恒 0」的实现下**照样通过**（因为每个词都会拿到“最近”的候选，而最近的恰好就是期望的那个）。也就是说：
  > **只有正例的测试，在这个 bug 面前与「没有测试」等价。**
  要抓到它必须断言**否定面**：「一个明显不相干的乱敲词，不得匹配任何真实命令」。
- **为什么中间还走了弯路**：我看到症状后把它归因成「阈值太松」，把阈值从「距离 ≤3」收紧到「≤2 且相似度 >0.5」——**在错误的层打补丁**。收紧后 `bogus-xyz` 恰好被挡掉（它到 `balance` 的距离真是 3），看起来“修好了”，但 `chek → chat`（距离 2）这类错误依然存在。**症状变窄 ≠ 根因修好**。

## 解决方案

- **修复方式**：三处递推补 `+ 1`（由并行体在 C1 提交 `4b4d7ac` 内修掉，并留了「实测踩过」注释）。
- **涉及文件**：`src/cli/cli-errors.ts`（`editDistance()`）。
- **待补护栏**：`tests/cli/cli-errors.test.ts` 增加
  1. **否定面**：`suggestSimilar('bogus-xyz', 真实命令表)` 必须为 `[]`；
  2. **通电自证**：同一候选表下 `docter → doctor` 必须命中（否则「空数组」可能只是因为候选表是空的）；
  3. **变异测试**：临时去掉 `+1` 后，第 1 条必须**变红**（证明这条用例真有牙，而不是恰好恒真）。

## 经验教训

- **算法类实现，正例测试等于没测试**：凡「算一个度量值再和阈值比」的实现（编辑距离、相似度、打分、代价函数），必写一条「明显不相似 ⇒ 必须判为不相似」的否定用例。
- **症状收窄 ≠ 根因修复**：调阈值能让症状消失时，先问「度量本身算对了吗」。本次调阈值只是把一条错误建议变成“没建议”，而错误照旧从别的口子漏出来。
- **是否需要更新规范**：✅ **已并入 `AGENTS.md`**（测试要求新增一条「**度量/算法类实现必须有否定面用例 + 变异自证**」：① 否定面用例 ② 阶梯自证 ③ 变异探针，判据一句话「**这个实现如果算错，我这条测试会红吗？**答否就是没测」）。
- **规范更新位置**：`AGENTS.md`（测试要求）；`docs/02-架构设计/ARCHITECTURE.md` **D90**（CLI 参数错误也是「给用户看的文案」，其中记了同一条测试纪律）。
