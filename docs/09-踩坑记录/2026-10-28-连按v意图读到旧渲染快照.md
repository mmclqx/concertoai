# 连按 `v` 时意图读到旧渲染快照，切换语义整段失效

> 日期：2026-10-28　版本：v5.0 T9（审批 UI 升级）　严重度：中（交互错乱，不影响安全语义）

## 现象

审批卡上**连按 10 次 `v`**（完整 diff 开/合），松开后卡片停在**展开态**，与「偶数次按键应回到收起态」的直觉相反。用户视角就是「按了没反应 / 按了乱跳」。

集成测试 `tests/ui/approval-integration.test.tsx` → 「狂按 v 10 次不会崩，且最终状态确定」第一次跑就红：

```
expected '[v] 完整 diff'  (收起态)
received '[v] 收起 diff'  (展开态)
```

## 根因

`useInput` 回调里用的是**渲染快照**里的 state：

```tsx
} else if (input === 'v') {
  getToggleThrottle().request({ diffFull: !diffFull });  // ← diffFull 是本次渲染的旧值
}
```

连按 10 次按键会在**同一批 React 更新**里执行，React 还没重渲染，`diffFull` 一直是 `false`。
于是 10 次算出来的目标值**全是 `!false === true`**，节流器「丢弃中间态、只保留最后一次意图」忠实地记下了同一个 `true` —— 最终停在展开。

> 关键教训：节流器本身没错，**错在喂给它的意图是错的**。中间态被丢弃时，错误也会被「合并」成一个看起来合理的结果，测试如果只断言「没崩」就永远发现不了。

## 修复

展示态的**逻辑真值**用 ref 维护（ref 赋值是同步的，能读到上一次按键刚写下的意图），state 只负责渲染：

```tsx
const diffFullRef = useRef(false);
const helpOpenRef = useRef(false);

} else if (input === 'v') {
  diffFullRef.current = !diffFullRef.current;              // ← 基于最新意图取反
  getToggleThrottle().request({ diffFull: diffFullRef.current });
}
```

配套：`requestApproval` / `finishApproval` 两个入口都把 ref 与 state 一起归零，避免上一次审批的展开态泄漏到下一次。

## 回归防护

- `tests/ui/approval-integration.test.tsx`：连按 10 次 → 断言最终为**收起态**，且随后 `y` 仍能正常批准；
- 同类问题（`?` 说明开合）用同一条路径，测试覆盖「展开后收起」；
- `tests/ui/toggle-throttle.test.ts`：原子级断言「连按 10 次 apply 次数 ≤ 3 且最后一次值正确」——**意图正确**与**节流生效**分开测，避免再次被「合并后的错误」掩盖。

## 一句话结论

> 凡是「累积/取反」类按键状态，**不要从渲染快照读**；快照会滞后于同一批事件，而节流/去抖会把滞后合并成一个看似正常的错值。
