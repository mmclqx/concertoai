# [2026-08-11] v3.1 审查发现版本号改动未提交 + 文档滞后于代码

## 问题描述
- 现象：`docs/08-审查记录/REVIEW-v3.1-full-2026-08-11.md` 报告 3 项严重问题（阻塞发布）：① 版本号 `package.json`/`src/version.ts` 仍为 3.0.0；② 文档引用不存在的 `src/loop/error-report.ts`；③ ARCHITECTURE 第 2 节全景图缺失 v3.1 模块。复查时发现：**版本号其实已被改成 3.1.0，但改动停留在工作区未提交**（git status 显示 modified），审查人看到的是已提交的旧状态（3.0.0）。
- 环境：Windows x64

## 根因分析
- 直接原因：版本 bump（package.json / package-lock.json×2 / src/version.ts / tests/smoke.test.ts / self-heal 相关 3 个测试的段标记 3.0.0→3.1.0）**已在工作区完成但未 git commit**；审查报告基于 `git log`/已提交文件，自然读到旧版本 3.0.0。
- 深层原因：
  1. **改码不提交 ≠ 完成**：版本号是多文件联动改动（6 处 + 段标记），改完未提交就进入下一环节，审查与代码状态脱节；
  2. **审查范围描述 vs 实际实现路径漂移**：M4 任务文档写 `src/loop/error-report.ts`（计划期预估名），实现落地为 `src/tools/error-codes.ts`，任务完成后未回填涉及文件路径；
  3. **ARCHITECTURE 第 2 节全景图未随目录树同步**：第 5 节目录树已含 v3.1 模块，但第 2 节 ASCII 图 tools/store 框漏了 error-codes.ts / projects.ts / accounts.ts——「目录树更新 ≠ 全景图更新」，两处需独立核对。

## 解决方案
- 修复方式：
  1. 版本号：确认 6 处一致 3.1.0（package.json / lock×2 / version.ts / smoke.test.ts）+ self-heal 测试段标记，补 README 状态行（v3.0.0/750-69 → v3.1.0/924-84），git commit 落盘；
  2. 路径修正：全项目搜索 `error-report.ts` 确认**无错误引用**（仅 REVIEW 报告自身描述），实际实现与文档均正确指向 `src/tools/error-codes.ts`，无需改动；
  3. ARCHITECTURE 第 2 节：tools 框补 `error-codes.ts`、store 框补 `projects.ts`/`accounts.ts`；
  4. 顺手修复审查警告：inferErrorCode 增加英文关键词（outside sandbox / command not found / spawn ENOENT）+ 补 1 用例（923→924）；self-heal 审批拒绝 break 前补 fail-closed 注释；accounts.ts chmod 加 `process.platform !== 'win32'` 前置。
- 涉及文件：package.json / package-lock.json / src/version.ts / tests/smoke.test.ts / src/tools/error-codes.ts / tests/loop/error-reporting.test.ts / src/loop/self-heal.ts / src/store/accounts.ts / docs/02-架构设计/ARCHITECTURE.md / README.md / CHANGELOG.md / docs/03-开发计划与任务/TASKS.md / docs/07.4-手工测试报告-v3.1.md

## 经验教训
- 如何避免同类问题：
  1. **版本号是多文件联动变更**：改版本号 = package.json + package-lock.json（顶部 2 处）+ src/version.ts + tests/smoke.test.ts + 代码里硬编码的 `@concertoai/cli@x.y.z` 段标记 + README 状态行，**一次改完立即提交**，不留工作区半成品；
  2. **审查前先 git commit**：进入「生成审查报告」环节前，确保工作区干净（`git status` 无 modified/untracked），否则审查基于旧状态产生假阳性；
  3. **计划路径 vs 实现路径回填**：任务完成后，把「涉及文件」中计划期预估值与实际落地文件核对回填（如 error-report.ts → error-codes.ts）；
  4. **全景图与目录树双核对**：ARCHITECTURE 第 2 节（全景图）与第 5 节（目录树）是两处独立维护，新增模块要同时更新，不能只更新一处。
- 是否需要更新规范：✅
- 规范更新位置：`AGENTS.md`（提交前自查：① 生成审查/发布报告前先 `git status` 确认工作区干净；② 版本 bump 后立即提交并全量搜索 `@concertoai/cli@x.y.z` 段标记与 README 状态行）
