# [2026-08-15] Ctrl+C 被误判为崩溃 + 测试问题未落盘导致中断丢失

## 问题描述
- 现象：用户在 test-autofix 项目测试 `concertoai workflow run`（precommit 模板）失败恢复交互时按 Ctrl+C，CLI 输出「未处理的 Promise 拒绝，详情见 crash.log」并退出码 1——用户主动取消被当成崩溃记录（AbortError: Aborted with Ctrl+C）。
- 环境：Windows x64 · Node v22 · @concertoai/cli v4.0.1
- 附加现象：同一批测试发现的「[F]修复后重试不自动修（UX 模糊）」「precommit 模板未提示 lint/格式约定前置」问题，在对话中断后未落盘，一段时间后被忽略（本次重新提出才补上）。

## 根因分析
- 直接原因：workflow.ts / plugin.ts / provider.ts 三处 `readline/promises` 的 `rl.question()` 在 Ctrl+C 时抛 AbortError，调用方未捕获 → unhandledRejection → crash-handler.ts 一律写 crash.log + exit(1)。
- 深层原因 1（代码）：crash-handler 的 unhandledRejection 不区分「用户主动中断（AbortError）」与「真实异常」——fail-closed 精神用错了场景：用户取消不是崩溃，crash.log 被污染会误导排查（用户看到崩溃记录会以为是 bug）。
- 深层原因 2（流程）：用户测试问题只做了口头分析、未落盘（执行日志/问题清单），对话中断后上下文丢失，问题被忽略。项目已有「执行日志」规范但只约束任务执行，未约束「用户测试反馈必须先记录」。

## 解决方案
- 修复方式：
  1. 新建共享模块 `src/cli/prompt.ts`：promptLine 捕获 AbortError → 返回 undefined（Ctrl+C 视为正常取消；非 TTY → undefined；其他错误原样上抛），workflow / plugin / provider 三处统一替换（消除重复 + 同类模式一次修完）。
  2. crash-handler.ts：unhandledRejection 收到 AbortError → 不写 crash.log、退出码 130（SIGINT 惯例），作为漏捕获兜底；真实异常行为不变。
  3. F 选项：promptRecovery 选 F 后打印 failureFixHint（「F 仅重跑失败步骤不自动修复，请手动修改代码」），消除「F 会自动修」误解（i18n zh/en 新增键）。
  4. precommit 模板：description + lint 步骤 description 补「需项目已配置 lint/typecheck/test 脚本与格式约定（biome.json）」。
- 涉及文件：src/cli/prompt.ts（新）/ workflow.ts / plugin.ts / provider.ts / crash-handler.ts / i18n zh+en / workflow/templates.ts + tests/cli/prompt.test.ts（新）/ crash-handler.test.ts（新）/ provider.test.ts（追加）

## 经验教训
- 如何避免同类问题：
  - 所有 readline question() 类交互输入统一走共享 promptLine，AbortError 必须在入口捕获，禁止裸 question()；
  - crash.log 只记录真实异常，用户主动中断（AbortError）绝不入日志；
  - 同类模式扫描：修复一个 Ctrl+C 问题时全项目搜 `readline/promises`，一处不漏（本次发现 provider.ts 第三处）。
- 是否需要更新规范：✅
- 规范更新位置：`AGENTS.md`（开发原则新增「测试问题先落盘」条目）
