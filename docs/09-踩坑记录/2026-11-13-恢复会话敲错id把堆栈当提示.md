# 2026-11-13 `chat -r` 敲错 id 把 Node 堆栈当错误提示甩给用户

## 问题描述

- **现象**：隔离 HOME + 真 TTY 实测（v5.2 手工验收）：

  ```
  > concertoai chat -r 20200101-000000-000
  [ConcertoAI] 未处理的 Promise 拒绝，详情见 C:\Users\…\.concertoai\crash.log
  Error: ENOENT: no such file or directory, open '…\sessions\20200101-000000-000.jsonl'
      at async open (node:internal/fs/promises:639:25)
      at async readFile (node:internal/fs/promises:1252:14)
      at async SessionStore.read (file:///…/dist/chunk-FNF743PH.js:633:17)
      at async runChat (file:///…/dist/chat-ER3VUHY6.js:5814:26)
  ```

  退出码 **1**、进程**自己退出**（不挂起）——两项硬指标都对，所以此前所有自动化用例都不认为它有问题。
  但屏幕上**没有一个字是给人看的**：用户不知道自己敲错了、不知道有哪些正确 id、也不知道下一步做什么。
- **环境**：Windows 10 x64 / Node 22.23.2（与平台无关，纯错误处理分支问题）

## 根因分析

- **直接原因**：`chat.tsx` 的 `-r <id>` 路径是裸 `await store.read(id)`，
  `SessionStore.read()` 对不存在的文件直接让 `readFile` 的 ENOENT 冒泡，
  最终落到全局 `unhandledRejection` 处理器（它只负责打印「详情见 crash.log」+ 堆栈）。
  `pickSession()`（`-r` 不带参数、走交互选择）那条路径有 `empty` 分支，**带参路径没有**。

- **深层原因（三条，都值得记住）**：

  1. **「退出码对、进程自己退出」被当成了「边缘路径已覆盖」**。
     AGENTS 边缘路径四条要求里，③「用户主动退出」是满足了，但 ②「失败后恢复」没有：
     失败之后用户能做的最有价值的事是「看到正确的 id」，而我们只给了一段堆栈。
     **退出码正确 ≠ 错误提示可用**，这两件事必须分别验收。

  2. **这条路径恰好是 v5.2 新能力的入口，设计时只想着「它已经能用了」**。
     `/approvals` 的全部价值是「`chat -r` 恢复昨天的会话后还能查到自动放行」——
     也就是用户**必然**会大量手抄 `20261113-024243-266` 这种 id。N2 的设计文档里
     一个字都没提这条路径失败时说什么。

  3. **错误处理按「有没有异常」二值化，而不是按「异常有几种事实」分类**。
     与同一天的 `doctor` N1 同源：`ENOENT`（记错 id）、`EACCES`（权限/磁盘）、
     `非法 id`（路径穿越）是**三件不同的事**，压成一句「读不出来」话就没法说准。

## 解决方案

- **修复方式**：新增纯函数层 `src/cli/resume-error.ts`（与 `slash/approvals.ts` 同构：无副作用、可单测）：
  - `classifyResumeError(id, error)` → `invalid-id` / `not-found` / `unreadable` 三态；
  - `describeResumeFailure({ id, error, recent })` → 要打印的行：
    - **invalid-id**：说清允许的字符集；
    - **not-found**：说「没有这个会话」+ **最近 5 个真实 id**（帮用户认出正确那个）；
      一条会话都没有时明说「暂无历史会话」，**不让用户以为记录丢了**；
    - **unreadable**：说「读取会话失败: <原因>」，**绝不**说成「不存在」；
  - 多行错误只取**首行并截断**（120 字），堆栈留在 `crash.log`；
  - 三态都附带下一步 `concertoai chat -l`（不留死胡同）。
- `chat.tsx` 改为 `readSessionOrExit()`：读 → 打印 → `process.exit(1)`，不再自己拼句子。
- `session.ts` 导出 `isValidSessionId()` 作为**唯一判定源**（不在调用方复制正则）。
- **涉及文件**：`src/cli/resume-error.ts`（新增）、`src/cli/chat.tsx`、`src/store/session.ts`、`src/i18n/zh.ts`/`en.ts`、`tests/cli/resume-error.test.ts`（新增）

## 经验教训

- **「退出码 1 + 自己退出」只是边缘路径的最低要求，不是达标线**。凡用户会走到的失败路径，
  必须再问一句：**屏幕上有没有告诉他「错在哪、正确的东西长什么样、下一步敲什么」**。
  自动化只断言退出码的话，这条永远不会红。
- **「这是别处的老代码」不构成不修的理由**：`-r` 带参分支早于 v5.2 就存在，
  但 v5.2 的 `/approvals` 把它变成了**必经之路**——新功能会改变老路径的权重，
  上线前应按新权重重新过一遍它的失败形态。
- **错误分类照抄 N1 的教训**：`ENOENT` / `EACCES` / 非法输入是三件不同的事，
  用一个 bool 或一句文案覆盖，必然对其中两种撒谎。
- 是否需要更新规范：✅
- 规范更新位置：`AGENTS.md`（测试要求 · 边缘路径段：补「失败提示是否可用」这一判据）
