# `npm test` 把测试数据写进了开发者真实的复盘记录

> 日期：2026-10-28　版本：v5.0 T10（拒绝复盘记录）　严重度：中（污染用户数据 + 污染不可见于测试输出）

## 现象

T10 实现完成后跑手工验证，`concertoai reflect list` 显示 **16 条**记录：

```
时间         级别       文件          风险类别
10-28 01:50  🟡 中      src/api.ts    网络请求/超时
10-28 01:50  ✅ 低      a.ts          —
10-28 01:50  — 未分析   b.txt         —
...
```

而我从没在真实终端里拒绝过这些编辑。检查 `project` 字段：

```
projects: [ 'concertoai-t9-blpH3r', 'concertoai-test-vpQTA6', ... ]
```

全部是 `mkdtempSync` 造的临时目录名 —— **都是 `npm test` 产生的**。

## 根因

三层因素叠加：

1. **默认开启**：`reflections` 默认 `on`（这是产品决策，合理）；
2. **写入路径是真实的**：`appendReflection()` 缺省写 `~/.concertoai/reflections.jsonl`（也是设计）；
3. **T9 的集成测试会走真实拒绝路径**：`approval-integration.test.tsx` 里有「按 n 拒绝」的用例，
   它们**不注入 writer**（T10 之前根本没有 writer 可注入），于是每跑一次 `npm test`
   就往开发者 home 里追加几条。

关键点：**这不是 T10 新增的 bug，而是 T10 让一个已存在的「测试写真实 home」缺陷变得有副作用。**

## 修复

| 层 | 做法 |
|---|---|
| 全局测试环境 | 新增 `tests/setup.ts`（`vitest.config.ts` 的 `setupFiles`）：`process.env.CONCERTOAI_REFLECTIONS = 'off'` |
| App 缺省值 | `reflectionsEnabled` 缺省读 `CONCERTOAI_REFLECTIONS`（嵌入调用方也能控；测试靠它兜底） |
| 要测写入的用例 | **显式**传 `reflectionsEnabled` + 注入 `appendReflectionForTest`（意图写在代码里，不靠环境巧合） |
| 要测默认值的用例 | 在 describe 里 `vi.stubEnv('CONCERTOAI_REFLECTIONS', '')` 清掉全局值（否则「默认 on」会被断言成 off） |

护栏用例：

```ts
it('未传 prop 时默认遵循环境变量 CONCERTOAI_REFLECTIONS=off（测试环境不落盘）', ...)
```

**为什么用环境变量而不是 mock `node:fs`**：`CONCERTOAI_REFLECTIONS` 是产品**本来就支持**的开关，
让测试走这条真实链路，比 mock 文件系统更贴近用户行为，也不会因为模块 mock 顺序偶发失效。

## 顺带发现

测试对「默认值」与「环境隔离」的需求是**互相冲突**的：全局关掉复盘会让「默认 on」的测试红。
解决办法不是让测试互相妥协，而是**让每组测试显式声明自己的前提**（stubEnv / 显式 prop）。

## 一句话结论

> 任何「默认写到用户 home」的功能，测试里必须**默认关掉**，需要写的用例再显式打开。
> 反过来（默认开、靠测试自觉隔离）一定会漏——因为下一个写测试的人不知道要隔离。
