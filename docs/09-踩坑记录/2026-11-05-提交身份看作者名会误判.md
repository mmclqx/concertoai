# 2026-11-05 提交身份看作者名会误判：`-c user.name` 管不住钩子读的环境变量

## 问题描述

- **现象**：本次 C6 提交用了 `git -c user.name="CONCERTOAI_AGENT" commit -m …`，命令回显 `[main 34cc627] …`、`git log` 里作者是 `CONCERTOAI_AGENT <…>` —— **看起来身份声明成功**。但 `git log -1 --format=%B` 的尾部是 `Agent: unmarked`。
- 环境：Windows 11 / git（cmd.exe）

## 根因分析

- **直接原因**：`.githooks/prepare-commit-msg` 读的是**环境变量** `CONCERTOAI_AGENT`；`git -c user.name=…` 只覆盖**作者字段**，不会设置环境变量。两者字面一样，语义完全不相干。
- **深层原因**：**「我传进去的东西」与「钩子实际读到的东西」是两条不同的通道**。命令成功、作者名正确、提交落盘——三个都真，唯一错的是钩子读的那个变量。而作者名恰好**长得像**身份声明（我甚至把 `user.name` 取成了 `CONCERTOAI_AGENT`），于是「看着对」覆盖了「实际对」。
- 同族：这就是 AGENTS 里「注入/全局扰动类验证必须先自证探针通电」的另一个面——**不要断言你以为传进去的东西，要断言对方实际读到的结果**。

## 解决方案

- **修法**：`cmd /c "set CONCERTOAI_AGENT=concertoai-loop&& git commit …"`，然后 `git commit --amend --no-edit` 重跑钩子，再 `git log -1 --format=%B` **读尾部**确认 `Agent: concertoai-loop`（而不是只看作者行）。
- **附带踩到的第二个坑（同一个提交）**：`cmd /c "set …&& git commit -m "很长中文消息""` —— **中文 + 嵌套双引号 + `&&`** 三者共存时，cmd 把一份 `-m` 拆成了多个 pathspec，报一串 `pathspec '…' did not match any file(s)`。改用 `git commit -F <消息文件>` 一次通过。
- 涉及文件：`.githooks/prepare-commit-msg`（无需改）、`docs/execution-log-20261105-2222.md` §8.0/§8.1

## 经验教训

- **判据：凡钩子参与的动作，核产物不核命令。** 提交后必须看 `git log -1 --format=%B` 的 **trailer**，而不是 `git log --oneline` 或作者字段——前者才是钩子的产出。
- **不要用「字面相同」的配置假装等价**：`user.name` 与 `CONCERTOAI_AGENT` 值一样，通道不同。命名相似最容易让人跳过验证。
- **Windows 上含全角标点的长提交信息一律走 `-F <file>`**：`-m` 在 `cmd /c` + `&&` 组合下会被引号处理拆坏，且报错方向（`pathspec` 不匹配）与真实原因（引号被吃）毫无关系，容易误判成「文件没 git add」。
- 是否需要更新规范：❌（属工具使用细节，`AGENTS.md` 已有「核产物」的同源纪律「探针通电 / 输出落盘 + 读尾部」）
- 规范更新位置：`ARCHITECTURE.md` 无需改；本条作为 `AGENTS.md`「归因类：关键判定一律输出落盘 + 读尾部」的实例
