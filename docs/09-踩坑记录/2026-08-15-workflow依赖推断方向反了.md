# [2026-08-15] workflow 依赖推断方向反了（precommit 模板生成错误 DAG）

## 问题描述
- 现象：`concertoai workflow init` 选 precommit 模板并确认「lint 与 typecheck 一起做」后，生成的 `precommit.yml` 依赖方向错误：
  ```yaml
  - name: lint
    run: "npm run lint"
    depends:
      - typecheck        # ← 错误：lint 依赖 typecheck，导致执行顺序 typecheck → lint
  ```
  期望是「先 lint 后 typecheck」（用户看到的提示 `lint → typecheck` 直觉），实际生成的 DAG 变成 lint 排在 typecheck 之后。
- 附加现象：用户在 Windows cmd 用 `type` 查看 YAML 时中文显示为乱码 `鎻愪氦鍓嶆鏌`。
- 环境：Windows x64 / Node v22 / @concertoai/cli 4.0.1

## 根因分析
- 直接原因：`src/workflow/parser.ts` 的 `DEPENDENCY_RULES` 中「lint 与 typecheck 通常一起做」规则写反：
  ```ts
  { pattern: /\bnpm run lint\b/, to: 'typecheck', ... }  // 语义 = lint 依赖 typecheck
  ```
  而 `types.ts` 明确定义 `InferredDependency.from = 依赖方（test 依赖 build）`——规则应表达「匹配步骤 X 依赖目标 T」→ `{ from: X, to: T }` → `X.depends += T`。lint 规则写成 `{ from:'lint', to:'typecheck' }` 等于「lint 依赖 typecheck」，方向与直觉相反（typecheck 应在 lint 之后）。
- 深层原因：
  1. **语义反向未在实现处显式声明**：`DEPENDENCY_RULES` 数组没有注释说明 `to` 是被依赖方，实现者把「lint 与 typecheck 一起做」的平级直觉直接写成 `lint → typecheck` 箭头，未对照 `InferredDependency` 注释校验方向。
  2. **提示文案箭头误导**：`cli/workflow.ts` 确认提示用 `X → Y` 展示，用户把箭头读作执行顺序（X 先执行），与「X 依赖 Y」的真实语义冲突，掩盖了反向 bug——用户确认「lint → typecheck」时实际确认的是「lint 依赖 typecheck」。
  3. **乱码为显示问题非文件错误**：生成的 YAML 是合法 UTF-8（实测 `Buffer.from(text,'utf8').equals(text)` 为 true），Windows cmd 默认代码页 GBK(936) 将 UTF-8 按 GBK 解码显示乱码；文件本身无编码问题。

## 解决方案
- 修复方式：
  1. `src/workflow/parser.ts`：规则方向修正——`npm run typecheck` → `to: 'lint'`（typecheck 依赖 lint，先 lint 后 typecheck），并将该规则置于 typecheck→build 之前（无 lint 时回落 build）；在 `DEPENDENCY_RULES` 顶部补充 `to` 语义注释（被依赖方，与 `InferredDependency` 一致）。
  2. `src/workflow/parser.ts`：`inferDependencies` 命中判断改为「目标不存在或已声明 → 继续尝试下一条规则」，修复旧逻辑「每条规则后无条件 break」导致 typecheck 无 lint 时漏推 build 的隐患。
  3. `src/cli/workflow.ts`：确认提示由 `X → Y` 改为 `X 依赖 Y`，消除箭头被误读为执行顺序的歧义。
  4. 新增回归测试：`tests/workflow/parser.test.ts` 增加「typecheck 依赖 lint（且无反向边）」「typecheck 无 lint 时回落到 build」2 个用例。
- 涉及文件：`src/workflow/parser.ts` / `src/cli/workflow.ts` / `tests/workflow/parser.test.ts` / `docs/09-踩坑记录/2026-08-15-workflow依赖推断方向反了.md`（本文件）

## 经验教训
- 如何避免同类问题：
  1. **依赖/箭头语义必须在实现处显式声明**：任何「边」结构（依赖、关系、指向）都要在规则表/常量旁注释「from 依赖 to / to 是被依赖方」，并用「X 依赖 Y」措辞展示给用户，禁止用「X → Y」——箭头会被误读为执行顺序。
  2. **规则表测试要覆盖方向断言**：不仅断言「推断出边」，还要断言「不产生反向边」（本次新增 `not.toContainEqual({from:'lint',to:'typecheck'})`）。
  3. **生成物（YAML/JSON）中文乱码先查编码再怀疑内容**：Windows cmd 显示 UTF-8 文件乱码是代码页问题（`chcp 65001` 或编辑器打开验证），不要误判为文件损坏；也不要为「显示正常」把 YAML 改成 GBK——YAML 标准为 UTF-8。
- 是否需要更新规范：✅
- 规范更新位置：`AGENTS.md` 提交前自查清单——建议新增「生成物方向/箭头语义自查」条目（本次为依赖推断，同类风险：插件权限 allowlist 方向、快照回滚方向、LSP 编辑方向）。
