# [2026-08-11] 文档测试基线未同步（81 文件 / 912 用例 → 实际 84 / 923）

## 问题描述
- 现象：v3.1-M6 完成后文档仍写「81 文件 / 912 用例」，但 `npm run verify` 实测为 **84 文件 / 923 用例**（M6 新增 3 个 E2E 测试文件 + trace.test.ts 新增 4 用例）。不一致点：`docs/02-架构设计/ARCHITECTURE.md` L431（目录树）、`CHANGELOG.md` L51（基线校准）、`docs/07.4-手工测试报告-v3.1.md` 4 处（基准行/预期行/已知问题/统计表）、`docs/03-开发计划与任务/TASKS.md` 顶部总览。若直接发布，门检「数字与行为描述」核对面会飘红。
- 环境：Windows x64

## 根因分析
- 直接原因：M5 收尾时基线校准到 81/912；M6 新增测试后只更新了 TASKS.md 里程碑状态（当时还是「待开始」），未同步刷新各文档的基线数字，也没有在 verify 后做一次「文档数字 vs 实测」全量核对。
- 深层原因：基线数字散落在 4 个文档 7 处，没有单一来源；且「新增测试 → verify 数字变化 → 同步文档」这一环没有在提交前自查清单里被强制触发（自查第 3 条「搜索文档中带数字的描述」只针对常量与行为描述，测试基线数字属于同类但易被遗漏）。

## 解决方案
- 修复方式：以 `npm run verify` 实测输出（84 文件 / 923 用例）为准，统一校准 4 个文档 7 处引用；历史完成记录（如 M5 的 81/912 变更日志条目）保留原文不动（历史事实），仅更新「当前基线」类表述。
- 涉及文件：`docs/02-架构设计/ARCHITECTURE.md`、`CHANGELOG.md`、`docs/07.4-手工测试报告-v3.1.md`、`docs/03-开发计划与任务/TASKS.md`

## 经验教训
- 如何避免同类问题：每个里程碑收尾时，在 `npm run verify` 拿到「Test Files / Tests」实测数字后，用 grep 全项目搜索旧的「N 文件 / M 用例」组合并逐一核对（区分「当前基线」与「历史记录」——历史记录不改，当前基线必须同步）；新增测试文件的提交与基线校准放同一次提交。
- 是否需要更新规范：✅
- 规范更新位置：`AGENTS.md`（提交前自查第 3 条补充：里程碑收尾时搜索「N 文件 / M 用例」基线数字与 `npm run verify` 实测一致）
