# 审批卡的说明散文被当 diff 行截断，`[?]` 解释被砍成省略号

> 日期：2026-10-28　版本：v5.0 T9（审批 UI 升级）　严重度：中（信息丢失，且丢的正是「这段话不可怕」的关键说明）

## 现象

`[?]` 说明区（以及「建议重点关注」这类长句）在中等宽度终端里显示成：

```
🟡 中风险：命中易误报规则（超时/断言/依赖变更），只是「建议重点关注…
```

用户看到的是**被腰斩的句子**，最关键的后半句「不是结论」正好被省略号吃掉——恰恰是 T8 已知局限要求必须传达到的那句话（medium 规则是噪声源，别当判决）。

## 根因

渲染层只有两把「宽度尺子」，一开始**只有一把**：

```ts
// 早期实现：所有行一律 clip()（按显示宽度截断 + 补 …）
function clip(text, width) { return truncateToWidth(text, width); }
```

`clip` 对 **diff 行**是完全正确的语义（源码行不能折行，折了就不是 diff 了），但把它套到**散文**上就是错的：散文截断 = 丢信息。

## 修复

按内容类型分两把尺子（`src/utils/text-width.ts` + `src/ui/approval-text.ts`）：

| 内容 | 处理 | 函数 |
|---|---|---|
| diff 行 / 命令行 | 按宽度**截断**（源码不可折行） | `truncateToWidth` |
| 标题 / 改动性质 / 影响面 / 风险点 / 关注行 / 说明 | 按宽度**折行**（保留全文） | `wrapToWidth(text, width, maxLines)` |

`pushWrapped` 处理缩进续行（风险点 `  ▪ ` 缩进 3 格、说明区缩进 6 格），`maxLines` 兜底防极端长文案撑爆屏幕。

## 回归防护

`tests/ui/approval-text.test.ts` → 「medium 的说明解释『这不是结论』」：

```ts
expect(text.replace(/\n/g, '')).toContain('只是「建议重点关注」，不是结论。'); // 整句没被砍
expect(helpSection).not.toContain('…');                                       // 折行不留截断痕迹
```

第二条断言是关键：它把「用截断冒充折行」这个具体错误变成红灯，而不是只检查「有没有这段文字」。

## 一句话结论

> 宽度处理要先问「这行能不能折」：**源码/diff 行只能截断，人类语言必须折行**。
> 用一把尺子套所有文本，丢掉的往往是句尾那句最要紧的话。
