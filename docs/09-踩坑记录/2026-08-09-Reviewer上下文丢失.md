# [2026-08-09] Reviewer 显式上下文丢失（TeamReviewerAgent.execute 忽略 _context）

## 问题描述
- 现象：`TeamReviewerAgent.execute(input, _context)` 用 `_context` 前缀忽略上下文参数，直接 `engine.review({ scope })` 调用审查引擎；上下文中的 code 工件（Coder 产出）不进入审查范围，Reviewer 只能靠磁盘路径读文件，虚拟工件（无路径）完全不可见。审核报告标记为 🔴 I2 必须修复
- 环境：Windows

## 根因分析
- 直接原因：`execute` 签名声明了 `context: AgentContext` 但从未读取，参数以 `_context` 命名并被空值断言/忽略
- 深层原因：v2.1 的 `ReviewerEngine.review()` 接口只接收 `ReviewScope`，未预留显式上下文入口；v3.0 把 Agent 升级为标准契约（execute 必须收 context）时，Reviewer 只是「透传」了 context 给引擎，但引擎接口不支持，导致上下文在 Agent→引擎边界丢失——违背显式上下文原则（§3.3）

## 解决方案
- 修复方式：① `ReviewEngineLike.review()` 增加可选 `contextArtifacts` 参数；② `execute` 从 `context.artifacts` 提取 code/file 工件透传给引擎；③ `ReviewerEngine` 将工件内联注入 5 个审查子代理 prompt（新增 `formatContextArtifacts()`）
- 涉及文件：`src/agents/reviewer.ts`、`src/reviewer/engine.ts`、`src/reviewer/types.ts`、`src/reviewer/index.ts`、测试 2 文件

## 经验教训
- 如何避免同类问题：Agent 实现 execute 时，若上下文必须传递给依赖引擎，先检查依赖接口是否支持显式上下文；「接口优先」下应在 Agent 接口定稿时就为引擎预留 context 参数。可加自检：`execute` 中 `_context` 前缀参数一律禁止（要么使用，要么删除）
- 是否需要更新规范：✅
- 规范更新位置：`AGENTS.md`（TypeScript 类型安全规范 / 提交前自查）
