# 2026-10-31 成本熔断「超 ¥1 立刻停」从头到尾没响过（判据被自身精度吃掉）

> 编号：K15（`TASKS.md` L116）｜严重级别：🔴 纪律级（闸门失效但**不报错**）｜修复于 2026-10-31

## 问题描述

- **现象**：手工测试脚本（`scripts/real-key-t233.mjs`、`scripts/t233-scenarios-67.mjs`）的花费闸门是「跑前读余额 → 跑后读余额 → 差额 > ¥1 就停手」。复验 K10 时 `--only=7` **真花 ≈¥2.11**（¥7.64 → ¥5.53），脚本却打印「差 0」，**熔断一次都没触发**；同时在跑前估算里我写的「≈¥0.0165」与真实花费差约 100 倍。
- **环境**：Windows 11 / Node 22 / DeepSeek 官方 API（真 Key，隔离 `HOME` 的临时项目）。
- **为什么危险**：它不是「功能没了」，而是**闸门看起来在工作**——脚本有阈值常量、有判断语句、有「超了立刻停」的日志文案，只是那条 `if` 永远不会成立。任何「跑一次手工测试」的人都会以为「没超预算」。

## 根因分析

- **直接原因**：判据（余额差）与被测量（真实花费）**不同源**。`GET /user/balance` 返回的 `total_balance` 只有 **2 位小数**，且**结算有延迟**——场景刚跑完的那一刻，钱还没扣到账上，于是 `before - after` 恒为 `0.00` 或 `0.01`。一次子代理调用 ≈¥0.0002，一张审查 5 子代理 ≈¥0.06，全部落在 1 分钱的量化噪声里。
  - 实测证据（2026-10-31，同一轮真 Key 跑）：本地累加 **¥0.118300**（`review` ¥0.0595 + `review --fix` ¥0.0588）时，余额即时差 **¥0.02**；约 10 分钟后重读才追到 **¥0.09**。也就是说「跑完立刻读余额」拿到的数字，最乐观也只有真实值的 1/6。
- **深层原因（这才是要记住的）**：**「闸门判据」和「记账口径」是同一个读数的两个消费者，而这个读数本身带延迟与量化误差。** 一旦判据的分辨率低于被测量的量级，闸门就退化成一句永远为真的 `if`，而且**失败形态是沉默的**——没有异常、没有红字，日志还会主动给出有利结论（「差 0」）。这与 AGENTS 里「检索类/归因类错误不报错、只安静地给出有利结论」是同一类病：**它不会失败给你看，它只会给你一个让你安心的数字。**
- **放大器**：同一份「估算」也被拿去当预算预期（跑前估算表），而估算按「一次问答」规模算、真实调用是「一次代理循环」（子代理多轮工具调用、`--fix` 每条问题一次带整文件内容的调用），两者相差两个数量级——「估算小 + 读数恒 0」两个假象互相印证，谁都不会去查余额。

## 解决方案

- **① 计量：换成与事实同源的读数**（`src/model/usage-tally.ts` 新增 + `src/model/client.ts`）
  - `DeepSeekClient.recordUsage(chunk, model)` 在 `yield` **之前**捕获 `chunk.usage`（用户中途 Ctrl+C 也已产生的 token 不会漏账），交给 `UsageTally` 累加；
  - `UsageTally.add(sample, modelId, at)` 用**本次请求的模型 + 请求时刻**调 T7 的 `costFor` 就地计价（不新建价格表、跨高峰/空闲档不串价）；
  - 之所以放在 client **单点**：4 条花钱链路（`loop` / `reviewer/autofix` / `core/commit-message` / `loop/self-heal`）共用同一 client 实例，各链透传要改 5 处且以后新增链路必漏。
- **② 可见：把「这次花了多少」交出来**（`src/cli/usage-line.ts` 新增，`review` / `commit` / `fix` 共用唯一渲染入口）
  - `💰 本次消耗：N 次调用 ｜ 输入 A / 输出 B tokens ≈ ¥C`，金额 **6 位小数**（2 位小数看不见一次子代理调用）；
  - `UsageTotals.measured` 区分「花了 0」与「量不到」：量不到时说「本次未能统计消耗，费用未知」，**绝不打印 ¥0**（¥0 会被读成「这次免费」）；未知模型 `priced: false`，金额只当**下限**。
- **③ 闸门：判据换源 + 不可度量 fail-closed**（`scripts/lib/cost-gate.mjs` 新增纯函数 + 两个驱动脚本改接线）
  - 唯一权威读数 = CLI 自己打的「本次消耗」行；余额降级为**事后量级对账**（保留探针读数，证明余额接口可用）；
  - `parseCostLine` 读不到 / 金额非法 / 含「未计价」标记 → `ok: false`；`gateDecision` 对 `ok: false` 一律 **stop**——「量不到」不许花钱；
  - 闸门抽成纯函数后，「有没有牙」变成 `tests/scripts/cost-gate.test.ts` 的 18 条断言（`npm test` 每次重跑）：超阈值必停、读不到必停、**注入阈值 ¥0.0001 / ¥999 的正反自证**；PTY 折行兜底（金额掉下一行仍能读到）。
- **涉及文件**：`src/model/usage-tally.ts`（新）、`src/model/client.ts`、`src/cli/usage-line.ts`（新）、`src/cli/{review,commit,fix}.ts`、`src/i18n/{zh,en}.ts`、`src/index.ts`、`scripts/lib/cost-gate.{mjs,d.mts}`（新）、`scripts/{real-key-t233,t233-scenarios-67}.mjs` + 7 个测试文件。
- **复验（真 Key，2026-10-31 15:0x）**：`node scripts/real-key-t233.mjs` **23 断言全 PASS**，其中三条是新加的「成本可度量」断言；`npm run verify` **2310 全绿**（基线 2254，+56）；`LUMEN_LOCALE=en` 换环境复跑全绿（并自证 `balance` 输出切英文，证明环境注入真的被读到）。

## 经验教训

- **闸门的判据必须与被测量同源**：想知道「花了多少」，就读「模型自己报的 token × 单价」，不要读「另一个系统延迟结算后的余额」。凡是「A 的读数 + 延迟 / 截断 → 推断 B」的判据，都要先问：**这个读数的分辨率够不够分出「有」和「没有」？**
- **「读不到」必须与「值 = 0」分开**：本次最贵的一句话是「差 0 = 没花钱」。任何度量接口都要有 `measured: false` 这种**第三态**，并且默认行为是 fail-closed（停手），不是继续。
- **闸门要能被测试证明有牙**：只要验证闸门必须真花钱 / 真超支，「有没有牙」就永远只能靠人相信。把判定抽成纯函数 + 注入读数与阈值，是让「闸门真的会响」变成回归用例的唯一办法（同 AGENTS「探针通电」：先证明探针真的通）。
- **沉默的失效比崩溃更贵**：崩溃会有人修；「日志说差 0」会被当成结论写进报告。所以**凡是给出有利结论的读数，都要交叉对账一次**（本次即「本地累加 vs 余额事后差」两条线同时打印）。
- 是否需要更新规范：✅
- 规范更新位置：`AGENTS.md`「阈值闸门禁止用带延迟 / 精度截断的外部读数当判据」（铁律区，紧接「转换函数边界」那条）；架构决策 `ARCHITECTURE.md` D86。
