# 2026-11-07 CJK 检索静默零命中（findstr / 内置检索工具都中招）

## 问题描述

- 现象：本轮（2026-11-07 凌晨，TASKS.md 落盘「冻结护栏测试实施计划」任务）为了确认 `tests/cli/freeze.test.ts` 是否存在、以及给该待办行追加一句指引，用两种方式做中文子串检索，**两次都返回「0 命中」**：
  1. `findstr /c:"本轮 T23.2 只落文档不动测试" "docs\03-开发计划与任务\TASKS.md"` → 管道后 `matched chars=0 MISS`；
  2. 内置检索工具 `search_content(pattern="冻结")` 在同一个文件上 → `hits: []`（而该文件里「冻结」出现几十次）。
- 反证（同一台机、同一会话）：`node -e "...s.indexOf('本轮 T23.2 只落文档不动测试')"` → `indexOf= 35522`、`split(key).length-1 = 1`；`git ls-files | findstr /i freeze` → 有命中。
- 环境：Windows x64 / cmd.exe（经 PowerShell 包装）/ Node 22。

## 根因分析

- 直接原因：`findstr` 与部分检索工具的**中文参数/中文模式走了非 UTF-8 代码页（GBK）**，与文件实际编码（UTF-8）不匹配 → 模式串被转换成乱码，永远匹配不上，自身**不报错**，只安静返回「0 命中」。
- 深层原因：**「检索」这个动作的失败是静默的、且方向偏向「给你一个对你有利的结论」**（「搜不到 ⇒ 不存在 ⇒ 干净」）。这一条 AGENTS 已经写过（「检索类」纪律），但规范里只要求「先让工具命中一个必然存在的样本」，**没要求探针与被测样本同域**——我做的正例探针是 ASCII 的 `freeze`（命中了 `docs/FEATURE_FREEZE.md`），被检样本却是**中文**子串，两者不同域，探针「通电」了但没覆盖被测的字符集，等于探针空转。

## 解决方案

- 修复方式（本轮即时处置）：**凡是中文子串的存在性判断，一律用 `node -e` + `fs.readFileSync` + `indexOf`/`split().length-1` 做，并把命中数打印出来**；`findstr` / 内置检索工具只用于 ASCII 关键词定位候选文件，结论必须再经 Node 复核。
- 涉及文件：本轮无代码改动（`docs/03-开发计划与任务/TASKS.md` 的编辑改用 edit_file + Node 复核），规范侧建议见下。
- 本次影响范围（已核）：两次 MISS 都**没有**导致错误结论落盘——第一次 MISS 前已用 `git ls-files` + `list_directory` 双路确认 `tests/cli/freeze.test.ts` 不存在；第二次 MISS 后改用 Node 复核，指引句正常追加、表格行未被拆断（`lines=1710`、第 105 行 `endsWith pipe: true`）。

## 经验教训

- 如何避免同类问题：
  1. **探针必须与被测样本同域**：查中文就用中文字符串做正例探针（如 `search_content("冻结")` 必须先在一个已知含该词的文件上命中），查正则就得用同一条正则命中已知样本。
  2. **存在性判断不许只信一次搜索**：至少两条独立路径（`git ls-files` / `list_directory` / Node `indexOf`），任一条能命中即为真；全不命中才可下「不存在」结论，且必须报出「用了哪几条、各自结果」。
  3. 中文结论一律**落盘可复验**（打印 `indexOf` 值或命中数），不写「我搜过了，没有」。
- 是否需要更新规范：✅
- 规范更新位置：`AGENTS.md`「适用范围扩至检索类 + 归因类」段——建议补一句：**正例探针必须与被测样本同域（同字符集 / 同匹配方式），用 ASCII 关键词通电不代表能查中文**。（本条属规范修订，**本轮不动 AGENTS.md**，留待用户裁决后与代码任务同批落地，避免夜间擅自改纪律。）
