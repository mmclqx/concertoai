# [2026-08-11] config.test.ts 环境变量隔离不全导致外部 LUMEN_LOCALE 假失败

## 问题描述
- 现象：在 shell 预设 `LUMEN_LOCALE=en` 后运行 `npm test`（或 `npm run verify`），`tests/store/config.test.ts` 报 **`AssertionError: expected 'en' to be 'zh'`** / `expected 'en' to be 'zh_CN.UTF-8'`，「全部缺省时用内置默认」与「locale 优先级」两个用例假失败；未预设环境变量时全绿。
- 环境：Windows（POSIX 同现，凡 CI/终端预设 locale 类环境变量即触发）

## 根因分析
- 直接原因：`beforeEach` 只 `vi.stubEnv('LANG', '')` 隔离系统 LANG，未 stub `LUMEN_LOCALE`；「locale 优先级」用例内部 `vi.unstubAllEnvs()` 后只重新 stub `LANG`，外部 shell 预设的 `LUMEN_LOCALE` 再次暴露 → `resolveConfig` 按「环境变量 > LANG > 配置」优先级读到 `en`，与断言 `zh` / `zh_CN.UTF-8` 冲突。
- 深层原因：测试隔离只覆盖了「常见」环境变量（LANG），未枚举项目自身定义的 env（LUMEN_LOCALE / LUMEN_MODEL / LUMEN_ALLOWLIST 等）。config.test.ts 只 stub 了 LANG，而项目 i18n 解析链（`resolveLocale`）同时消费 `LUMEN_LOCALE`——凡是断言「全部缺省」或「LANG 兜底」的用例，都必须把项目级 env 一并隔离，否则外部环境一污染就假失败。

## 解决方案
- 修复方式：
  1. `beforeEach` 补 `vi.stubEnv('LUMEN_LOCALE', '')`（与 LANG 并列隔离）；
  2. 「locale 优先级」用例 `vi.unstubAllEnvs()` 后补 `vi.stubEnv('LUMEN_LOCALE', '')`。
- 涉及文件：`tests/store/config.test.ts`

## 经验教训
- 如何避免同类问题：断言「默认值」或「LANG 兜底」的测试，必须在 `beforeEach`/`unstubAllEnvs` 后隔离**项目自身消费的全部环境变量**（DEEPSEEK_API_KEY / LUMEN_* 等），不能只隔离系统变量；新增环境变量解析时，搜索依赖该解析的测试并补隔离。
