# 2026-11-10 `vitest run <文件> -t <过滤词>` 零匹配也返回成功——拿它当判据就是恒绿

## 问题描述

- **现象**：给 `dedup`／`show` 写「指令进度记录」判据时，第一版 `doneCriteria` 写成：
  ```
  npx vitest run tests/scripts/instruction-state.test.ts -t show
  expect: exit 0 且输出含 "Tests"
  ```
  `show` 子命令**还没写**、相关用例**一条都没有**，`write` 的基线实测却打印：
  ```
  instruction-state: baseline C1 = GREEN ｜ RUN  v4.1.12 F:/developer/2026/concertoai
  ```
  ——**判据在「功能完全不存在」时就已经绿了**。
- **环境**：Windows x64 / Node 22 / vitest 4.1.12
- **危害等级**：🔴 高——这不是一条测试写错，而是**一整类判据写法恒绿**：任何用 `-t <过滤词>` 过滤的判据，在用例被删、被改名、过滤词打错、文件里还没写用例时，都会**静默返回成功**。

## 根因分析

- **直接原因**：vitest 在「过滤器零匹配」时的行为是**全部 skipped**，而不是失败：
  ```
  Test Files  1 skipped (1)
       Tests  73 skipped (73)
   exit code = 0
  ```
  我的判据只断言 `exit 0` + 输出含 `Tests` 字样——两条都被满足（`73 skipped` 里就有 `Tests`）。
- **对比「文件不存在」**：同一个 vitest，指定一个不存在的用例文件是 **exit 1**（`No test files found, exiting with code 1`）。所以问题不在 vitest「不报错」，而在**我挑的那把尺子（过滤词）本身就允许零匹配**。
- **深层原因**：判据里只要出现「**过滤器**」这个中间层，就会出现「过滤后一个都没选中 ⇒ 空集 ⇒ 空集上的全称命题恒真」的经典漏洞。这与 AGENTS「判定类护栏必须双向验收」里那条「一个『过滤掉一切』的废实现能轻松骗过 ②（不该红必不红）」是同一个形状：**过滤条件放宽到失明，护栏就等于不存在**。
- **我是怎么发现的**：不是靠读代码，而是靠 `write` 的 **`baselineCriteriaState` 实测**——它在落记录时当场跑一遍全部判据，并打印 `baseline C1 = GREEN`。**「还没做就已经绿」这一步立刻把问题顶出来了**。如果当初用了 `--skip-baseline`，这条坑会一直睡到某次「判据说 done、功能其实没做」时才爆。

## 解决方案

- **判据改落「文件粒度」**：把 `show` 的用例拆成独立文件 `tests/scripts/instruction-state-show.test.ts`，判据写成
  ```
  npx vitest run tests/scripts/instruction-state-show.test.ts
  ```
  这样「文件不存在 ⇒ exit 1」「用例被删空 ⇒ 文件里没有 `it(`，`check:tests` 那条护栏也会红」，两道都还在。
- **保留 `expectContains: ["Tests"]`**：作为第二道（防止「跑了 0 个用例但 exit 0」的极端情况）。
- **归入纪律**：AGENTS 新增第 34 条，明确「判据里禁止用 `vitest run <文件> -t <过滤词>`」并给出替代（文件粒度 / `expectContains`）。
- **顺带确认了一条既有纪律的价值**：`write` 默认实测基线（除非显式 `--skip-baseline`）这件事**当场抓到了本坑**，应继续保留；`--skip-baseline` 只该用于「脚本自举 / 用例内部」。
- **涉及文件**：`.tmp-batch-payload.json`（指令载荷，判据定义处）、`tests/scripts/instruction-state-show.test.ts`（新建）、`AGENTS.md`（第 34 条）

## 经验教训

- **「零匹配算通过」是所有过滤型判据的通用陷阱**：`grep -c` 返回 0 行、`vitest -t`、`jest -t`、`--testNamePattern`、`findstr` 无命中但退出码 0（本仓库另一条踩坑 `2026-11-07-CJK检索静默零命中.md` 同源）——**凡是「先筛再判」的地方，都要先证明「筛出来的集合非空」**。
- **判据要能用一句话自证不是恒绿**：「这个功能如果完全没做，这条判据会红吗？」——本坑的答案是「不会」，所以它当场就不合格。
- **`write` 的基线实测是这类问题的唯一发现渠道**：它把「判据在功能未实现时的颜色」写进 `baselineCriteriaState`。看到 `GREEN` 而功能还没写，**第一反应必须是「判据写错了」，而不是「我已经做完了」**。
- **是否需要更新规范**：✅ 已写入 AGENTS 第 34 条（判据写法硬要求）。理由：这不是一次性失误，而是**会重复使用的判据模板**，模板错了后面每一条 doneCriteria 都会跟着恒绿。
