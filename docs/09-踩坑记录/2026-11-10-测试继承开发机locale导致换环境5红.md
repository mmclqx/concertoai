# 2026-11-10 测试继承开发机 locale —— 默认环境全绿、换环境 5 红

## 问题描述

- **现象**：给 `.githooks/prepare-commit-msg` 的进度提醒写了 18 条用例，默认环境 **18/18 绿**（跑了三轮都绿）。按 AGENTS 硬要求换环境复跑 `LUMEN_LOCALE=en npm run test`，**2562 passed / 5 failed**，红的全在 `tests/scripts/githooks.test.ts`。
- **报错长这样**：`expected 'concertoai: agent identity NOT declar…' to contain '指令未收尾'` —— 用例要中文提醒，hook 给了英文提醒。
- **环境**：Windows x64 / Node 22 / `cmd /c "set LUMEN_LOCALE=en&& npm run test -- --silent"`
- **危害等级**：🟠 中高——**本机永远复现不了**。这不是产品 bug，但会让「换环境跑全量」这条纪律变成噪音：如果当时的处置是「记一笔 flaky」或加 `retry`，那 5 条就会长期红着，团队很快学会「这条红了不用管」，护栏等于不存在。

## 根因分析

- **直接原因**：测试里每个子进程 env 都写成 `{ ...process.env, ...env }`，把**开发机 shell 的 `LUMEN_LOCALE=en` 继承进了 `git commit` 起的 hook**。而 hook 的提醒语言恰恰由 `LUMEN_LOCALE > LANG` 决定，于是「期望中文」的用例在 en 环境里拿到了英文输出。
- **深层原因**：**AGENTS 里早就写了这条**——「spawn / fork CLI 的用例，env 必须显式指定 `LUMEN_LOCALE`（不依赖开发机 shell），『locale 不受外部影响』是必须写出来的承诺，不是默认行为」。写用例时我知道这条规则存在，但**没把它用在自己身上**：因为被测对象是「一个 sh 脚本 + git」，看起来跟 CLI 的 locale 体系无关——事实上 hook 里正是复刻了 `src/i18n` 的 locale 解析规则（§11.3 的等价性表用例就是为这条漂移准备的），所以它**就是** locale 相关的。
- **同族证据**：这一轮里还有一条同形状的缺口（`docs/13` §11.2）——4 条用例只断言 stderr 文案、没断言提交成功，于是「把 `exit 0` 改成 `exit 1`」这种阻断提交的破坏只红 13/18。两件事的共同点是：**测试有一个没写出来的隐含前提**（一个假设「locale 是我要的」，一个假设「反正提交会成功」），而隐含前提只在特定环境下成立。

## 解决方案

- **给测试钉一个基线 env**，而不是到处补 `LUMEN_LOCALE`：
  ```ts
  const BASE_ENV: NodeJS.ProcessEnv = { ...process.env, LUMEN_LOCALE: '', LANG: '' };
  ```
  所有 `git` 调用从 `BASE_ENV` 出发；要英文的用例**显式覆盖** `{ LUMEN_LOCALE: 'en' }`。
  这样「默认中文、英文显式声明」变成文件级的不变量，新增用例不会再次漏掉。
- **补断言（P3 缺口）**：4 条用例各加 `expect(c.status).toBe(0)`；性能用例加「每次计时提交必须成功」（失败时测到的是「失败耗时」，数字没有意义）。
- **顺手修一处「恰好压线」的阈值**：`blocked 原因超长` 的 `length < 100`，中文行实测正好 100（踩在边界上），改成 `< 60 + 60` 并在注释写明余量。
- **验证**：默认环境 170 文件 / 2567 用例全绿；`LUMEN_LOCALE=en` 同数全绿（修前 2562 passed / 5 failed）；探针 P3 由「13/18 红」变为「18/18 红」（改坏必红这一半补齐）。
- **涉及文件**：`tests/scripts/githooks.test.ts`、`docs/13-hook提交时进度提醒-方案.md`、`docs/12-指令进度记录机制.md`

## 经验教训

- **「我的环境跑绿了」不是证据，是抽样**。这次默认环境连绿三轮，换一个环境立刻 5 红。判据分界线是：**红不红取决于执行环境，而不是取决于代码对不对** ⇒ 这类改动必须换环境跑全量并同时记录两种环境的用例数。
- **「被测对象看起来跟 X 无关」是最容易漏 X 的判断**。hook 是个 sh 脚本，但它内部复刻了 locale 规则 ⇒ 它就是 locale 敏感的。**判断要不要隔离环境，看它读不读那个变量，不看它是什么形态**。
- **假红必须按严重缺陷修**，不许「记一笔 flaky」或加 `retry`：一个「红了不用管」的护栏比没有护栏更坏，因为它会训练人忽略红色。
- **是否需要更新规范**：✅ 已覆盖，不新增条目。AGENTS「进程级全局状态隔离」条（spawn 用例显式指定 `LUMEN_LOCALE`）与「新增判定类护栏必须换环境跑全量」条已经把这条写死；本轮的具体收获（hook 也算 locale 敏感、"看起来无关"是漏判来源）补进 `docs/13` §11.3，并作为该条的实例证据。
