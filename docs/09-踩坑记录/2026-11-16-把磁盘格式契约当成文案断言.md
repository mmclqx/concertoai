# 把「磁盘格式契约」当成「没本地化的文案」

> 日期：2026-11-16
> 触发：v5.4 候选 A（1122 处中文字面量断言的分类盘点）
> 性质：**分类错误**，不是数字错误。差一点就按错误分类动手改代码。
> 同族：[`2026-11-14-交接单写出来了却永远读不到.md`](2026-11-14-交接单写出来了却永远读不到.md)（round-trip 失明）

---

## 一、我当时写下的（错的）

候选 3 收尾时，我在 `CHANGELOG` 与看板上写了这么一句：

> 「全项目扫一遍，中文字面量作断言值还有 1122 处 / 130 个文件（重灾区和……，
> **同功能的 `tests/cli/handoff.test.ts` 28 处也没治**）」

言下之意：这 28 处和候选 3 治的那 26 处是**同一个病**，只是还没来得及治。

## 二、实测之后（对的）

`tests/cli/handoff.test.ts` 那 28 处断言的是：

```ts
expect(section(text, '## ① 做到哪一步')).toContain('无记录');
expect(text).toContain('> 会话: sess-9');
expect(text).toContain('> 写入时间: 2026-11-14T12:00:00.000Z');
expect(section(text, '## ④ 为什么退出')).toContain('正常收尾');
```

它们守的是 **`handoff.md` 这份磁盘文件的格式**，不是「屏幕上该说什么话」。

两条硬证据：

1. **写侧不本地化**：`src/cli/handoff.ts` 里 `t()` 出现 **0 次**（含中文的字符串 22 行）。
2. **读侧按中文键匹配**：`headerValue(text, '项目')`。实测：

   ```
   读侧问「项目」时：
     中文头部 `> 项目: C:\dev\demo`   ⇒ "C:\dev\demo"
     英文头部 `> Project: C:\dev\demo` ⇒ undefined
   ```

## 三、照着错分类动手会怎样

假如按「测试卫生」的旗号把这 28 处改成 `t()`：

1. 为了让它绿，必须把**写侧**也改成 `t()`（否则 `t()` 在 en 下产生英文头部、断言写的是中文键）；
2. 写侧一本地化，`handoff.md` 在 en 环境下写出 `> Project:` / `> Session:`；
3. 读侧 `headerValue` 仍问『项目』『会话』⇒ **永远 undefined**；
4. `classifyHandoffDir()` 于是认为「交接单里没有项目路径」⇒ **真交接单进「可清理」**；
5. 下一步用户敲 `handoff prune --yes`，**证据被删**。

**一个「测试卫生」的理由，换来一个不可逆删除的缺陷。** 这正是 v5.3 N4 那类
round-trip 失明的翻版：**写得完美，读回来判定永远不成立**。

## 四、根因：把「字符串里有中文」当成了「这就是文案」

「含 CJK 的字符串字面量」只能说明它**是文本**，说不清它**是什么文本**。至少五种：

| 类 | 例子 | 该不该改成 `t()` |
|---|---|---|
| (a) UI 文案（模块已走 i18n） | `'可清理 145 个'`（来自 `t().handoff.summary`） | ✅ 该 |
| (b) **磁盘格式契约** | `'## ① 做到哪一步'` / `'> 会话: …'` | ❌ **绝对不许** |
| (c1) UI 文案（模块未走 i18n） | `'✅ 项目 demo 已注册'` | ⚠️ 先让产品走 i18n |
| (c2) fixture / 模型回复 | `'hello\n世界\n'`、`'实现一个 TODO 应用'` | ❌ 不动 |
| (c3) 仓库内开发脚本输出 | `scripts/*.mjs` 的中文提示 | ❌ 不动（非用户界面） |

**判据一句话**：
> 只有当**写侧和读侧都本地化**时，格式字符串才可以本地化；
> 单侧本地化 = 备份/读取链路断在自己手上。

## 五、为什么这次没造成事故

因为候选 3 的那一轮**先做了盘点**，而不是直接「把 1122 处一起改」。
盘点的第一个产出就是「这一坨不是一件事」。**如果当时按数字推平，这条缺陷今天就落地了。**

## 六、这次盘点里，尺子又坏了两次（一并记）

同一个动作（分类）里，我的分类器犯了两个错，都是抽样才发现的：

1. **漏了 `.tsx` 候选**：解析 import 时只找 `.ts` / `index.ts`，于是 `ui/App` 被判「不走 i18n」，
   `tests/ui/app.test.tsx` 的 **50 处**全被划进「fixture」——**错判一整类**。
   修完 (a) 从 552 → 621、(c) 从 549 → 482。
2. **文件名规则过宽**：`/^[a-z][a-z0-9_-]*\.(json|md|log)\b/` 把 UI 文案
   「`tsconfig.json 需要格式化`」判成「磁盘格式」——**误伤正是最危险的那一类**（(b) 变多会让人更保守，但读数失真）。

**教训**：分类器输出的不是结论，是**待核对样本**。文档里每个读数都必须附抽样，否则
下一个人没法验证我判得对不对。

## 七、沉淀成规则（已写进 `docs/14-测试断言分类盘点.md`）

1. 任何「N 处欠账」写进文档前，**先定口径**（同一个仓库，换把尺子读数从 1122 变 1125）。
2. 分类没做之前，**禁止批量改断言**。
3. (b) 类断言就地加注释标明「这是格式契约」，防止下一个人按同样的错误分类再改一次。
4. 要本地化文件格式，必须**写侧 + 读侧 + 历史文件兼容**同时改，属独立设计任务，
   不能塞进「测试卫生」。
