# [2026-08-14] 端到端测试暴露三处自动化未覆盖 bug（发布后收尾）

## 问题描述
- 现象：v4.0.0 发布后专业评审补充 5 个用户视角端到端案例（审查修复闭环 / 工作流发版 / Provider 切换 / 插件安装 / IDE 诊断），实际执行暴露 3 个真实 bug：
  1. `/review --fix` 批量修复中，A 类写盘后 verify 失败被回滚的项，修复报告 reason 仍显示「待批量审批」而非「修复后验证失败，已自动撤销」（语义误导，npm v4.0.0 携带该 bug）；
  2. LSP「🔧 用 ConcertoAI 修复」CodeAction 在配置了 `files.includes: ['src/**']` 的项目中永远缺失——biomeFixEdits 临时副本放系统临时目录，被 biome.json includes 忽略，biome 处理 0 文件；
  3. Windows 下 `execFileAsync('npx.cmd', args)` 抛 EINVAL（Node 无法直接 spawn .cmd）→ LSP 真实诊断静默为空。
- 环境：Windows x64 / Node v22 / 真实 DeepSeek API

## 根因分析
- 直接原因：
  1. autofix.ts 执行循环中 rolledback 分支未写 reason（只处理了 fixed 分支），残留初始值「待批量审批」；
  2. biome 的 `files.includes` 只处理项目内声明的路径，tmpdir 副本不在其中；
  3. `execFile` 不经过 shell，直接 spawn .cmd 在 Windows 抛 EINVAL（与 tools/shell.ts 已解决的 ENOENT 同类，但路径不同）。
- 深层原因：**单元测试全绿（1334 用例）≠ 端到端可用**。三处均为真实环境（真实 biome 子进程 / Windows spawn / 真实模型多问题场景）才暴露，Fake runner / mock 注入完全覆盖不到；发布前未跑用户视角完整路径，且发布后工作区改动未提交未发布（P1 发布卫生问题）。

## 解决方案
- 修复方式：
  1. `src/reviewer/autofix.ts`：rolledback 分支显式 `p.item.reason = t().reviewer.reasonVerifyFailed`；补回归断言（`tests/reviewer/autofix.test.ts`「verify 失败 → 自动回滚」增加 reason 断言，拒绝「待批量审批」残留）；
  2. `src/lsp/diagnostics.ts`：biomeFixEdits 临时副本优先放项目 `src/`（无 src 回退 tmpdir）；补 2 个真实 biome 子进程集成测试（`tests/lsp/diagnostics.test.ts`）；
  3. `src/lsp/diagnostics.ts`：`execFileAsync('npx.cmd')` → `spawn(cmd, { shell: true })`（与 tools/shell.ts 跨平台策略一致）。
- 涉及文件：`src/reviewer/autofix.ts` / `src/lsp/diagnostics.ts` / `tests/reviewer/autofix.test.ts` / `tests/lsp/diagnostics.test.ts`

## 经验教训
- 如何避免同类问题：
  1. **发布前必须跑用户视角端到端路径**（不只单元测试）；「单元测试全绿 ≠ 端到端可用」；
  2. **Windows 平台验证不可替代**：真实子进程（biome/tsc/npx）的 .cmd spawn 问题测试注入 Fake runner 覆盖不到；
  3. **发布后工作区必须立即提交/发布**：修复滞留在工作区会让 npm 包携带 bug（AGENTS.md 自查清单第 7 条强化为「发布 commit 后立即 git status 必须为空」）。
- 是否需要更新规范：✅
- 规范更新位置：`AGENTS.md`（自查清单新增第 13 条：发布 commit 后立即 `git status` 必须为空）
