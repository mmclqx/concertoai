# [2026-08-11] team 超时后子进程树残留（Windows 需手动 taskkill）

## 问题描述
- 现象：手工测试 `concertoai team "<任务>"` 中 verify 超时后，npm/node 子进程树**残留**在系统中，需手动打开任务管理器 `taskkill /T /F` 清理进程树。
- 环境：Windows x64（npm 会 spawn 多层子进程：npm → node → vitest workers）

## 根因分析
- 直接原因：`src/agents/qa.ts` `ChildProcessQaRunner.run` 超时后 `spawn('taskkill', ['/pid', pid, '/T', '/F'])` **不等待 taskkill 完成**就返回（`spawn` 异步，未监听 close）；POSIX 分支直接 `child.kill('SIGKILL')` 只杀顶层进程（未用进程组 `-pid`），子进程树整体残留。
- 深层原因：① 超时处理的「杀进程」与「收尾返回」未同步——taskkill 是异步的，必须等它退出才意味着进程树已清理；② POSIX 下 `shell: true` 的子进程同进程组，正确做法是 `process.kill(-pid, 'SIGKILL')` 杀整组而非只杀顶层；③ 缺少 kill 后 close 宽限兜底，极端情况（taskkill 完成但 close 未触发）会导致 run 永不返回或进程残留。

## 解决方案
- 修复方式：抽出 `killTree(child)`（导出供单测）——Windows：`taskkill /pid <pid> /T /F` 并**等待 killer close 后 resolve**；POSIX：进程组 `process.kill(-pid, 'SIGKILL')`（失败回退 `child.kill`）。`run` 超时后调用 `killTree().then(...)`，kill 完成后再起 1500ms 宽限定时器兜底 settle（避免 close 未触发时 run 永不返回）；用 `settled` 标志防重复 resolve。
- 涉及文件：`src/agents/qa.ts`（killTree + run 超时流程）、`src/agents/index.ts`（导出 killTree）、`tests/agents/qa.test.ts`（3 用例：Windows 等待 killer close / POSIX 进程组 SIGKILL / pid 缺失直接 resolve）

## 经验教训
- 如何避免同类问题：**异步杀进程必须等待完成**（监听 killer close），不能 fire-and-forget；`shell: true` 的子进程树清理 POSIX 用进程组信号、Windows 用 taskkill /T；超时路径要加宽限兜底防止 Promise 永不 settle；killTree 逻辑可复用（`src/tools/shell.ts` 的 killTree 有同样问题，可对齐）。
