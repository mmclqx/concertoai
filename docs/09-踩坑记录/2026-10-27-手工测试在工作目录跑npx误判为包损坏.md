# 手工测试在工作目录跑 npx，误判「包损坏」（2026-10-27）

## 现象

v5.0 T1 验收「npx 零安装实测」时，在**项目根目录** `F:\developer\2026\concertoai` 执行：

```
npx --yes @concertoai/cli@4.1.1 --version
```

输出：

```
'concertoai' 不是内部或外部命令，也不是可运行的程序
或批处理文件。
```

`npm pack` 检查包内容却完全正常（120 文件，`dist/cli/index.js` + `package.json` 都在，`bin` 声明正确）。一度判定为「v4.1.1 真实发布缺陷：Windows 用户无法 npx 零安装」。

## 根因

**不是包的问题，是测试目录选错**：

- 当前目录本身就是 `@concertoai/cli` 的源码项目（`package.json` 的 `name` 与要 npx 的包**同名**）；
- `npm exec` / `npx` 的解析顺序是**先看本地 `node_modules`**，再看 registry；
- 本地 `node_modules` 里没有 `@concertoai/cli` 这个包（本项目自己不依赖自己），但 npm 认为「你要的包名==当前项目名」→ 直接在本地 bin 里找 `concertoai` 命令 → 不存在 → 报「不是内部或外部命令」；
- 全程没有安装动作，所以 `_npx` 缓存里查不到任何痕迹（这正是当时最迷惑的地方）。

## 修复 / 正确做法

在**隔离的空目录**重跑，立即通过：

```js
const dir = fs.mkdtempSync(path.join(os.tmpdir(), 'npxcheck-'));  // 空目录
spawn('npx', ['--yes', '@concertoai/cli@4.1.1', '--version'], { cwd: dir, shell: true });
// → exit 0，stdout: 4.1.1
```

## 教训（已并入 AGENTS 第 16 条精神）

1. **手工测试必须在独立空目录**：尤其验证「别人拿到这个包装不装得上」时，**绝不能在包自己的项目根跑**——同名包会被本地优先解析。
2. **报错先怀疑环境，再怀疑产物**：`npm pack` 已证明包完整 → 应第一时间怀疑执行环境而非发布物。本次差点据此写出一条不存在的「P0 发布缺陷」。
3. **`_npx` 缓存无痕迹 = 没发生安装**：可作为「npx 是否真的去下载了」的快速判据。
4. **隔离目录 + 隔离 HOME 双保险**：缺 Key 引导测试还需把 `HOME`/`USERPROFILE` 指向临时目录，否则会读到开发机真实的 `~/.concertoai/accounts`，结果随机器变化（见 `tests/e2e/missing-key.test.ts`）。
