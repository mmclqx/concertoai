# 2026-11-07 归档校验脚本：探针自己先出两次错（假红 + 空转），靠反向自证抓出来

## 问题描述

- 背景：`CHANGELOG.md` 的 v4.1.1 条目归档（把散落在 `[5.0.0]` 小节内的 v4.1.1 内容移入新建的 `## [4.1.1]` 小节）需要自证正确。写了一个临时校验脚本 `.tmp-check-changelog.mjs`，断言四组：**顺序**（`4.1.1` 在 `5.0.0` 与 `4.1.0` 之间）/ **残留**（旧自注清零）/ **归类**（v4.1.1 特征串已移出 `5.0.0`）/ **数字**（基线用例数为 1404 而非 1402）。
- 结果：前三组一次通过，**数字组连错两次**，而且两次都是**探针自己的错**，不是被校验内容的错。

### 第一次：粗粒度断言把正确内容判红（假红）

```js
// 写法：同时包含 "1402" 和 "基线校准" 就算违规
const badBase = lines.filter((s) => s.includes('1402') && s.includes('基线校准'));
// 实测：FAIL(1 行)
```

被判红的那一行其实是**正确的**：`- **基线校准**：117 文件 / **1404** 用例全绿…——热修阶段为 1402，P0 追加 2 后为 1404（原行写 1402 是中间值，…）`。它既有「1404」（正确值）又有「1402」（说明里的历史值），而我的断言只看「两个词是否同时出现」，于是把「带说明的正确内容」判成「未修正」。

这与 2026-11-07 同日冻结护栏事故的**同一个毛病**：判据面过宽 ⇒ 假红。**假红的代价是让护栏当天失信**。

### 第二次：改坏逻辑没改到，探针空转

修了假红后，为证「断言有牙」加反向自证：内存里把 1404 改回 1402，断言必须翻红。结果：

```
「基线校准」数字位为 1404 -> PASS
改坏后 badBase 条数 -> 0  FAIL(探针空转)
```

原因是**改坏用的正则也匹配不到 Markdown 粗体**：原文是 `/ **1404**`，我的替换正则写 `\/\s*1404`，中间的 `**` 让替换根本没发生——所以「改坏后」其实就是原文，断言自然不翻红。**探针空转 = 反向自证无效 = 正向 PASS 毫无证明力。**

## 根因分析

- 两次的共同根因：**断言/改坏逻辑写的时候只想着「意思对」，没验证「在这份真实文本上跑得通」**。Markdown 粗体 `**1404**`、中文全角冒号、行内反引号这些格式字符，都是正则天然的地雷，而「我脑子里的字符串」和「文件里的字符串」不是同一个。
- 更深一层：第一次错（假红）如果只有正向断言，我会**看到 FAIL 就去改内容**——把正确的内容改坏。这正是「假红比假绿更早杀死护栏」的具体机制：**假红会把人引向修改被守护的对象**。第二次错（空转）如果只有正向断言，我会**看到 PASS 就宣布完成**，而那条 PASS 什么也没证明。
- 关键的救命点：**反向自证与正向断言同时 FAIL 时，指向的是「探针坏」，而不是「内容坏」**。两个 FAIL 同时出现本身就是诊断信息；只有正向 FAIL 时无法区分这两种情况。

## 解决方案

- 修法（脚本内，已落地并跑通）：

```js
// 1) 锚定具体形状，只抓数字位；允许 Markdown 粗体
const baseRe = /基线校准[^\n]*?\/\s*\*{0,2}(\d+)\*{0,2}\s*用例/;
// 2) 改坏时用同一个宽松形状，确保真的改到
const mutated = lines.map((s) => s.replace(/(基线校准[^\n]*?\/\s*)\*{0,2}1404\*{0,2}/, '$1**1402**')).join('\n');
// 3) 先断言「改坏后仍能匹配到行」（探针通电），再断言「badBase 翻红」（探针有牙）
```

- 终态实测（全 PASS）：

```
「基线校准」数字位仍为 1402 -> PASS
「基线校准」数字位为 1404 -> PASS
改坏后仍能匹配到「基线校准…/ N 用例」的行数 -> 13 PASS(探针通电)
改坏后 badBase 条数 -> 1 PASS(探针有牙)
```

- 临时脚本用完即删（不在仓库留脚本；结论已写入 `CHANGELOG.md` / `TASKS.md` / 执行日志）。
- 涉及文件：`CHANGELOG.md`、`docs/execution-log-20261107-231231.md`。

## 经验教训

- **「探针通电」必须是一句独立断言，不能靠推理**：本次修法里 `mBase.length > 0`（改坏后仍能匹配到行）这一句是新增的关键——它把「改坏动作真的发生了」变成可观测的，而不是假设的。AGENTS 已要求「注入/扰动类验证必须先自证探针通电」，本次是**校验脚本类**验证的同构案例。
- **反向自证的价值不只是「证明有牙」，还包括「诊断探针自身」**：正向 FAIL + 反向 FAIL ⇒ 探针坏；正向 PASS + 反向 FAIL ⇒ 空转；正向 FAIL + 反向 PASS ⇒ 内容真的不对。四种组合各有含义，只写正向就只剩一种信息。
- **判据要锚定「结构形状」而不是「关键词共现」**：`includes(A) && includes(B)` 这种写法在「同一行既有正确值又有历史值说明」时必然假红。改成 `正则捕获数字位 + 精确比对值` 才稳。
- **在 Markdown / 富文本上写正则，先打印一行原文再写**：肉眼确认 `**`、全角标点、反引号的实际位置，比事后调正则快得多。
- 是否需要更新规范：**建议并入已有的「度量/算法类必须有否定面 + 变异自证」条款**，补一句「反向自证必须先断言『改坏动作生效』，否则空转与有牙在输出上无法区分」。本文档先记录，等下次修订 `AGENTS.md` 时一并追加（不单独开规范条目，避免条款继续膨胀）。
