# [2026-08-11] 新增 E2E 测试未过 lint 就提交（unused import / 变量 + import 排序 + 格式）

## 问题描述
- 现象：v3.1-M6 新增的 3 个 E2E 测试（`tests/e2e/team-cli.test.ts` / `self-heal.test.ts` / `project-isolation.test.ts`）在 `npm run verify` 时 lint 段报 **6 个 FIXABLE 错误**：`project-isolation.test.ts` 未使用的 `writeFileSync` import、`team-cli.test.ts` 未使用的 `model` 变量、3 处 import 排序（organizeImports）、2 处格式（mcpServers 多行、makeSpan 参数换行）；`tests/observable/trace.test.ts` 也有 1 处格式问题。verify 红。
- 环境：Windows x64

## 根因分析
- 直接原因：新增测试文件是「写完即入库」，没有在本地先跑 `npm run lint`（或 `lint:fix`）再提交；Biome 的 unsafe 修复（unused import / unused 变量）默认被 `--write` 跳过，`lint:fix` 只自动修了 4 处，剩余 2 处需手动删。
- 深层原因：工作流是「写完测试 → 直接 git add → 等到 verify 才暴露」，lint 检查被推迟到整段收尾；且对 Biome「unsafe fix 需手动确认」的机制不熟悉，误以为 `lint:fix` 会全修。

## 解决方案
- 修复方式：
  1. `npm run lint:fix` 自动修 4 处（import 排序 + 格式）；
  2. 手动删 `writeFileSync`（`project-isolation.test.ts` L11）与 `const model = ...`（`team-cli.test.ts` L20）两处 unused；
  3. 重跑 `npm run verify` 确认 build/lint/typecheck/test 四段全绿。
- 涉及文件：`tests/e2e/team-cli.test.ts`、`tests/e2e/self-heal.test.ts`、`tests/e2e/project-isolation.test.ts`、`tests/observable/trace.test.ts`

## 经验教训
- 如何避免同类问题：新增/修改测试文件后、`git add` 前先跑 `npm run lint:fix`（或至少 `npx biome check src tests`）；Biome 对 unused import / unused 变量默认标为 unsafe fix，`--write` 不自动应用，需手动删除或加 `--unsafe`（本项目不用 `--unsafe`，手动删更安全）。自检：`git diff --stat` 出现新测试文件时，先 lint 再提交。
- 是否需要更新规范：✅
- 规范更新位置：`AGENTS.md`（提交前自查可加一条：新增测试文件先跑 `npm run lint:fix` 且留意 unsafe fix 手动确认）
