# [2026-08-11] VS Code 频繁崩溃 — 6 个 AI 扩展并行加载导致内存溢出

## 问题描述
- 现象：VS Code 在使用过程中突然闪退退出，无任何提示，随后自动重启。最近一次发生在本日凌晨 02:20，当天已有 2 个崩溃转储（34MB + 41MB）。
- 环境：Windows 11 x64，VS Code（Commit df53daabb1），ConcertoAI 项目开发中。

## 根因分析

### 直接原因
VS Code 渲染进程（Electron renderer process）在持续运行约 2 小时 23 分钟后崩溃，扩展主机被迫终止。

关键日志证据（`%APPDATA%\Code\logs\20260810T235702\window1\exthost\exthost.log`）：
```
2026-08-11 02:20:43.966 [info] Extension host terminating: renderer closed the MessagePort
2026-08-11 02:20:44.007 [error] An error occurred when disposing the subscriptions for extension 'ms-dotnettools.csdevkit':
2026-08-11 02:20:44.008 [error] Error: Connection is disposed.
```

### 深层原因：扩展过多导致资源耗尽

系统中共安装了 **6 个 AI 编码助手扩展**，启动时全部并行加载：

| 扩展 ID | 名称 | 版本 |
|----------|------|------|
| `anthropic.claude-code` | Claude Code | 2.1.226 |
| `continue.continue` | Continue | 2.0.0 |
| `danielsanmedium.dscodegpt` | CodeGPT | 3.24.43 |
| `openai.chatgpt` | ChatGPT | 26.803.41515 |
| `marscode.marscode-extension` | MarsCode | 1.7.2 |
| `alibaba-cloud.tongyi-lingma` | 通义灵码 | 2.6.7 |

加上 C# DevKit（`ms-dotnettools.csdevkit`）及其大量 ServiceHub 子进程（28+ 个 .svclog），崩溃后重启的 VS Code 实例中 `Code.exe` 进程数高达 **85 个**，按 WorkingSet 估算总内存占用约 **20GB+**（单进程最高 888MB，多个 600MB+ 进程）。

### 调查过程（完整步骤）

#### 步骤 1：确认操作系统和 VS Code 日志位置
```bash
node -e "console.log(process.platform)"     # → win32
dir "%APPDATA%\Code\logs" /b /o-d            # 列出所有会话日志目录（按时间倒序）
```
日志目录按 `YYYYMMDDTHHMMSS` 命名。找到两个关键会话：
- `20260810T235702`：崩溃发生的会话（23:57 启动 → 02:20 崩溃）
- `20260811T022059`：崩溃后自动重启的会话

#### 步骤 2：查找崩溃转储（Crashpad）
```bash
dir "%APPDATA%\Code\Crashpad\reports" /o-d   # 崩溃转储按时间倒序
```
结果：最近两个崩溃转储生成于 `2026/08/11 02:20`（与日志断开时间吻合）：
```
5c7b2f6b-...dmp  34,542,080  ← 2026/08/11 02:20
07bbad04-...dmp  41,150,304  ← 2026/08/11 02:20
```
此前还有 10 个历史崩溃转储（最早 2024/12/17），说明这是**长期反复发生的问题**。

#### 步骤 3：分析崩溃会话的 main.log
```bash
type "%APPDATA%\Code\logs\20260810T235702\main.log"
```
主进程日志完整无中断，末端停留在 `01:57:34` 的例行更新检查，没有直接的 crash/error 记录——说明**崩溃发生在渲染进程（Electron window process）**而非主进程，且是硬崩溃（无 JS 异常捕获机会）。

#### 步骤 4：分析崩溃会话的 agenthost.log
```bash
type "%APPDATA%\Code\logs\20260810T235702\agenthost.log"
```
发现崩溃时刻（`02:20:43`）Agent Host 中所有 ProtocolServer 客户端同时断开：
```
2026-08-11 02:20:43.960 [info] [ProtocolServer] Client disconnected: ade8a8e8-...
2026-08-11 02:20:43.961 [info] [ProtocolServer] Client disconnected: f50befdf-...
2026-08-11 02:20:43.965 [info] [ProtocolServer] Client disconnected: 95745b69-...
```
Agenthost 日志在此之前持续为各 AI 扩展的 Copilot/Claude 客户端注册和 session list 请求——正常运作到崩溃瞬间。同时有 `ENOPRO: 未找到资源` 错误（userdata 文件系统提供程序），但属于启动阶段已知问题，非崩溃原因。

#### 步骤 5：分析崩溃会话的 renderer.log
```bash
powershell -Command "Get-Content '%APPDATA%\Code\logs\20260810T235702\window1\renderer.log' -Tail 50"
```
渲染日志揭示了启动阶段的**累积压力**：
- `23:57:14` — Extension host 无响应（unresponsive）
- `23:57:18` — 开始性能采样
- `23:57:23` — 再次无响应
- `23:57:27` — 再次性能采样
- `23:57:31` — Continue 扩展配置解析失败（`models.0: Invalid input`）× 多次
- `23:57:31` — CodeGPT 扩展 EADDRINUSE 端口 54115 冲突
- `23:57:31` — 出现乱码 "出现未知错误。有关详细信息，请参阅日志。"

日志末端停在启动阶段（23:57），说明渲染进程日志在崩溃前没有任何记录写入——符合**硬崩溃**（native crash）特征，即在渲染进程内存耗尽/GPU 崩溃时无机会刷新日志缓冲区。

#### 步骤 6：分析崩溃会话的 exthost.log
```bash
powershell -Command "Get-Content '%APPDATA%\Code\logs\20260810T235702\window1\exthost\exthost.log' | Select-Object -Last 50"
powershell -Command "... | Select-String -Pattern 'error|crash|terminate|uncaught|exception' | Select-Object -Last 20"
```
扩展主机日志明确记录了崩溃时的级联效应：
```
02:20:43.966 [info] Extension host terminating: renderer closed the MessagePort
02:20:44.007 [error] An error occurred when disposing the subscriptions for extension 'ms-dotnettools.csdevkit':
02:20:44.008 [error] Error: Connection is disposed.
02:20:44.079 [error] Canceled: Canceled
```
渲染进程关闭了与扩展主机之间的 MessagePort，扩展主机被动终止，C# DevKit 的清理逻辑因连接已断开而抛出异常。这不是扩展的错误，而是渲染进程先崩溃导致的连锁反应。

#### 步骤 7：确认扩展安装情况和进程数
```bash
dir "C:\Users\mmc\.vscode\extensions" /b     # 列出所有已安装扩展
tasklist /fi "imagename eq Code.exe"           # 列出所有 Code.exe 进程及内存
```
结果：
- **扩展列表**确认了 6 个 AI 助手同时存在
- **进程列表**显示崩溃后重启的 VS Code 仍有 **85 个 Code.exe 进程**，内存分布为：
  - 14 个进程 > 600MB（最高 888MB）
  - 约 20 个进程 300-500MB
  - 约 46 个进程 100-170MB
  - 估算总内存 ≈ 23GB

#### 步骤 8：排除其他可能原因
- **Windows Event Log**：`Get-WinEvent -LogName Application` 未发现 Code/electron/crash 相关事件 → 非系统级杀进程
- **GPU 驱动崩溃**：renderer.log 在崩溃前无 GPU 相关错误 → 可能但不作为首要原因
- **扩展版本问题**：Continue 配置错误（models.0: Invalid input）和 CodeGPT 端口冲突（EADDRINUSE）是启动时已知问题但非崩溃直接原因

### 综合结论
6 个 AI 编码助手扩展同时加载 → 每个扩展启动独立的 Agent Host 客户端（CopilotClient / Claude SDK 等）+ 各自的子进程 → C# DevKit 额外启动 28+ ServiceHub 进程 → 进程总数爆炸（85+）→ 物理内存耗尽（~23GB）→ 渲染进程 OS 级 OOM / 资源不足崩溃。

## 解决方案

### 立即措施（推荐执行）
1. **禁用冗余 AI 扩展**（保留 1-2 个真正使用的）：
   ```bash
   code --disable-extension alibaba-cloud.tongyi-lingma
   code --disable-extension danielsanmedium.dscodegpt
   code --disable-extension openai.chatgpt
   code --disable-extension marscode.marscode-extension
   ```
2. 如果不写 C# 时，临时禁用 C# DevKit：
   ```bash
   code --disable-extension ms-dotnettools.csdevkit
   ```

### 长期措施
1. **清理历史崩溃转储**（已积压 12 个 dump 共 ~400MB）：
   ```bash
   del "%APPDATA%\Code\Crashpad\reports\*.dmp"
   ```
2. **清理 VS Code 缓存**：
   ```bash
   rmdir /s /q "%APPDATA%\Code\Cache"
   rmdir /s /q "%APPDATA%\Code\CachedData"
   ```
3. **考虑升级 VS Code**（当前版本 Commit df53daabb1，可检查是否有更新）
4. **在工作区 `.vscode/extensions.json` 中设置 `unwantedRecommendations`**，避免多人协作时互相推荐卸载的扩展。

## 经验教训
- **如何避免同类问题**：
  1. VS Code 扩展不是堆得越多越好——每个 AI 编码助手扩展都会启动独立的后台进程/Agent Host 客户端，N 个扩展 = N 倍进程开销 + N 倍内存占用。
  2. 选择 1-2 个 AI 助手即可覆盖需求，冗余扩展应主动禁用或卸载。
  3. 环境问题（VS Code 崩溃）也会影响开发效率——应在踩坑记录中沉淀排查方法，便于快速定位。
  4. 排查 VS Code 崩溃的标准路径：`%APPDATA%\Code\logs\` → 找崩溃时间对应的会话 → main.log（排除主进程）→ renderer.log（渲染进程是否有 OOM/GPU 错误）→ exthost.log（扩展是否有未捕获异常）→ `Crashpad\reports`（确认崩溃次数和频率）。
- **是否需要更新规范**：❌（属于个人开发环境管理范畴，不影响项目代码规范）
- **规范更新位置**：无
