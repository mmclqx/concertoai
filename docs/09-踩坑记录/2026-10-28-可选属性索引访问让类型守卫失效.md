# `?? 兜底` 兜了个寂寞：可选属性的索引访问把 `undefined` 带了进来

> 日期：2026-10-28　版本：v5.0 T17（`concertoai commit`）　严重度：中（`npm run typecheck` 直接红，全量 verify 卡在第三步，整轮任务熔断）

## 现象

```
tests/cli/commit.test.ts:250:16 - error TS2722:
Cannot invoke an object which is possibly undefined
  return rawAsk(question);
```

`rawAsk` 明明是这样来的：

```ts
const rawAsk = options.ask ?? answers('y');   // 左边空就兜右边，怎么会是 undefined？
```

`answers()` 返回一个**一定能调用**的函数，`??` 的语义是「左边是 null/undefined 才取右边」——
既然右侧一定存在，`rawAsk` 在直觉上不可能 undefined。但 tsc 说的是对的。

## 根因

问题出在 `answers()` 的**返回类型**，而不是实现：

```ts
function answers(...values: Array<string | undefined>): CommitCommandOptions['ask'] {
  //                                                ^^^^^^^^^^^^^^^^^^^^^^^^^^^^
  //                                                这个属性在接口里是「可选」的：
  //                                                ask?: (question: string) => Promise<string | undefined>
}
```

**索引访问 `T['k']` 会原样带上属性本身的可选性**，所以 `CommitCommandOptions['ask']`
的真实类型是 `((q: string) => Promise<string | undefined>) | undefined`。

于是 `??` 根本没事可做：

```ts
options.ask ?? answers('y')
//  (Fn | undefined) ?? (Fn | undefined)  →  (Fn | undefined)
```

两边都可能 undefined，兜底等于没兜。类型系统没有说谎——**是我把「可选属性」当成了「函数类型」在用**。

这也解释了为什么它不是运行时 bug：实际值永远来自 `answers('y')`，跑起来毫无问题；
**只有类型层面在喊**，而这一声喊恰好把 verify 卡死在 typecheck 那一步（T17 整轮因此熔断）。

## 修复（不打 `as any`、不加 `!`）

在**类型源头**剥掉可选性，让「这个函数一定可调用」成为类型事实，而不是调用点的运行时信仰：

```ts
/** 审批询问函数的非空签名（`CommitCommandOptions['ask']` 是可选属性，索引访问自带 `| undefined`）。 */
type AskFn = NonNullable<CommitCommandOptions['ask']>;

function answers(...values: Array<string | undefined>): AskFn { … }

const rawAsk = options.ask ?? answers('y');   // 现在右侧非空 → 结果是 AskFn
```

顺带把 `harness(options: { ask?: AskFn })` 一起改齐——**同一个可选属性被消费的每个位置都要改**，
只改返回值会留下「传参处仍可能 undefined」的第二条漏网路径。

## 为什么不用别的写法

| 写法 | 为什么不用 |
|---|---|
| `rawAsk(question)!` | `!` 是**对编译器发誓**，不是修类型；真出问题时它静默放行（这里虽不会，但模式会被抄到会出问题的地方） |
| `rawAsk?.(question) ?? undefined` | 把「不可能发生」写成「可能发生」，读代码的人会以为这里常有 undefined；且返回值类型被悄悄放宽 |
| `as any` / `as AskFn` | 把类型守卫整个删掉，等于承认不打算让编译器帮忙 |
| 在定义处写 `(...) : NonNullable<...>` | 能用但不表达意图；`AskFn` 这个名字能让下一个人一眼看出「这是去掉可选性的函数类型」 |

## 一句话结论

> **可选属性的索引访问自带 `| undefined`**——它不是一个「函数类型」，
> 而是「可能没有的函数」。「兜底」只有在右侧确实非空时才成立；
> 要断言「右侧一定非空」，请在**类型源头**用 `NonNullable` 表达，别在调用点补助手。

## 自检清单（下次写注入点时的 30 秒核对）

1. 我用的这个类型是 `interface['field']` 吗？→ 先看 `field` 有没有 `?`。
2. 有 `?` → 后续所有「兜底 / 传参 / 调用」都按 `| undefined` 对待，或在源头 `NonNullable`。
3. 出现 `!` 或 `as` 想「先过编译」→ 停手，先判断是不是类型源头就错了。
