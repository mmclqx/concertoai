# 低风险不扫影响面，UI 却说「你的项目太大」

> 日期：2026-10-28　版本：v5.0 T11（配置与降级收尾，修 T8/T9 遗留缺陷）　严重度：中（对用户说假话）

## 现象

T11 写对照组测试时，截了一张真实的审批帧：

```
│ ✅ 低风险审批 · 编辑文件 b.ts                     │
│ 操作意图：新建文件                                │
│ ✅ 未检测到已知风险模式（已检查 15 类规则）        │
│ 影响面：影响面未分析（项目过大，文件数超过 2000）  │   ← 假话
│ @@ +1,1 @@                                        │
│ +unlink(targetPath);                              │
```

这个临时测试项目里**只有 1 个文件**。而 UI 告诉用户「项目过大，文件数超过 2000」。

## 根因

`analyzeApproval` 的影响面策略是「只在中高风险时才扫」（省 90% IO，合理）。
低风险时它用 `emptyImpact()` 兜底，而 `emptyImpact` 的默认参数是：

```ts
export function emptyImpact(status: ImpactSummary['status'] = 'skipped'): ImpactSummary
```

`skipped` 在 UI 的语义是「项目较大，文件数超限」。于是**「我决定不扫」被渲染成「你的项目太大」**。

`ImpactSummary.status` 原本只有四态：`ok` / `timeout` / `skipped` / `error` ——
其中 `skipped` 被迫同时承担两种完全不同的含义：
1. 文件数超限（客观限制）；
2. 低风险不需要扫（主观省略）。

## 修复

新增第五态 `not-needed`，并把 `emptyImpact()` 缺省值改成它：

```ts
status: 'ok' | 'timeout' | 'skipped' | 'not-needed' | 'error';
export function emptyImpact(status = 'not-needed'): ImpactSummary
```

文案各自独立：

| status | 中文文案 |
|---|---|
| `ok`（有引用） | 该文件被 N 个文件引用（…） |
| `ok`（零引用） | 未发现其他文件引用该文件（已扫描 M 个文件） |
| `timeout` | 影响面未分析（超时 300ms） |
| `skipped` | 影响面未分析（项目过大，文件数超过 2000） |
| `not-needed` | **低风险改动，未做影响面扫描（仅中高风险才扫）** |
| `error` | 影响面未分析（读取失败） |

## 为什么不是「低风险就显示无影响」

因为「没扫」和「扫了没找到」是两种事实——这正是 T9 措辞红线②的原话。
`not-needed` 的文案刻意说明了**原因**（仅中高风险才扫），这样用户看到时
既不会误以为项目太大、也不会误以为没人引用。

## 回归防护

- `tests/ui/approval-degrade.test.tsx`：rich 对照组断言渲染出风险区块（不再撞 `skipped` 假话）；
- `approval-insight.ts` 的 `emptyImpact()` 与 `scanImpact` 的 `skipped` 分支各有单测
  （`tests/core/approval-insight.test.ts` 的降级矩阵第 ⑧ 行仍断言真超限时为 `skipped`）；
- 五态在 `ImpactSummary.status` 的 JSDoc 里列成表格，改文案时看得到全貌。

## 一句话结论

> 一个枚举值**同时承载两种事实**时，文案必然在某一侧说谎。
> 判断标准：如果两种情况的「用户下一步动作」不同，就必须是两个枚举值。
