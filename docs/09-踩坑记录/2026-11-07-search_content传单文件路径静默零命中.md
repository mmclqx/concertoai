# 2026-11-07 `search_content` 传单个文件路径时静默返回 0 命中

## 问题描述

- 现象：核对「`CHANGELOG.md` 里有没有 v4.1.1 相关内容」时，`search_content(pattern='4.1.1', path='CHANGELOG.md')` 返回 `hits: []`、`skippedBinary: 0`；同一文件用 Node 直读（`readFileSync` + `split` 计数）得 **15 处**。
- 危害等级：**高**。若采信工具结果，会得出「CHANGELOG 里没有 v4.1.1 相关内容 ⇒ 看板那条待办描述过期、无需归档」——**与事实完全相反**，而且这个错误**不报错**，只安静地给出一个「干净」的有利结论。这正好命中 AGENTS 已写明的两类错误之一（「这两类错误都不报错，只安静地给出有利结论」）。
- 反差点：同一次会话里 `search_content('.gitignore', 'tests')` 有 5 命中，所以「工具能用」这个印象是真的——只是不适用于传文件。

## 根因分析

- 直接原因：`search_content` 的 `path` 参数语义是**目录**。传单个文件路径时不匹配、不报错，直接返回空结果。
- 怎么定性出来的（不靠猜）：对照矩阵实测五格——

| `path` 入参 | 检索词 | 结果 | 这格排除了什么 |
|---|---|---|---|
| `.` | `4.1.1` | ✅ 命中（含 `CHANGELOG.md` 12 处） | 排除「搜索功能本身坏了」 |
| `docs` | `ARCHITECTURE` | ✅ 命中大量 | 排除「`docs/` 下 .md 不可搜」 |
| `CHANGELOG.md` | `4.1.1` | ❌ 0 | — |
| `CHANGELOG.md` | `v5.0` | ❌ 0 | 排除「只是这个词不存在」 |
| `docs/FEATURE_FREEZE.md` | `冻结` | ❌ 0 | 第二个独立样本（文件名就叫 FEATURE_FREEZE、正文满篇「冻结」）⇒ 排除「CHANGELOG 特殊」 |

- 一个被自己推翻的初判：一开始以为是「大文件失明」（`CHANGELOG.md` 91979 字符）。但 `path='.'` 时该文件能被命中，所以**体积不是判据**。若不做对照实验而按体积猜，就会写出一个错的根因，并据此制定「大文件特殊处理」这种无用对策。

## 解决方案

- 处置：**单文件检索一律用 Node 直读**（`readFileSync(p,'utf8').split('\n')` + `includes` / 正则），需要行号就带索引打印；**目录级检索继续用 `search_content`**（它工作正常）。
- 不做什么：不改工具、不写进代码护栏（这是运行环境工具的行为，不是本项目代码）。仅把判据写进本文档，下次遇到同类场景先按矩阵验一次。
- 涉及文件：`CHANGELOG.md`（本轮实际改动对象）、`docs/execution-log-20261107-231231.md`（§四 完整取证记录）。

## 经验教训

- **「0 命中」在验过正例前没有证据力**（AGENTS 已有此条，本次是它的第二次实证）。本次新增的具体形态是：**正例必须与被测样本同域**——要证明「单文件能搜」，正例就得是「同一个单文件、搜一个必然存在的词」，而不是「另一个目录、搜另一个词」。我最初的正例是 `path='.'` 搜 `4.1.1`，它证明了「搜索能工作」，但**证明不了「单文件入参能工作」**。
- **否定面同样要成对**：`CHANGELOG.md` 搜 `4.1.1` 得 0 时，必须再搜一个**必然存在**的词（`v5.0`）也得 0 —— 两格都 0 才说明是「入参方式失效」，而不是「这个词恰好不在」。单看一格，两种解释都成立。
- **工具给的「干净结论」成本最高**：它省掉的正是核对动作，而核对动作是这个结论唯一的支撑。凡「搜不到 ⇒ 判定干净/过期/无需处理」的结论，先问一句「我这个搜法，如果目标真的存在，它会命中吗？」
- 是否需要更新规范：**不需要新增条目**。AGENTS「检索类」条款已覆盖（本次是它生效的案例），但可在下次修订时把「正例必须与被测样本同域 + 否定面要换词复搜」这两条操作细节补进该条，作为具体做法示例。
