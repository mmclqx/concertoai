# [2026-08-10] 审核时按 Esc / Ctrl+C 误退出应用（审批/计划审批阶段）

## 问题描述
- 现象：chat 内工具调用弹审批框（编辑/命令）、`/plan` 计划审批、或模型流式生成过程中，用户按 **Esc**（或 Ctrl+C）会直接退出整个应用——「不小心又出去了，审核时很容易就出去了」。审批框提示「批准 (y) / 拒绝 (n)」并未告知 Esc 的后果，误按即丢会话。
- 环境：Windows x64（Ink TUI）

## 根因分析
- 直接原因：`src/ui/App.tsx` 的 `useInput` 中 `if (key.escape) { exit(); }` 是**无条件**的——它在审批分支之后、ctrl+c 分支之后兜底匹配，任何阶段按 Esc 都调用 `useApp().exit()`：
  - `phase === 'approval'`：Esc 直接退出应用（本应拒绝该操作）；
  - `phase === 'plan-approval'`：Esc 直接退出应用（本应拒绝计划）；
  - `phase === 'streaming'`：Esc 直接退出应用（本应与 Ctrl+C 一致中断生成）。
- 深层原因：Esc 的「退出」语义只应在 idle 态成立（输入框 placeholder 也提示「Esc 退出」），但实现没有按 phase 区分；Ctrl+C 分支虽有 streaming 判断，审批阶段却落在 `else { exit(); }`，同样误退出。

## 解决方案
- 修复方式（`src/ui/App.tsx` useInput 重排分支）：
  1. `phase === 'plan-approval'`：Esc / Ctrl+C = **拒绝计划**（`setPlan(null) + setPhase('idle') + setError(t().plan.rejected)`），不退出；
  2. `phase === 'approval'`：Esc / Ctrl+C = **拒绝该操作**（`approvalResolver(false)` fail-closed），不退出；
  3. streaming 态 Esc = 与 Ctrl+C 一致中断当前生成（`abortRef.current?.abort()`），不退出；
  4. 仅 idle 态 Esc 才 `exit()`（与提示文案一致）。
- 涉及文件：`src/ui/App.tsx`；配套测试 `tests/ui/app.test.tsx` 新增 4 用例（审批 Esc 拒绝 / 审批 Ctrl+C 拒绝 / 流式中 Esc 中断 / idle Esc 退出）

## 经验教训
- 如何避免同类问题：所有「全局热键」必须按 phase 分派后再落兜底行为；审批交互（approval/plan-approval）天然是 fail-closed 语境——任何非 y 输入都应「拒绝」而非「退出/放行」。自检：`useInput` 兜底分支里出现 `exit()` 时，先确认前面是否已拦截全部非 idle 阶段。
