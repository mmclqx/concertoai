# 分析被降级时，复盘把所有编辑都记成了「低风险」

> 日期：2026-10-28　版本：v5.0 T10（拒绝复盘记录）　严重度：中（记录失真，会让复盘功能整体失去意义）

## 现象

`tests/ui/approval-reflect.test.tsx` 里这条断言第一次跑就红：

```ts
// 非 TTY → T8 降级为 plain → 没有洞察 → 必须是 unknown，不是 low
expect(entry.level).toBe('unknown');
// Expected: "unknown"   Received: "low"
```

也就是说：在非 TTY 环境（`concertoai run`、管道、CI）里拒绝编辑，
复盘记录会写下 **`level: 'low'`** —— 而事实是**根本没有做任何分析**。

## 根因

`analyzeApproval` 的降级契约里，`level` 是「`max(hits.level)`，无命中为 low」。
降级时 `hits` 为空数组 → `levelOf([])` 返回 `'low'`。所以：

```ts
level: insight?.level   // ← 降级时是 'low'
```

`undefined` 只覆盖了「分析还没到达」这一种情况；**降级时对象是存在的**，
只是它装的是「没分析」而不是「低风险」。

这是 T9 措辞红线②（「未分析 ≠ 无影响」）在**数据层**的同一个错误——
UI 上已经守住了（`describeImpact` 五态分开），但往复盘里写的时候又踩了一遍，
因为 `level` 这个字段名太像「结论」了。

## 修复

判据必须用 `degraded`，不能用 `level` 本身：

```ts
const analyzed = insight !== null && insight !== undefined && insight.degraded !== true;
const entry = buildReflection({
  level: analyzed ? insight.level : undefined,        // → 'unknown'
  categories: analyzed ? insight.hits.map(...) : undefined,
  focusLines: analyzed ? insight.focusLines : undefined,
});
```

`buildReflection` 侧再兜一层：`level` 缺省写 `'unknown'`，且 unknown 时**丢掉 categories**
（没有分析结论就不该有「风险类别」，否则复盘表里会出现不存在的风险）。

## 回归防护

| 用例 | 断言 |
|---|---|
| `approval-reflect.test.tsx` →「n 拒绝后追加一条」 | 非 TTY（plain）下 `entry.level === 'unknown'` 且 `categories === []` |
| 同上 →「rich 模式（TTY 注入）」 | 对照组：真分析了才允许出现 high/medium/low |
| `reflection-store.test.ts` →「未分析（level 缺省）→ unknown，绝不冒充 low」 | 纯函数层锁死语义 |

## 一句话结论

> 「没有结论」和「结论是低风险」是两个事实，**不能共用一个默认值**。
> 当一个字段既能表达"值"又能表达"没测到"时，必须再加一个显式的 `degraded`/`analyzed` 判据。
