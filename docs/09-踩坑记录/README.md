# 踩坑记录（docs/09-踩坑记录/）

> 目的：沉淀「遇到 Bug → 根因 → 修复 → 教训」的完整闭环，避免同类问题重复踩坑。
> 维护时机：**每次遇到 Bug 并修复后，立即新增一条**（与代码修复同一次提交或紧随其后）。

---

## 文件命名

```
YYYY-MM-DD-问题简述.md
```

- 日期：修复日期（与代码提交同一天）
- 问题简述：10~20 字中文，动词短语（如 `版本号不同步`、`Reviewer上下文丢失`）
- 示例：`2026-08-09-版本号不同步.md`

## 内容模板

```markdown
# [日期] [问题标题]

## 问题描述
- 现象：...
- 环境：Windows / macOS / Linux

## 根因分析
- 直接原因：...
- 深层原因：...

## 解决方案
- 修复方式：...
- 涉及文件：...

## 经验教训
- 如何避免同类问题：...
- 是否需要更新规范：✅ / ❌
- 规范更新位置：`AGENTS.md` / `ARCHITECTURE.md`

## 相关链接
- 对话记录：...
- 相关 PR/Commit：...
```

## 维护规则

| 触发时机 | 动作 |
|----------|------|
| 遇到 Bug 并修复 | 新增一条踩坑记录（问题/根因/方案/教训） |
| 修复涉及规范缺失 | 在「经验教训」勾选 ✅ 并更新对应规范（AGENTS.md / ARCHITECTURE.md） |
| 版本发布前 | 汇总本次版本修复的踩坑记录，写入手工测试报告「已知问题/修复项」 |

## 记录质量要求

1. **根因而非表象**：必须写「深层原因」，禁止只写「现象 + 改了什么」
2. **可复现**：现象描述要具体到操作路径，便于后人复现
3. **可检索**：标题用动词短语 + 关键词，便于 grep
4. **规范联动**：若根因是「无规范约束」，必须同步更新 AGENTS.md 并在「经验教训」勾选 ✅
