# [2026-08-16] 手工测试 cd 跨盘符未生效导致污染项目根目录

## 问题描述
- 现象：执行 v4.1.1 preflight 手工测试时，`cd C:\tmp\concertoai-mt44` 后所有命令（echo 写 package.json / workflow init / preflight 自动初始化）实际都写入了**项目根目录** `F:\developer\2026\concertoai`，导致根目录 `package.json` 被 mt44 模板整体覆盖（丢失 dev/build/test/verify 脚本、全部依赖、type: module），`npm run dev` 报 `Missing script: "dev"`。
- 环境：Windows x64 / cmd.exe

## 根因分析
- 直接原因：cmd 中 `cd C:\...` 从 `F:` 盘切换到 `C:` 盘**不生效**（跨盘符必须 `cd /d`），但命令不报错，后续命令仍停留在原盘当前目录，所有 `>` 重定向和文件生成都落在项目根。
- 深层原因：手工测试隔离目录操作**缺乏强制约束**——没有在每步命令前核对当前目录（提示符被忽略），也没有用 `pushd/popd` 或独立脚本包装隔离步骤；测试记录文档只记录了命令，未记录实际执行目录，事故发生后难以第一时间定位。

## 解决方案
- 修复方式：
  1. `git restore package.json` 恢复 HEAD 版本（dev 脚本 + 依赖 + type: module 全部还原）
  2. 删除根目录残留 `index.ts`
  3. 删除 `.concertoai/workflows/precommit.yml`（测试残留，skills/snapshots 为原有内容保留）
  4. `npm run dev` 验证正常启动（非交互终端保护提示为预期行为）
  5. `npm run verify` 全绿（build + lint + typecheck + 全量测试通过）
  6. 在测试记录 `docs/11-手工测试结果/v4.1.1-test-result-1.md` 补充事故说明（含恢复措施与教训）
- 涉及文件：`package.json`（恢复）、`index.ts`（删除）、`.concertoai/workflows/precommit.yml`（删除）、`docs/11-手工测试结果/v4.1.1-test-result-1.md`（补充事故说明）

## 经验教训
- 如何避免同类问题：
  1. **跨盘符切换必须 `cd /d <路径>`**（cmd 基础陷阱），进入隔离目录后第一件事 `cd` 确认当前目录
  2. 隔离测试建议用 `pushd <dir>` 开头 + 结束 `popd`，或写成独立 `.cmd` 脚本执行，杜绝手工逐条命令
  3. 测试记录文档必须记录「实际执行目录」（可加 `> cd` 输出作为证据），而非只记录意图
  4. 写文件类命令（echo > file / 初始化）执行前先核对 pwd
