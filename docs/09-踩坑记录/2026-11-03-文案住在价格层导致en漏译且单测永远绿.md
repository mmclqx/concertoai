# 2026-11-03 文案住在价格层：`en` 漏译一处，且旧单测断言的正是那句硬编码中文

## 问题描述

- **现象**：`LUMEN_LOCALE=en concertoai balance` 打出 `📊 Current DeepSeek V4 Flash 空闲价: input ¥1/M · cache hit ¥0.02/M · output ¥4.5/M` —— 整句英文，中间夹一个中文词。同一实现在 TUI 状态条、`/model` 状态、`auto` 预设引导里都是这个中文词。
- **环境**：全平台（与终端、locale 编码无关；只取决于 `setLocale('en')`）。
- **报警方式**：**没有任何报警**——不报错、不崩、`npm run verify` 全绿、单测全绿。

## 根因分析

- **直接原因**：`src/model/models.ts` 的 `tierLabel()` 是个写死的中文三元表达式：
  `return tier === 'peak' ? '高峰价' : '空闲价';`。它是**用户可见文案**，却被放在「价格事实层」，与 locale 完全无关。
- **深层原因（两层）**：
  1. **文案住在非呈现层** ⇒ 翻译工作「按行扫字典」永远扫不到它：模板 `balance.priceTier` 早已 zh/en 双语齐备，唯独 `{tier}` 这个占位符的**取值**来自价格层。查字典查不出问题，因为字典里本该没有它。
  2. **旧单测锁死的正是缺陷本身**：`tests/model/models.test.ts` 里有 `it('tierLabel 双语标注') { expect(tierLabel('peak')).toBe('高峰价') }` —— 这句断言把「写死中文」当成期望行为写进了测试。于是**测试越绿，缺陷越稳固**：谁想改成走 i18n，都得先让这条用例红，看起来像「改动破坏既有契约」。
- **为什么只在换环境跑全量时暴露**：默认开发环境是 `zh`，中文档位词「看起来正常」；只有 `LUMEN_LOCALE=en` 跑全量（AGENTS 第 31 条要求的动作）才会出现中英混排。

## 解决方案

- **修复方式**：
  1. `tierLabel()` **迁到** `src/i18n/index.ts`（唯一实现，读 `t().tierLabel.{peak,offpeak}`），字典 zh/en 各新增 `tierLabel: { peak, offpeak }`（en：`peak hours` / `off-peak hours`）；
  2. `src/model/models.ts` **删掉实现**并留注释说明「本文件只谈价格事实、不谈怎么说」，保持**零 i18n 依赖**（`i18n` 侧用 `import type { PriceTier }` 单向类型引用，编译期擦除，无运行时环）；
  3. 4 个调用点（`cli/balance.ts` / `cli/slash/model.ts` / `model/auto.ts` / `ui/StatusBar.tsx`）改 import；`src/index.ts` 保持对外导出（换来源不换签名）；
  4. 把那条「锁死缺陷」的旧断言从 `models.test.ts` 删掉，改在 `tests/i18n/tier-label.test.ts` 里**双向断言**。
- **涉及文件**：`src/i18n/{index,zh,en}.ts`、`src/model/models.ts`、`src/cli/balance.ts`、`src/cli/slash/model.ts`、`src/model/auto.ts`、`src/ui/StatusBar.tsx`、`src/index.ts`、`tests/i18n/tier-label.test.ts`（新）、`tests/cli/balance.test.ts`、`tests/model/models.test.ts`。
- **护栏（三条，各配反向样本）**：`models.ts` 不得再出现 `高峰价/空闲价`；`models.ts` 不得 `import '../i18n'`；4 个调用点不得再从 `model/models` 取 `tierLabel`（正则按**整段 import 语句**匹配，多行具名导入也要抓得住）。

## 经验教训

- **判据一句话**：这个字符串是**给用户看的**还是**层内事实**？前者必须进字典——即使它住在价格层、命令层、配置层。
- **「零 CJK」这类否定断言必须同用例自证正例**：`expect(line).not.toMatch(CJK)` 对空字符串、对「根本没渲染」都成立（探针空转）。本次每个 en 断言都先 `setLocale('zh')` 断言同一函数/同一行**确有 CJK**，再切 en。
- **旧断言可能是缺陷的共谋**：迁移前先问「这条用例红，是破坏契约，还是终于把缺陷测出来了？」——本次是后者，所以旧断言应当**删除**而不是改成等价的中文断言。
- **顺带踩到的小坑（值得记）**：探针注释里写「`configureHolidayCalendar({ holidays: [] })` → 有日历，不附加『未配置节假日表』提示」是**未验证的推断**。实测空数组并不等于「已配置」（`configured` 判据是计数 > 0），提示行照旧附加。所幸「整行零 CJK」口径覆盖的是整段（含提示行，en 提示也是英文），断言反而更强；但**推断不能写成注释里的断言口吻**（AGENTS 已有条款，本次是又一例）。
- **是否需要更新规范**：✅ 已在 `ARCHITECTURE.md` 记为 **D89**（文案归 i18n 单一来源；判断「给用户看 vs 层内事实」；双向断言），并对 D88 补注「`model/auto.ts` 是 model 层唯一呈现型模块例外，其整段中文入字典另挂账」。
- **规范更新位置**：`docs/02-架构设计/ARCHITECTURE.md`（D89 + 目录树 `i18n/index.ts` 说明）；`AGENTS.md` 无需新增（「检索/归因类自证」与「换环境跑全量」条款已覆盖本次两类失误）。
