# 2026-11-14 测试把开发者真实交接单覆盖成假的——「查不出为什么退出」的真凶是我们自己的用例

## 问题描述

- **现象（用户报）**：一次真会话「不知为何又退出了」，去查却查不出原因；交接单标题写着
  「正常收尾 / 会话: 无 / 最后一条助手结论：完成了」，与用户实际经历（做完一半被打断）对不上。
- **排查结论**：**没有崩溃**（`~/.concertoai/crash.log` 最后写入停在一天前）。真原因是两件事叠加：
  1. 那次真会话是**撞 50 轮工具循环上限**收尾的（`~/.concertoai/sessions/20261114-211718-279.jsonl`
     264 条，最后一条是 tool 回填、后面没有收尾 assistant 消息），16:05:04 写过一份正确的交接单；
  2. **16:23:55 那份交接单被测试覆盖了**——被 `tests/ui/tool-step.test.tsx` 写成
     「正常收尾 / 会话: 无 / 结论：完成了」。
- **危害不是脏文件，是证据被擦**：用户来问「为什么退出」时，唯一那份记录已经是假的。
  于是「查不出来」被合理归因成「本来就没记录」——**假记录比没有记录更糟**。

## 根因分析

- **直接原因（定位到行）**：`tests/ui/tool-step.test.tsx` 的 `makeApp` 用
  `ctx={{ cwd: process.cwd() }}`（= 仓库根）渲染**真 `App`**，而 App 每轮收尾都会写交接单
  （v5.3 N4），落点 `handoffsDir()` = `os.homedir()/.concertoai/handoffs/`（**调用期**读 homedir）。
  ⇒ 每跑一次 `npm test`，就往开发者真实 home 里写一份「会话: 无」的假记录，覆盖掉真记录。
- **实测取证**（同一份文件，跑一遍单文件用例前后）：

  | 时刻 | 大小 | sha256 前 16 位 |
  |---|---|---|
  | 跑之前 | 5799 B | `552e480abb16ecc3` |
  | 跑 `npm test -- tests/ui/tool-step.test.tsx` 之后 | 460 B | `213aa447a8951fae` |

- **深层原因（这一类坑的第 4 次）**：`tests/setup.ts` 里已经有三个「测试写到真实 home」的
  隔离开关（`CONCERTOAI_REFLECTIONS` / `CONCERTOAI_HINTS` / `CONCERTOAI_METRICS`），
  每一次都是**事后补开关**。N4 新增了第四个写盘点（`handoffs/`）**却没有对应开关**，
  于是同一个坑第四次。根子上是「新增写盘点」这个动作**没有配套判据**。

## 解决方案

- **落地（两处一起钉才叫隔离）**：
  1. `tests/ui/tool-step.test.tsx`：`beforeEach` 建一次性 home + 项目目录，
     `ctx={{ cwd: tmpCwd }}`，并把 `USERPROFILE` **与** `HOME` 都指向它（`afterEach` 复位）。
     **只钉 `cwd` 不够**：那只换项目子目录，仍然落在真实 `~/.concertoai/handoffs/` 下。
     **只钉 `USERPROFILE` 也不够**：POSIX 侧读 `HOME`，换平台跑就静默失效。
  2. `tests/handoff-home-guard.global.ts`（**vitest `globalSetup`**）：套件开始前快照本项目交接单的
     sha，结束后比对；变了 ⇒ 归因，归因是测试写的 ⇒ 判红（`process.exitCode = 1` + throw）。
  3. 静态护栏 `tests/ui/handoff-isolation.test.tsx` 第 ③ 条：挂载真 `App` 的 UI 用例不许出现
     `cwd: process.cwd()`（要用仓库根就写常量 `REPO` 并配套钉家目录）。

## 这一轮里「尺子自己坏了」五次（全部实测，务必记住）

| # | 第一版写法 | 实测症状 | 教训 |
|---|---|---|---|
| 1 | 把护栏写成**某个用例**（「读 sha → 渲染 → 再读 sha」） | 变异 M1 下**全绿**，而真实文件同一轮被覆盖（5799B→460B） | **vitest 文件是并行跑的，用例只看得见自己 worker 的顺序**。套件级不变式只能放 `globalSetup`（前后快照），与文件顺序、并行度无关 |
| 2 | 静态判据「含 `<App` + `cwd: process.cwd()` + 源码不含 `USERPROFILE`」 | 变异 M1 下**仍绿**：文件里 `pinHome` 的**函数定义**仍写着 `process.env.USERPROFILE = …`，于是「含 USERPROFILE」成立 ⇒ 免检 | **函数定义 ≠ 被调用**。拿「源码里出现过某个字符串」做替代判据，恰好放过最常见的失效形态（写了函数没调） |
| 3 | 改成「含 `<App` + `cwd: process.cwd()`」后立刻跑 | 把 `tool-step` 与**本文件自己**都判违规——两个文件的**头注释**里都写着「原来的写法是 `ctx={{ cwd: process.cwd() }}`」 | **字面量扫描必须先剥注释**。解释缺陷历史的那句话，让护栏去咬了解释者 |
| 4 | `teardown` 里失败就 `throw` | vitest 只打一行 `error during close …`，**退出码仍是 0** ⇒ CI 全绿 | 「喊了但没拦住」＝没有护栏。必须在 throw 前显式 `process.exitCode = 1` |
| 5 | 只给纯函数 `classifyChange` 写用例 | 变异 M-C（把调用点的 `classifyChange(...)` 换回 `after === before ? 'unchanged' : 'test-written'`）**8/8 全绿** | **测了实现、没测接线**。补 `tests/cli/handoff-home-guard-teardown.test.ts` 直接调 `setup()`/`teardown()`，M-C 才精确红 1 条 |

## 第六次：判据方向也会造出假红（最重要的一条）

- **第一版判据**：`sha 变了 ⇒ 判红`。实测当场被打脸：本轮 verify 启动前 3 分钟，
  真交接单被**开发者自己的 chat 会话**刷新过（`> 会话: 20261115-001903-259`、
  `> 退出原因: max-turns`、17:44:21）——那是交接单的**正常用法**（App 每轮收尾都刷新快照）。
- 后果：任何人「**边开 chat 边跑 verify**」都会看到假红。而 `AGENTS.md` 的判据句写得很清楚：
  **按规范做事反而假红，比不做事更糟——它教人怀疑规范，而规范是这套流程唯一的地基**。
- **修法**：判据拆两步——先判「变没变」，变了再**归因**：
  - 新内容的 `> 会话:` 匹配真实会话 id（`YYYYMMDD-HHMMSS-mmm`，`newSessionId()` 定长拼出）
    ⇒ `external-session`：**不判红**，但打印一行读数（不许静默，否则下次真出问题会误以为「守卫跑过且干净」）；
  - `> 会话: 无` / 假 id（`s-1`、`s-3`）/ 文件读不到 ⇒ `test-written`：判红。
- **归因判据必须双向验**：只测「缺陷 ⇒ 红」时，一个「恒返回 `test-written`」的废实现也全绿，
  而它会把所有「边开 chat 边跑 verify」的人判红。故 `handoff-home-guard.test.ts` 里两个方向都有，
  外加「sha 相同 ⇒ `unchanged`」的负例面。
- **正则定长而不是 `\d{3,}`**：这条判据的用途是**免罪**，宽一寸就是把测试写的假 id 也放过去。

## 经验教训

- **「测试写到开发者真实 home」是结构性问题，不是某个用例的手滑**：四个写盘点
  （reflections / hints / metrics / handoffs）四次踩。新增任何「默认写 `~/.concertoai/` 的功能」时，
  **同一提交里必须回答「测试会不会写到它」**——要么给隔离开关，要么套件级守卫。
- **交接单的价值 100% 在「内容为真」**：它是给「下次的我」看的证词。测试把它写成假的，
  等于把一个诊断工具的读数随机篡改——而它**不报错**。
- **判据放在「能看见事实的那一层」**：进程内顺序看不见并行 worker 的写入；套件级不变式只能套件级验。
- **「变了」不等于「坏了」，判据必须能归因**：否则护栏会开始驱逐正常用法（本条：边开 chat 边跑 verify）。
  判据的默认方向要选**不制造假红**的那一侧，而「宁松勿紧」的代价必须用双向用例钉住。
- **本轮的边界，不假装覆盖**：
  - 守卫守的是「**本项目那份文件的内容**不许被改」；`handoffs/` 根目录**目录数增长**
    （本轮实测每跑一次全量 +43 个，本机累计 689 个）属**噪音类污染**，只打印不判红——
    真堵它需要「给 `paths` 加测试专用 home 覆盖」，超出本次范围，已登记为候选。
  - `> 会话:` 这一行的存在性依赖交接单格式。若将来把该行改名/去掉，归因会退化成
    「一律 `test-written`」⇒ 假红回归。故 `tests/cli/handoff-home-guard.test.ts` 里有一条
    用**真实生成器**（`SessionStore.create`）产出的 id 做探针通电，格式一改就红。
- 是否需要更新规范：✅
- 规范更新位置：`AGENTS.md`「测试要求」段「进程级全局状态隔离」条款 ② 的示例清单补 `handoffs/`；
  新增一段「本机真实数据的写入点必须与测试隔离」；已知边界段补「打开就退不可追溯」。
