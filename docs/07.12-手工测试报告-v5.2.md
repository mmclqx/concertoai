## 二、`/approvals`：会话恢复后仍能查到（N2 的真机判据）

### 2.1 两阶段 PTY（`scripts/pty-drive-v51.mjs --only=s5`）

**为什么必须两阶段**：单进程里「既自动放行、又敲 `/approvals`」**证明不了**结论进了会话文件——
`/approvals` 读的是内存 `messages`，一行都没落盘时看着也是对的。所以起两个独立进程，
中间**只通过** `~/.concertoai/sessions/*.jsonl` 传递。

| # | 断言 | 结果 |
|---|---|---|
| ⓪ | 探针通电：本地 mock 收到 **2** 次请求（证明 `baseUrl` 生效、零真钱） | ✅ |
| ① | 阶段一确实自动放行过（留痕 `已自动放行` + 磁盘出现 `// 求和`） | ✅ |
| ② | 进程 B `chat -r <id>` 后 `/approvals` 列出「本会话自动放行 1 次」+ `src/math.js` | ✅ |
| ③ | 否定面：不是误报「没有记录」 | ✅ |
| ④ | 文案纪律：回执里不出现「安全」（未命中 ≠ 安全） | ✅ |

> 取证纪律：脚本退出后 stderr 刷了两段 `Error: AttachConsole failed`（node-pty 的 ConPTY 拆除辅助进程）。
> **退出码 0、断言全 PASS** —— 按 AGENTS「有 stderr ≠ 失败，判据看退出码」处理：不拿它定罪，也不掩盖。

## 四、本轮最重要的发现：N1 只修了被截图的那一句（已修）

**现场**（真机，v3 待迁移状态，修复前）：

```
✅ 配置迁移完整性: 配置仍为 v3 格式（schema v1），启动时将自动迁移
  无需备份（本机未做过 v3→v4 迁移，config 一开始就是 v4 格式）
```

第一句说「你是 v3」，第二句说「你一开始就是 v4」——**同屏互相否认**，与 N1 修掉的那个 bug

**为什么漏**：`v3 配置（待迁移）` 那条用例只有一句 `toContain('配置仍为 v3 格式')` ——

## 九、`chat -r` 敲错会话 id：从「甩 Node 堆栈」到「说人话」（v5.2 边缘路径修复）

**为什么会去测这条**：`/approvals` 的全部价值是「`chat -r` 恢复昨天的会话后还能查到自动放行」——
也就是说**用户必然会大量手抄** `-r` 的 id，而它形如 `20261113-024243-266`（日期-时分秒-毫秒），**手抄必错**。
新功能把一条老路径变成了必经之路，所以它的失败形态必须按新权重重新验收一遍。

### 9.1 修复前（真实读数，隔离 HOME + 真 TTY）

```
> concertoai chat -r 20200101-000000-000
[ConcertoAI] 未处理的 Promise 拒绝，详情见 C:\Users\…\.concertoai\crash.log
Error: ENOENT: no such file or directory, open '…\sessions\20200101-000000-000.jsonl'
    at async open (node:internal/fs/promises:639:25)
    at async readFile (node:internal/fs/promises:1252:14)
    at async SessionStore.read (file:///…/dist/chunk-FNF743PH.js:633:17)
```

退出码 **1**、进程**自己退出**——两项硬指标都对，所以此前所有自动化用例都不认为它有问题。
但屏幕上一个字都没说人话：**用户不知道错在哪、不知道正确的 id 长什么样、不知道下一步敲什么。**

### 9.2 修复后（三条真机路径逐条实测）

| 输入 | 屏幕上看到的（逐字） | 退出 | 结论 |
|---|---|---|---|
| `chat -r 20200101-000000-000`（记错） | `没有这个会话: 20200101-000000-000` / `最近的会话（新 → 旧）:` / `  20261113-024243-266  1 条` / `  20261112-120000-001  1 条` / `查看全部会话: concertoai chat -l` | exit **1**，**自行退出** | ✅ 错在哪 + 正确的长什么样 + 下一步 |
| `chat -r ../etc/passwd`（非法） | `会话 id 不合法: ../etc/passwd（只允许字母、数字、下划线、点和短横线）` / `查看全部会话: concertoai chat -l` | exit **1**，**自行退出** | ✅ 不谎称「没有这个会话」 |
| `chat -r 20261113-024243-266`（**正例自证**） | `已恢复会话 20261113-024243-266（1 条消息）` + 历史消息重绘 + 正常输入框 | 常驻（TUI 正常） | ✅ 证明前两条不是「什么都报错」 |

> **为什么第 3 条必须跑**：不会「什么都说没有这个会话」的废实现也能让前两条全绿。
> 正例自证是这一节的地基 —— 没有它，「两条 PASS」证明不了任何事。
>
> 另外两处**取证纪律**（本轮都真实踩到）：
> ① 第三条一开始把外层超时压到 90s 就挂了 —— 不是 bug，是**TUI 本来就不会自己退出**（正例的预期形态），
>    脚本靠 10s backstop 收尾；把「超时」直接读成「失败」就错了。
> ② 输出里的 `Error: AttachConsole failed`（node-pty 的 ConPTY 拆除辅助进程）出现在断言之后，
>    不影响退出码 —— 按 AGENTS「有 stderr ≠ 失败」处理。

### 9.3 三种失败分开说的依据

| 事实 | 说什么 | 为什么不能合并 |
|---|---|---|
| `ENOENT`（记错 id） | 「没有这个会话」+ 最近 5 个真实 id | 用户此刻要的是**正确的那个长什么样** |
| `EACCES` / 其他读失败 | 「读取会话失败: <原因>」 | 说成「不存在」就是**撒谎**（文件在，只是读不了） |
| 非法输入（含 `/`、`..`） | 「会话 id 不合法」+ 允许的字符集 | 与「不存在」是两件事：一个是他敲错了字符，一个是他抄错了编号 |

这与 §四 的 `doctor` N1 是**同一条教训**：`ENOENT` / `EACCES` / 非法输入是三件不同的事，
压成一个 bool 或一句话，必然对其中两种撒谎。

| 项 | 结果 |
|---|---|
| 新增文件 | `src/cli/resume-error.ts`（纯函数：`classifyResumeError` / `describeResumeFailure`，与 `slash/approvals.ts` 同构） |
| 接线 | `chat.tsx` 的 `readSessionOrExit()`：读 → 打印 → `exit 1`；`session.ts` 导出 `isValidSessionId` 作**唯一判定源** |
| 新增用例 | **+11 条**（含否定面「EACCES 不得说成没有这个会话」、「不把堆栈甩给用户：无 `at async`、每行 ≤200 字」、en 侧无 CJK） |
| 变异探针 **M8** | `classifyResumeError` 无条件 `return 'not-found'` ⇒ **精确红 2 条**（分类用例 + 否定面）；复原后 `resume-error.ts` sha256 `342b27652d63` 与备份逐字节一致 |
| 规范联动 | `AGENTS.md` 边缘路径段补「失败提示是否可用」判据；`docs/09-踩坑记录/2026-11-13-恢复会话敲错id把堆栈当提示.md` |
