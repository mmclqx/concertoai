### S3 设计决策（05:40）

1. **薄包装（G6）**：把 `repair.ts` 里内联的「错误 → 修复动作」优先级抽成纯函数 `strategyFor(error)`，`repairVerifyReport` 与 `fix --dry-run` **共用同一份判定**（不是复制第二套）。
2. **`--dry-run` 零写入**：只跑 `npm run verify` + `parseVerifyReport`，产出「每个错误 → 打算怎么修」的策略清单；**不调模型、不调 lint:fix、不建快照、不写盘**，且**不需要 API Key**（第一次跑的用户也能先看诊断）。
3. **判定用退出码**（承接 T15 教训）：`--dry-run` 的「通过/不通过」看子进程真实退出码，解析只用于归因；解析不出具体错误时**如实说「没能定位」**，不假装无需修复。
4. **两道审批门**：① 开跑前确认（覆盖 `lint:fix` 这种免审批的确定性修复）；② 每次模型修复写盘前逐次确认（复用 `requestApproval`，diff 展示沿用审批框文案）。非 TTY 且无 `--auto-approve` → **fail-closed 拒绝启动**并指路 `--dry-run`。
5. **超限转人工 + 现场保留**：直接复用 `RepairVerifyResult.exceeded`；文案只用真实存在的命令（`concertoai snapshot list` / `concertoai snapshot clean`）+ 快照目录路径，**不发明** `snapshot restore`。
