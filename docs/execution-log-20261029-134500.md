## 二、实测踩到一个坑：npm 会吞掉 `--owner`

用户预期「`npm run lock claim --owner concertoai-loop` 比 `node scripts/...` 短且不易错」。**实测这个形式是错的**：

| 命令 | 结果 |
|---|---|
| `npm run lock claim --owner concertoai-loop` | ❌ **exit 2**「claim 需要 --owner」——npm 把 `--owner concertoai-loop` 当自己的配置吃掉，脚本什么都没收到 |
| `npm run lock claim --owner=concertoai-loop` | ❌ **exit 2**，同样被吞 |
| `npm run lock claim -- --owner concertoai-loop` | ✅ **exit 0** 已持有（`--` 之后的参数才透传给脚本） |
| `npm run lock status --owner concertoai-loop` | ⚠️ `--owner` 被吞，参数变成 `status concertoai-loop`，owner 为空 → 无主判断 → **exit 1**（不是「空闲」） |
| `set "CONCERTOAI_AGENT=concertoai-loop"&& npm run lock claim` | ✅ **exit 0**（走环境变量，无需 `--`） |

→ **AGENTS 第 22 条已按实测的正确形式写入**：`npm run lock claim -- --owner concertoai-loop`，并明写「**`--` 不能省**」及两种被吞的表现；同时保留环境变量形式作为替代。

**如果直接按用户原话写成 `npm run lock claim --owner ...`，开工第一步就会 exit 2 报「需要 --owner」——比原方案更长且更容易错。**这一条已如实回写。
