## 四、本轮抓到的真缺陷与坏尺子（详见踩坑记录）

1. **真缺陷（一行顺序废掉整个功能）**：`headerValue` 用「遇到非 `> ` 行就停」做边界，
   而交接单首行是 `# 交接单 — <项目>` ⇒ 首次迭代即 `break` ⇒ `> 项目:` 永远读不到
   ⇒ 消费端每次都判「另有项目，已忽略」。**写得完美、读永远失败**，所有产物看着正常。
   抓它的是那条 round-trip 用例。修法：边界改成「第一个 `## ` 小节」。
2. **坏尺子 1**：`child.kill('SIGINT')` 在 Windows 恒假红（该平台无 POSIX 信号，`kill(signal)` 直接终止进程）
   ⇒ 改用 `process.emit('SIGINT')`（走同一监听器），并把「不验 OS 投递信号」这条边界写进用例注释。
3. **坏尺子 2**：想用 200 条 `run_command` 造出超 4000 字的交接单——造不出来（② 栏 20 条上限把体积压住了）。
   ⇒ 拆成两条：先立「正常产物到不了上限」这个事实，再用手改的超长文件测防御面。
4. **biome 把注释粘进依赖数组**：`--write --unsafe` 补齐 4 处 `useCallback` 依赖时，
   把邻近注释一起写进了数组（`maxTurns, // v5.3 N4 …` 三处）。手工清理后 lint 归零。
