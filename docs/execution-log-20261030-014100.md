## 三、publish 实际结果：**E403 2FA 阻断，包未发出**

首跑 `npm publish` 退出码 1，且 stderr 回显的是**测试用例里的**「⚠️ 闭环超限/失败，触发事务回滚」（该串在 `verify-*.log` 里反复出现，是 `team` 用例的正常输出）——**差点把测试噪声当成 publish 的失败原因**。改为落盘 `npm publish > publish-attempt1.log 2>&1` 后读尾部，拿到真实失败点：

```
npm notice name: @concertoai/cli
npm notice version: 5.0.0
npm notice filename: concertoai-cli-5.0.0.tgz
npm notice package size: 987.9 kB
npm notice unpacked size: 3.4 MB
npm notice shasum: 44ed767fb7941f7303e3ffce1cd43e5e7b4d6186
npm notice total files: 171
npm notice Publishing to https://registry.npmjs.org/ with tag latest and public access
npm error code E403
npm error 403 403 Forbidden - PUT https://registry.npmjs.org/@concertoai%2fcli
npm error 403 Two-factor authentication or granular access token with bypass 2fa enabled is required to publish packages.
```

**关键判读**：`prepublishOnly`（= `npm run verify`）**已通过**（打到了 Tarball Details 阶段），失败发生在 registry 鉴权阶段。**代码侧无问题，是账号侧写权限策略。**

随后取证 token 形态（不打印密钥）：

| 检查 | 结果 |
|---|---|
| `~/.npmrc` | `//registry.npmjs.org/:_authToken=npm_…`（`npm_` 前缀 + 40 字符 = **granular access token**），项目内无 `.npmrc` |
| `npm token list` | `Publish token npm_wxN6...Ayvp… with id 90e23b created 2026-08-11` |
| `npm profile get --json` | `"tfa": false`，`name: mmclqx`，`email_verified: true` |
| `npm profile get tfa` | **空输出** |
| `npm view`（只读） | 正常 |

→ **矛盾点即根因**：只读 API（`whoami` / `view` / `profile get`）对 granular token 放行，写 API（`PUT` 发版）要求「2FA OTP 或带 Bypass 2FA 的 granular token」；而该 token 创建时未勾选 bypass。`npm profile get` 的 `tfa:false` 是**账号级**开关，不等于**token 级**写权限，两者不可互相推断。
