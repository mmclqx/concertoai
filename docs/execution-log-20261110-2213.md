**关键设计（都写进代码注释）**

1. **命门**：`insight.degraded !== false ⇒ ask`。降级路径（非 TTY / CI / config-plain / 超大 diff）的 `level` 恰好是 `low`，唯一能区分的就是 `degraded`。
2. **顺序即语义**：先显式挡 `high`/`medium`，再判 `low`；末尾 `default ⇒ ask/unknown-level` 让「将来新增等级」默认拒绝，而不是因为没人更新这个文件就放行。
3. **`kind` 刻意不 import**：避免 `core → tools` 反向依赖；漂移由 `tests/core/auto-approve.test.ts` 的编译期断言在 `typecheck` 阶段挡住。

**过程中被自己的护栏抓了一次（如实记）**

护栏第一版搜 `action: 'allow'` 判顺序，结果**真实仓库被判红**——因为类型声明 `action: 'allow' | 'ask'` 在文件顶部，天然早于 degraded 判断。
修法：只认放行**分支**形态 `return { action: 'allow'`。教训：**「这个词出现过」≠「这个行为发生过」**，顺序类断言必须锚定到具体语句形态（与 AGENTS「检索类必须先做正例自证」同源）。

**实现要点**

- **双入口**：`addAutoLowOption(program)`（无子命令默认进 chat）+ `addAutoLowOption(program.command('chat')…)`。
- **包装优先级**：`allowlist-only` 分支**先返回**，auto-low 不覆盖它（两种策略语义不同，混起来会变成「既拒绝不了也问不了」）。
- **判定用分析 `skipImpact: true`**：只求 `degraded`/`level`，不扫影响面（那是卡片的事）。
- **fail-closed**：`try/catch` 兜底 ⇒ `insight = null` ⇒ `ask`。
- **留痕带累计次数**：`notice` 是单行槽位，只报最近一次会被下一条提示覆盖，用户可能一次都没看见。
- **计数归零**：`send` / `sendPlan` 入口各重置一次（本轮任务口径）。

**真机抓到 1 个真 bug（断言抓的，不是我看出来的）**

`addAutoLowOption(program).command('chat')` 这行**实际是把选项又加回根命令**（`.command()` 返回的是子命令，但我写在 addAutoLowOption 之后调 `.command('chat')`，等于对 program 重复注册），
实测 `npx tsx src/cli/index.ts chat --help` 直接抛：
`Cannot add option '--auto-low' to command 'concertoai' due to conflicting flag '--auto-low'` → 落 crash.log。
修法：先 `.command('chat')` 建子命令，再把结果交给 `addAutoLowOption`。
> 这条正是 `tests/cli/auto-low-option.test.ts` 存在的理由：**UI 集成用例直接渲染 `<App>`，根本不走 CLI**，这类注册错误它一条都抓不到。
