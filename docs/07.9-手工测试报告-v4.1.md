### 1.1 🔴 问题 1：第一次就失败「Missing script: lint」→ preflight 环境预检 + 自动初始化

**测试场景**（完整复现命令，v4.2 可直接复用）：

```bat
:: 1. 新建裸项目（package.json 仅 name/version/空 scripts）
mkdir C:\tmp\concertoai-mt41
cd /d C:\tmp\concertoai-mt41
echo {"name":"mt41","version":"1.0.0","scripts":{}} > package.json
:: 2. 放一个 precommit 工作流（lint/typecheck 两步骤，depends 用块状列表——parser 不支持内联列表，见已知问题 #3）
mkdir .concertoai\workflows
type nul > .concertoai\workflows\precommit.yml
:: 3. 用 dist 构建的 CLI 直接跑（本仓库开发环境）
node F:\developer\2026\concertoai\dist\cli\index.js workflow run precommit < nul
```

> 说明：`< nul` 模拟非 TTY（fail-closed 分支）；交互 TTY 下的 y 分支由 preflight.test.ts 覆盖。

| 步骤 | 操作 | 预期结果 | 实测 |
|------|------|----------|------|
| 1 | 裸项目 `workflow run precommit`（非 TTY） | 不出现「Missing script: lint」裸失败 | ✅ |
| 2 | 预检报告 | `⚠️ 环境未就绪（5 项缺失）：缺少脚本 lint / 缺少脚本 typecheck / 依赖未安装 biome / 依赖未安装 typescript / 配置文件缺失 biome.json`（每项标注可自动初始化） | ✅ |
| 3 | 非 TTY fail-closed | `非交互环境且环境未就绪，已停止执行。请先配置缺失项后重试。` 退出码 1 | ✅ |
| 4 | 半完成状态：配好 scripts + biome.json（仅缺依赖） | 预检精确到 2 项（依赖未安装 biome/typescript），不重复报脚本/配置缺失 | ✅ |
| 5 | 配好依赖（node_modules/.bin 存在） | 预检通过，直接开始执行 | ✅ |
| 6 | 自动初始化 y 分支（交互审批流） | 报告 → y → 操作计划（npm install -D @biomejs/biome / typescript + 写 biome.json + 注入 scripts）→ 二次确认 → 执行 | ✅（preflight.test.ts 10 用例覆盖交互序列；CLI 非 TTY 无法走 y 分支属 fail-closed 设计） |

**结果**：✅ 通过——「装完模板直接 run，环境自动配好」的客户诉求落地；静态预检三维（脚本/依赖/配置）+ 精确到半完成状态的裁剪。

### 1.2 🔴 问题 2：F 是「假按钮」→ F 等待态闭环 + 60s 超时

**测试场景**：workflow 步骤失败 → 失败恢复界面出现 `[R]重试 [S]跳过 [F]修复后重试 [A]放弃`。

| 步骤 | 操作 | 预期结果 | 实测 |
|------|------|----------|------|
| 1 | 步骤失败后选项展示 | R/S/F/A 四选项展示 | ✅ |
| 2 | 选 F 后行为 | 打印「请手动修改代码…Enter 重试 / a 放弃（60s 超时自动放弃回滚）」，进入等待循环 | ✅（`tests/cli/workflow.test.ts` 等待态 7 用例：Enter 重试 / a 放弃 / 超时放弃 / 非法输入重提示 / 非 TTY abort） |
| 3 | 60s 无输入 | 自动放弃（abort）→ 整体回滚，不挂起 | ✅（`tests/cli/workflow.test.ts` fake timers 断言超时路径） |
| 4 | Ctrl+C / 非 TTY | fail-closed → abort | ✅ |

**结果**：✅ 通过——F 从「假按钮」变为「真等用户修完再跑，忘了也不挂死」。

### 1.3 🟡 问题 3：进度条重复刷屏 → 内部重试归零 + retry 语义重定义

**测试场景**：lint 步骤失败（伪造 `error TS1234` + `npm error code 1`）。

| 步骤 | 操作 | 预期结果 | 实测 |
|------|------|----------|------|
| 1 | 失败步骤执行次数 | `▎ 正在执行 step 1/2: lint…` 只出现 1 次（无内部静默重试 3 遍） | ✅ |
| 2 | 失败后直接进入恢复交互 | 摘要 + 详情 + R/S/F/A | ✅ |
| 3 | retry 语义（步骤级恢复上限） | 缺省不限（向后兼容）；retry: N = 第 N+1 次恢复强制 abort；retry: 0 = 不允许恢复 | ✅（executor.test.ts retry 语义 5 用例 + 既有 YAML 向后兼容） |
| 4 | orchestrator 无回归 | 独立 scheduler 实例，不受 maxRetries: 0 影响 | ✅（orchestrator 133 用例全绿） |

**结果**：✅ 通过——「失败只跑一次就进入 R/S/F/A，不刷屏」。

### TTY 交互验证（node-pty ConPTY 真实 TTY 驱动，2026-08-15 全部完成）

> 背景：自动化执行器 stdin 非 TTY，promptLine `!isTTY → undefined` 走 fail-closed 分支，管道无法驱动交互。**解法：`scripts/pty-drive.mjs` 用 node-pty ConPTY 创建真实伪终端**——子进程 `stdin.isTTY=true`，交互分支（preflight y/N、F 等待 Enter/a/超时、审批 y）**真实执行**，仅按键由脚本按事件序列驱动（等待匹配文案后发送按键）。5 场景一键复现：`node scripts/pty-drive.mjs all`（C1 需网络真实安装依赖；C4 需真实等待 60s 超时）。

**执行结果（一键复现：`node scripts/pty-drive.mjs all`；C1 需网络真实安装依赖，C4 需真实等待 60s 超时）**：

| # | 场景 | 驱动按键序列 | 预期 | 结果 |
|---|------|--------------|------|------|
| **C1** | preflight 自动初始化 | `y` → 计划 → `y` | 真实 `npm install -D @biomejs/biome` + 写 biome.json + 注入 scripts → lint 跑通 | ✅ PASS |
| **C2** | F 等待态 Enter 重试 | `f` → 等待文案出现后修复脚本 → `\r` | F 等待：Enter 重跑失败步骤，通过 | ✅ PASS |
| **C3** | F 等待态 a 放弃回滚 | `f` → `a` | 放弃 → 整体回滚（marker.txt 恢复） | ✅ PASS |
| **C4** | F 等待态 60s 超时 | `f` → 无输入（真实等 60s） | 超时自动放弃（abort）→ 回滚，不挂起 | ✅ PASS |
| **C5** | 审批节点 y 继续 | `y` | 审批节点暂停 → y 继续执行 publish | ✅ PASS |

> 注：node-pty 子进程退出时 conpty_console_list_agent 会打 `Error: AttachConsole failed` 噪音（已知问题，不影响场景判定——每个场景均有明确 ✅ PASS 判定）。
