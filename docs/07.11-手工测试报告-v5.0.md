**不成立的部分（真缺陷 K10）**：

```
### 🔧 修复结果
✅ 已修复 0 个 / ⚠ 需人工处理 14 个 / ❌ 自动回滚 0 个
- ⚠ src/calc.js:1 — 注释与实现相互矛盾…（未配置模型，无法生成修复补丁）
- ⚠ src/calc.js:3 — 冗余中间变量 result…（未配置模型，无法生成修复补丁）
…
```

同一进程**刚刚用模型审完了 9 个维度**，`--fix` 却说「未配置模型」→ 修复永远 0 条。根因已定位到行：`src/cli/review.ts:458` 审查阶段用 `options.model ?? resolveModel(undefined)`（有默认值），而 `:480` 传给 `--fix` 的是 `model: options.model`（**没有默认值**）；`src/reviewer/autofix.ts:250` 判定 `options.model === undefined` 即返回「未配置模型，无法生成修复补丁」。用户不敲 `-m` 时 `--fix` 100% 失效，且**原因说反了**。

> 这也解释了本轮场景 7 唯一的 FAIL 断言（`--fix` 既没弹审批、也没说「没有可自动修的点」，而是走了「有可修点但生成补丁失败」的第三态）。

**度量口径的诚实说明（本轮实测推翻了原判据）**：

1. 余额只保留 2 位小数、且**结算有延迟**：脚本在场景刚跑完就读余额，两次读数都发生在结算前 → 「场景前后差」恒显示 **¥0**，于是「单场景超 ¥1 立刻停」的闸门**在真正超支时不会响**（本轮 ¥2.11 就是证据）。
2. 我最初按「单文件、小 diff、5 子代理」估出 ≈¥0.0165，**实测 ¥2.11，低估约 100 倍**。原因：`--fix` 每条建议级问题都要一次「带整文件内容 + 生成补丁」的调用，且审查子代理内部有多轮工具调用（上下文逐轮增长）——**估算表用的是「一次问答」的规模，不是「一次代理循环」的规模**。
3. 结论（已记 K15）：成本纪律不能靠余额差，必须用响应 `usage` 的 token × 单价**本地累加**；否则「估算—熔断—记账」三步全是纸面纪律。

## 九、结论与建议

1. **主路径可用**：8 个场景里 7 个通过，审批风险卡、拒绝复盘、场景提示、双输出 init、4 动词、斜杠开关全部按设计工作，性能余量充足。

   - 先把 K10 修掉（1 行数据流 + 2 条用例），因为它把「有可修点」变成「永 0 修复 + 错误原因」；

   - K3 / K4 / K5 / K6 / K11 / K12 为体验与覆盖率提升，建议发布后单独一轮。
4. **测试资产可复用**：5 个驱动脚本 + 3 份证据文件已落盘（§一表），下次回归直接重跑；`MOCK_HITS > 0`、就绪门、`childEnv()` 剔除真 Key 这三条已写进脚本注释，避免再踩。

### 10.5 ⚠️ 复验时撞出的一条**新阻塞候选**（K16，本轮未修，等裁决）

**K16：审查子代理全部失败时，报告显示「✅ 未发现明显问题，代码质量良好」且 `exit 0`。**

- **证据**：我用自己的探针（假 Key，0 花费）跑 `concertoai review`，5 个子代理全部 401 失败，输出却是
  `严重程度：🔴 严重 × 0 · 🟡 中等 × 0 · 🟢 建议 × 0` + `✅ 未发现明显问题，代码质量良好。` + `退出码 0`。
- **代码级因果已定位**：`src/reviewer/engine.ts:78-87` 聚合时只处理 `result.ok === true` 的分支；
  失败分支的注释写着「子代理失败 → 该维度标记为审查未完成（**静默跳过**）」，**而实际代码只是跳过，没有任何「未完成」标记**。
  于是 5 个全失败 = 0 条问题 = 报告「质量良好」。
- **为什么这条比 K1 更严重**：K1 是「屏幕全绿 + 退出码 1」（至少 CI 会红）；K16 是「屏幕全绿 + **退出码 0**」——
  断网、Key 过期、余额耗尽、代理不通，任何一种都会让 `review` 变成**绿灯放行**。
  这与 T18 立下的「判不了绝不冒充通过」红线直接冲突（那条只覆盖了「范围解析失败」，没覆盖「模型调用失败」）。
- **建议**：若要发布 v5.0（主打能力之一就是 `concertoai review`），这条应当与 K1/K2/K10 同级处理。
  修法：失败子代理计入「本维未完成」，报告显示 `N/9 维未完成` 并 `exit 1`；顺带把 K7（无 verify 脚本写「❌ 失败」）一起改。
