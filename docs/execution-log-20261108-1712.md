三个子命令，全部写死 `docs/12` §9.2 的五条安全约束。关键设计决策（每条都对着一个「能悄悄为真的废实现」）：

| 设计 | 为什么必须这样（不这样的后果） |
|---|---|
| 判据 pass = `!timedOut && exitCode === 0 && missing.length === 0` | 只看 `exitCode` ⇒ `npm test` 里「0 个用例被跑」也 exit 0（正是 K15 修掉的「不会失败的测试」同族） |
| 超时记 `exitCode = 124`（coreutils 口径） | 记 `0` 是假绿，记 `null` 会让「不可度量」和「没跑」混为一谈 |
| `expectContains` **逐条比对 stdout+stderr**，`desc` 由脚本**不解析** | 把自然语言当判据 = 又一次「我说通过」；结构化字段才能真正机械判定 |
| `write` 时**实测一遍全部 criteria** 记 `baselineCriteriaState` | 恒绿空转的自证：本次实测 `C1/C2/C3` 写入当时**全 RED**，后来转绿才是真进展（若基线也全绿，说明判据根本没在测东西） |
| 状态文件路径 `CONCERTOAI_INSTRUCTION_DIR` 可覆盖 | 测试必须能隔离，**绝不许碰开发者真实的 `.git/` 状态**（与 `tests/setup.ts` 关复盘/提示同一条理由） |
| 单步 `--status done`：复用需**同时**满足 `exitCode===0` + `≤10 分钟` + `head 一致` | 只判新鲜度 ⇒ 「刚改完代码又复用旧 PASS」；只判 `exitCode` ⇒ 复用两小时前那句 PASS |
| 复用记录**保留原 `at`** + 写 `reusedFrom` | 把「复用」刷成当下时间，事后就无法判断它是否过期（等于伪造了一次实测） |
| 终态 `--set-status done` **重跑全部、一律不复用** | 最后一道门；宁可多跑一次。测试断言「全部 `reused:false`」 |
| 并发保护：写前比对磁盘原文 | 只靠 `rename` 原子性防不住「读-改-写」丢失更新；比对原文才能 exit 23 而不是覆盖别人的进度 |
| `git ls-files --error-unmatch` 命中即拒写 | ADR-051 红线①「状态文件不进版本库」从文档条款变成**可执行断言** |

### 5.3 测试抓到的**真 bug**（不是我预先想到的）

`cmdUpdateSetStatus` 里读的是 `opts.status`，而终态形态的取值在 `opts['set-status']` —— 于是 `--set-status done` **恒被当成用法错误 exit 2**。四次失败里三条由它引起（`expected 2 to be 21` / `expected 2 to be +0`）。**单测抓到的，不是我肉眼发现的**——这正是「否定面用例」的价值：如果只测「全部通过时能 done」，这个 bug 会让测试**假绿**（`--set-status done` 返回 2，只要断言写松一点就被当成「拒绝了，符合预期」）。

另 1 条失败是**测试自己写错**（把基线实测次数数成 1，实为 2）。两条都改了，改完 45 → 46 用例全绿。
