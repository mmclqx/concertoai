| 步骤 | 操作 | 预期结果 |
|------|------|----------|
| 1 | 在项目内故意引入一个 Biome 可修复错误（如多余的 `import type`） | `npm run verify` 的 lint 段报错（FIXABLE） |
| 2 | 运行 `concertoai self-heal` | 自动执行 lint 段分类 → `npm run lint:fix` 直修（无审批）→ 重新 verify → 输出「✅ verify 全部通过，无需修复」 |

| 4 | 修复后 verify 仍失败（模拟无效修复） | 触发 SnapshotManager 回滚，文件恢复到修复前状态 |
| 5 | chat 内输入 `/self-heal`（verify 通过时） | 输出「✅ verify 全部通过，无需修复」，修复期间状态条可见 |
| 6 | 连续失败超过 2 次 | 输出详细错误报告（各段 errors + 已尝试修复）并转人工 |

### 1.4 Orchestrator CLI + 运维命令（M5）

| 步骤 | 操作 | 预期结果 |
|------|------|----------|
| 1 | `concertoai team "实现一个 TODO 应用（含认证）" --dry-run` | 仅输出拆解清单（Task 名/负责人/依赖/文件），**不执行任何 Agent** |
| 2 | `concertoai team "实现一个 TODO 应用（含认证）"`（交互） | 展示拆解清单 → y 批准 → 对抗性闭环（Coder→Reviewer→QA）→ 聚合输出工件引用 + 中文摘要；`--auto-approve` 跳过确认 |
| 3 | chat 内 `/orchestrate 实现TODO应用` | 触发 team 全链路，结果转聊天消息；执行期间 `o` 键打开可观测性面板可见 Orchestrator/team-loop spans |
| 4 | 构造闭环超限（QA 一直失败） | 闭环 ≤5 次后退出，触发事务回滚（新增文件删除 / 修改恢复原状），快照清理 |
| 5 | `concertoai audit export` | stdout 输出保序 JSON 数组；`--out <file>` 写文件（目录自动创建）；无审计日志时「暂无审计日志」退出码 0 |
| 6 | `/agent update <name>`（已安装且注册表有新版本） | ✅ 更新到新版本；无更新时「已是最新」 |
| 7 | `/agent update`（无参数） | 列出所有可更新 Agent（`from → to` 版本） |
| 8 | `/review --severity strict` / `lenient` | strict：🟡 medium 也触发 reject；lenient：仅 🔴 critical 触发 reject；非法值报错列出合法值 |
| 9 | `/review`（无参数） | 保持 v3.0 默认（critical 必 reject / medium 可 reject） |
