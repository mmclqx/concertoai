## 两条必须记的自身失误

1. **探针 E 第一版空转**：同进程里改 `process.env.USERPROFILE` 再调 `resolveMetricsEnabled()`，得到「没写盘」——**假绿**。根因：`config.ts` 的默认路径在**模块 import 那一刻**就由 `os.homedir()` 定型，改 env 太晚，实际读的是我**真实的** `~/.concertoai/config.json`。改法：**子进程 + env 在启动前设好**，且子进程第一行先打印 `configPath()` **断言落在临时目录**（探针通电自证）。这条已写进任务书 §0.2 与风险 R3。
2. **把「不存在的字段」当成「新缺陷」写了半小时**：探针 D 里我往 v3 配置塞 `apiKey: 'sk-v3-in-config'`，看到迁移后 `providers.deepseek.apiKey` 仍为 `undefined`，一度以为发现了「迁移不搬 Key」的新缺陷。回读 `ConcertoAIConfig` 全部字段（`config.ts:108-180`）才确认：**这个字段根本不存在**，我塞的是野生字段（`legacy` 原样保留但无人认领）。⇒ 结论反转为「只读改造对 Key 可见性零影响」，并作为 T1.1 的**允许改依据**写进文档。**未验证的推断不能写成断言**——AGENTS 有条款，本轮又踩了一次小号版本。
