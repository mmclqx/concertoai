## 三、今天纠正的一处错判：`handoff.test.ts` 那 28 处**不属于本类**

**我原先写的（错）**：把 `tests/cli/handoff.test.ts` 的 28 处中文字面量断言算进「1122 处同类欠账」，措辞是「同功能的 28 处也没治」。

**实测之后（对）**：

- 那 28 处断言的是**磁盘产物格式**：`section(text, '## ① 做到哪一步')`、`'> 会话: sess-9'`、`'正常收尾'`。
- `src/cli/handoff.ts` 里 **`t()` 出现 0 次**（含中文的字符串 22 行）；读侧 `headerValue(text, '项目')` 也是**硬编码中文键**。
- 所以**把它们改成 `t()` 是错的**：写侧一旦本地化、读侧还认中文键，`> 项目:` 立刻读不到——正是 v5.3 N4 那类 round-trip 失明。

**更正后写进文档的原则**：「1122 处」是**混了三种异质断言**的毛数，**不能按一个数推平**：

| 类别 | 是什么 | 该不该改 |
|---|---|---|
| (a) | 断言 **i18n 渲染出来的 UI 文案** | 该改，与产品同源（候选 3 治的就是这类） |
| (b) | 断言**磁盘产物格式**（`handoff.md` 四栏 / `> 键:`） | **不该**改 `t()`；该显式标注「格式契约」，甚至加护栏防后人误改 |
| (c) | fixture / 字典值本身 | 不该改 |

**顺带两条实测读数**（供下一步候选 A 用，不是推断）：

- 130 个文件里 **23 个（313 处）**调过 `setLocale` ⇒ 至少有一条断言在 en 下跑过；**107 个（809 处）从不调** ⇒ en 完全没验证。
- 那 26 个调 `setLocale` 的文件**全部有 `setLocale('zh')` 复位**（文本核查，0 例外）⇒ 眼下没有活着的假红。**未实测**跨文件泄漏（vitest 默认 isolate，我没验，不当断言写）。

**为什么这处错判值得单独记一节**：错的不是数字，是**分类**。按「1122 处一个数」去推平，会把 (b) 类契约测试改成 `t()`，然后**写侧一改语言就真的读不到自己的交接单**——那是拿一个「测试卫生」的理由制造一个 v5.3 N4 级别的产品缺陷。
