## 四、口径裁决（两处是有意为之，不是漏改）

1. **单位策略**：`¥` 与 `tokens` 在 en 下**保持原样**（价格是人民币，不能改美元），
   但「/百万」这半句是**文字**，en 必须是 `M`。所以它进模板而不是拼在代码里 ——
   这正是 `¥1/百万`（zh）与 `¥1M`（en）必须**按 locale 分别断言**的由来。
2. **新增独立键组 `modelCmd`（28 键），不塞进 `cli.model`**：后者是**参数帮助**
   （`--model` 的 description），与「运行期输出」是两种东西；混在一起以后改帮助
   文案会误伤运行期文案。
3. **入口层两句与命令层两句刻意不同**：`resolveModel`（启动期）的 `resolveAutoNotice`
   与 `/model auto` 命令的 `autoEnabled` **是两句不同的话**。统一文案属**改文案**、
   不在 i18n 范围 ⇒ 保持原样、只做本地化。用例里也按此分开取键
   （第一版拿错了键，红而产品是对的）。

## 六、尺子坏了三次（不删）

1. **探针脚本没有 `finally`**：上一版 `runTest` 读数失明时直接抛错，`p.restore()` 没执行
   ⇒ **变异被留在工作区**，探针自己制造了一次污染。现在：`try { mutate; 跑 } finally { restore }`，
   并给失明错误附上输出尾部（否则「失明」本身无法归因——上一轮只看到一句
   「汇总行没匹配上」，不知道是语法错、编译错还是措辞变了）。
2. **PTY 检查脚本硬编码日志名**：变异轮跑完，它读的却还是 `.tmp-v56b-pty-en.log`
   ⇒ 屏幕上明明已经变中文，探针报「仍绿」。**探针无牙的读数，先怀疑尺子。**
   改成从 argv 取文件名后，同一变异立刻红在 `Tier:` 那句（CJK=21）。
3. **同屏范围过宽**：第一版把整屏当 `/model` 区域，于是状态条（`¥0.0000¥（…）` 重复 `¥`
   与全角括号）和消息标签（`你` / `助手`）也被计进 CJK ⇒ **范围外的漏译替本轮缺口背锅**。
   改成分四块，各块自己的边界自己说清；反过来「放宽成不查」也是假绿，两侧都不含糊。

另记两处**工装坑**（与产品无关，但会让探针白跑）：
- Windows ConPTY 上 `term.kill()` 会 attach 控制台进程列表，`AttachConsole failed`
  把探针自己打断（上一轮 zh 那轮就是这么断的）⇒ 改用 Ctrl+C 收尾、**不调 kill**；
- 内联 `node -e` 起 pty 出事会把**外层 cmd 一起带走**，一条证据都不剩 ⇒ 独立脚本 + 边收边写盘；
- Ink 提交后输入框**不清空**、`\x7f` 退格也不处理 ⇒ 改成「一条命令一个会话」，
  **不为了好测去改产品**。
